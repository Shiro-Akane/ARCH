## 0. 顺序、基线与不可混淆的边界

用户优先级固定为 **4 > 1 > 5 > 2 > 3**，映射如下：

| 阶段 | 工作 | 结束条件 | 与计时的关系 |
| --- | --- | --- | --- |
| O6 | 共享数学、CPU 调度与自引力执行优化；必要参数 | 历史 ≤10 只作中间成本线；本轮还须共同科学预算及 O6+ ≤2 | 先有界诊断，数学通过后冻结阶段版本做正式短计时；未达标则留在 O6 |
| O6+ | O6 签收后的跨模型 CPU 深度优化 | 预登记、共同物理和科学预算成立的代表点，逐点攻关整程比 ≤2；无法共同比较的能力单列 | 同资源、同终点、三次中位数；报告绝对耗时和工作量，不能以 GPU 倍数替代 CPU 结果 |
| O7 | 二维柱坐标改为轴对称 `(r,z)`，贯通 AMR／物理／用户接口 | 度量、源项、引力、AMR、重启及两后端短验收；保住 O6 性能门槛 | 复测受影响的既有基准；RZ 收益单列，不能替代 Cartesian CPU 优化 |
| O8 | 用户物理域／自引力边界接口及收支诊断 | 边界数学、时序、后端、兼容条件通过；保住内置路径性能 | 完成后冻结长时验证版本；新增回调成本另列 |
| O9 | 复核冻结版本性能，再公共模型长时验证 | 同物理终点、科学误差、资源和长期预算分别合格 | 不承担首次达到 CPU 目标的任务；主要长轨迹约 30–60 分钟 |
| O10 | 非均匀／映射网格和 AMR 设计讨论 | 给出选型与影响清单 | 本轮不实现新的网格体系；实施后须另建结果版本 |

执行链：**有界基线诊断 → 共享数学优化 → CPU／受影响 CUDA 短验证 → O6 版本冻结与性能验收 →
O6+ 跨模型诊断与深度优化 → RZ／BC 修改、短验证及性能防退化 → 最终版本冻结 → 性能复核 →
长时科学验证 → 网格后续讨论**。
每轮短计时只对应已经通过数学检查的固定版本；开发／编译与采样错开。这样先优化再长测，
同时能在 O6 内及时检验优化是否足够，不能把所有计时都拖到 O9 才发现目标未达到。
O6+ 的 ≤2 线与 O6 的科学、CPU／CUDA 合同属于本轮统一出口；未通过时保持本轮开放，
不能把失败点移交 O7／O8。后续提交也必须复核已经实证达到的代表点。

## 1. O6：CPU 与共享数学优先，自引力执行一并优化

### O6.0 必须达到的目标及比较口径

**本阶段以完成任务的 CPU 总墙钟为目标，Cellular 的正式门槛为 `T_ARCH / T_FLASH <= 10`，
并继续争取更低。它是待验证的工程要求，不是当前成绩或保证可以达到的预测。**
必须同时通过科学预算、同资源比较和通用性检查，不能用平均比值掩盖失败场景。

[历史记录](../../validation/gravity/flash/O5OptimizationReport.zh-CN.md)为 CPU16 159.49 s／
FLASH MPI1 4.56 s，约 34.98 倍。若仅按这组旧分母估算，10 倍对应 45.6 s，要求约
3.50 倍整程提速、减少约 71.4% 的墙钟。这只是工作量级估计：旧输入的 Coulomb 设置不同，
资源也不等价，不能把 45.6 s 固化成新的科学验收秒数。新输入下两个程序及优化前 ARCH 都要重测。

| 验收线 | 固定规则 | 结束条件 |
| --- | --- | --- |
| 主要性能线 | 本机同 8 个物理核：ARCH CPU8 对 FLASH MPI8，同样绑核与输出口径 | 两个预先登记的完整 Cellular 代表点，各自总耗时中位数之比 ≤10；科学预算同时通过 |
| 历史延续线 | 保留 ARCH CPU16 对 FLASH MPI1 的资源组合；使用重新对齐的同一物理输入，旧原始数据另存 | 主代表点同样 ≤10；明确仅为本机任务成本，不能替代同资源门槛 |
| 串行诊断线 | ARCH CPU1 对 FLASH MPI1；用于分离数学成本与并行效率 | 发布总耗时、工作量与主要阶段成本，不用多线程收益掩盖串行热点 |
| 后端线 | 相同 ARCH 数学、输入和误差预算，CUDA 对已优化的 CPU 生产配置 | CPU/CUDA 科学一致；代表性规模整程 GPU 正向加速，同时报告绝对秒数 |

若参考构建不能正确支持 MPI8，先恢复该能力；确实受模型约束时，两端统一单核验收并明确范围，
不能悄悄换成 CPU8／MPI1 关闭同资源门槛。线程／MPI 设置先登记；CPU16 扩展性另列，
不对每个 case 挑选不同资源组合来粉饰成绩。GPU 同时列出对 CPU8 及该输入下实测最快
CPU1／8／16 的比值，正向加速按最快 CPU 判定，不能只挑较弱 CPU 配置作分母。
未来 H100 使用同一口径另测。

- [ ] 用实测独占阶段成本建立预算。若某热点占比为 f、局部加速为 s，整程时间比例近似为
  `(1-f)+f/s`；历史 3.50 倍目标要求可优化部分至少覆盖约 71.4% 的成本，即使局部无限加速也如此。
  这只用于排除收益不足的路线，不能给未知热点预填百分比。历史输出不足 0.5%，单靠 I/O 不够。
- [ ] 在现有诊断输出中补充有界计数：EOS 逆解／迭代／插值，burn 活跃单元、RHS／Jacobian、
  线性分解、接受／拒绝子步，MG 迭代、kernel／同步和边界求值。按阶段聚合，避免每单元写日志。
- [ ] 保留运行、推进、输出、AMR 和各物理阶段的清楚计时范围；嵌套计时不得相加当总耗时。

- [ ] 在原 EOS／CUDA 失败测试入口补齐 C5 的可恢复候选失败后接受、必要失败必须停止的配对轨迹；
  不清除整个批次的错误状态来掩盖真实坏单元。

### O6.5 实施次序与未达标处理

1. **先登记基线和科学预算，再改共享数学。** 优先处理 EOS 热启动、同状态结果复用和
   BD 启步／重复求值；已有解析 Jacobian 和合并拷贝继续复用，不重新申报旧改动的收益。
2. **再处理实测执行成本。** CPU 调度、负载和工作区复用按剩余热点推进；网络分解及 MG
   各有自身证据。CPU 通过相关科学检查后再验证同一数学的 CUDA 路径，随后冻结版本短计时。
3. **整程不达标则继续 O6。** 记录阶段收益、余下热点、可消除成本及下一项修改；
   “比旧版快了”“GPU 倍数更大”或“额外物理更完整”均不能单独关闭本轮 CPU 目标。
4. **工程优化不足时另立数值方法子项。** 依据剩余宏步、EOS 或 ODE 成本，评估有误差控制的
   时间推进／面热力学或积分策略；先给独立稳定性、收敛和热闭合依据，再比较完成任务成本。
   本计划不预先授权把近似路线替换严格默认，也不把增大 CFL 或冻结温度当作已经成立的优化。
5. **目标保持可审计。** 目前没有证据保证纯工程修改足以达到 3.50 倍，更不能由旧的不等资源
   数据预测同资源成绩。如果正确性与速度目标暂时不能同时满足，阶段标记“正确性通过、性能未达标”，
   保留问题和证据，不回退物理、不抬高阈值，也不把欠账转移到 O9 后宣称完成。

**O6 出口：**关键 EOS／网络／低密度／恢复语义／重力检查通过；CPU 与 CUDA 使用同一公式；
O6.0 的 CPU 整程门槛、通用性和 GPU 代表性正向加速均有绑定版本的证据。
优化后的 CPU／GPU 绝对时间都要报告；共享数学优化可能使 CPU/GPU 倍数下降，这本身不是退化。
这一出口先于 O7 的几何实现；后续版本的复测保留该门槛，而不是让 O9 首次承担性能达标责任。

### O6+：本轮同精度、跨模型 CPU 性能验收

**目标是预登记的可比代表点各自 T_ARCH CPU8 / T_FLASH MPI8 ≤2，且两者满足同一科学误差预算。**
这是本轮未达成前不得关闭的目标，不是已有成绩或对任何输入的保证。其他预登记的共同模型也逐点要求 ≤2；
双方方程、物性、维数、边界或终点不等价时，只记录能力和成本差异，
不把它们合并进倍数承诺，也不通过关掉 ARCH 特有的正确物理来制造对等。

以 [O6 阶段记录](../../validation/gravity/flash/O6OptimizationReport.zh-CN.md)当前三次中位数估算，
A 为 50.71／5.92 s（8.57 倍），B 为 57.15／6.01 s（9.51 倍）。同一参考耗时若保持不变，
2 倍线分别是 11.84／12.02 s；ARCH 尚需约 4.28／4.75 倍**额外整程提速**。
现有 Hydro 单项已耗 31.91／38.26 s，即使 Burn 变成零成本也无法达到目标。
该估算只定位工作量，不把 FLASH 当前秒数当作后续不可变分母。ARCH 活跃单元宏步是 FLASH 的
2.40／2.37 倍，需同时核对真实宏步、AMR 历程、数值阶段及单位工作成本，不能把总差距直接归咎于 EOS。

1. **先冻结比较合同。** 本轮保留 A/B 作为固定回归点，并预登记纯流体、
   Helm 无燃烧、独立燃烧、扩散／自引力和双方都能表达的耦合模型。各模型注明公共方程和输入、
   物理终点、空间／时间分辨率、AMR 活跃叶单元、输出量及误差预算。只比较双方确实具备的模型；
   启动成本主导的小探针用于功能诊断，正式性能样本要有足够工作量。
2. **按成本结构推进。** 先剖析 Hydro 中的重建、通量、面 EOS、AMR 重网格及调度，再查宏步数量、
   网络／EOS 复用和线性代数；记录每项的调用次数、实际耗时、消除后的整程上界以及 CPU/GPU 共同收益。
   优先去除同状态重复求值、无效数据移动和不必要同步；若改时间推进、CFL 或面热力学算法，必须有
   独立稳定性、收敛、激波和热闭合依据，不能只针对 Cellular 调参数。
3. **逐点验收而不平均冲淡失败。** 固定代码版本、编译选项、绑核和完成任务的计时范围；同一主机
   8 个物理核上 ARCH CPU8 对 FLASH MPI8 各运行至少三次，报告各点中位数、绝对秒数、方差或范围、
   宏步／活跃单元工作量及科学误差。至少两个空间或时间规模检验收益不会只出现在小算例。
   CUDA 在 CPU 数学签收后复测同公式与整程正向收益，另列 GPU 绝对时间；不把 GPU 加速比折算成
   未实测的 FLASH/GPU 等价比。
4. **未达标时保留物理和证据。** 若共同误差预算下 ≤2 需要不可接受的物理简化，记录可解释的
   成本下界、未消除热点和下一项方法研究；不改预算、不放宽已有测试，也不把 O6+ 写成完成。
   O7／O8 不承接本轮未完成的 O6／O6+ 出口；O9 长轨迹使用已完成共享数学优化并冻结的版本。

### O7.2 度量、流体和输运

轴对称单元代表完整旋转环体。建议二维 RZ 对外使用完整 `2*pi` 积分量，与 FLASH 的
轴对称物理含义对齐；内部可约去公共常数，但所有模块、边界质量矩与输出必须用同一约定。

```text
V       = pi * (r_right^2 - r_left^2) * Delta_z
A_r     = 2*pi*r_face*Delta_z
A_z     = pi * (r_right^2 - r_left^2)
h_r,h_z = Delta_r, Delta_z
L Phi   = (1/r)*d_r(r*d_r Phi) + d_z^2 Phi = 4*pi*G*rho
```

这些是计划的统一约定，不是新增的另一套后端数学。
FLASH 对二维 cylindrical 的定义及有限体积说明见
[官方几何文档](https://flash.rochester.edu/site/flashcode/user_support/flash_ug_devel/node65.html)。

- [ ] 复用 `GridMetrics` 的环体积分、面面积、物理长度、体积平均 `1/r`；更新 `GridGeometryView`、
  `PhysicalPosition` 和 CUDA 度量缓存。不能仅修改 CFL 而漏掉轴向面积。
- [ ] 几何源项继续只有 `GeometricSources.h::add_geometric_source_cell` 一份；
  2D 柱坐标的第二动量是 z，第三动量保留方位速度的含义。
  轴对称不等于无旋流：离心项及角动量耦合复用 3D 柱坐标公式的无方位导数特例。
- [ ] 同步扩散梯度、矢量基旋转、黏性几何项、诊断速度分量、div／vorticity 和 AMR 指标；
  保持恒压静止态的压力通量与几何源项相消，不添加额外能量源补偿。
- [ ] 轴线标量／z 分量按偶对称，径向及方位速度按奇对称处理；没有实际方位轴，
  不再执行旧的跨半圈 donor 搜索。非零内半径是物理边界，不等同坐标轴。
- [ ] 对缺少物性闭合的 Helm 黏度／组分扩散通道保持明确能力限制；几何公式通过不代表材料模型补齐。

### O8.1 一个注册入口、不同物理结果

| 物理对象 | 首批明确支持的用户控制 | 核心约束 |
| --- | --- | --- |
| 流体 | 保留 periodic／outflow／reflecting，增加指定入流／用户 primitive 边界 | EOS 构造能量，组分完整且有效；法向、时间和单位明确；普通 outflow 不宣称非反射特征边界 |

### O9.3 30–60 分钟如何使用

1. **科学比较先固定物理终点。** 在最终优化版本上，以特征时间和收敛需求选 t_end，
   再选相同分辨率／问题规模，使主要 CPU 长轨迹约 30–60 分钟；GPU 与 FLASH 完成同一任务。
   GPU 提前完成是结果，不为凑满一小时单独增加它的终点或精度。
2. **后端耐久性另列。** 若同任务 GPU 运行过短，再选一个共同扩大的问题，或明确登记独立
   30–60 分钟后端持续运行组；后者只能用于长期稳定性，不拿不同工作量相除当加速比。
3. **墙钟只是资源预算。** 长时间须覆盖多个相关动力学／扩散／反应阶段和反复 AMR。
   不用过小 dt 或已经完全停烧的静态尾段制造“长时验证”。超过预算可保存检查点并标记未完成，
   不能把被超时杀死的运行判为通过。
4. **检查点检查覆盖中段。** 连续轨迹与同后端／跨后端续算到同一终点配对；
   用预先固定的采样时刻核对场、拓扑、预算和错误状态，不只看最终一帧。
5. **正式短计时重复，长轨迹按科学需要重复。** 短代表点采用交替顺序及多次独立样本；
   长轨迹初次优先覆盖各模块和关键耦合，发现漂移、波动或随机性后再有针对性重复，避免组合爆炸。

## 5. O10：Grid／AMR 后续设计讨论，最低优先级

本阶段只产出选择依据。AMR 本身已经造成跨层非均匀分辨率；这里讨论的是块内物理网格映射、

| 方向 | 可复用部分 | 主要代价与待回答问题 |
| --- | --- | --- |
| 单调径向拉伸／逻辑到物理映射 | 保留 Morton 和逻辑细化，由 GridMetrics 统一真实面位置／体积／长度 | 当前单一 dx 假设、重构、粗细插值、椭圆算子和度量缓存需重审；拉伸本身不能保证解除极点角向限步 |
| 定向细化或角向选择性粗化 | 原指标和有限体积守恒思想 | 现有各向同性四叉／八叉层级、邻接、接合和 MG 层级会受影响，不能只改 refine 阈值 |
| 轴／极点合并单元或多块坐标图 | 共享通量和几何度量接口 | 拓扑、跨图矢量、AMR、CUDA 访存和 Poisson 都需重新设计与验证 |
| 局部时间步／层级 subcycling | 现有 stage／flux register 可作为基础 | 自引力全域场时刻、burn／diffusion 分裂、reflux 和重启一致性复杂，不能当纯网格优化 |

优先用 O9 中实际限步单元、物理长度比、RKL 阶段和 MG 迭代证据讨论径向映射与定向策略。
