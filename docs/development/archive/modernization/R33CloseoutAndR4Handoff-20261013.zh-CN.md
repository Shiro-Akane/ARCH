## R4.1：原runner组门槛保护

**W2唯一写入**：[原runner](../../../../tools/validate_backend_results.py)、[现有工具测试](../../../../tests/tooling/validation/test_validate_backend_results.py)；必要时更新其现有使用说明。原manifest由Codex保管，默认不改；不另建runner、诊断模式或证据框架。

当前backend manifest有22个case、5个三档组和7个非组case。任何显式`--case`目前均跳过所有组检查，包括显式选择全部case。R4冻结如下最小语义：

| 选择方式 | R4目标行为 |
| --- | --- |
| 不传`--case` | 原完整manifest执行及组门槛保持 |
| 显式选择全部case | 与不传选择的组检查一致，不能绕过 |
| 选择一个或多个完整组 | 按**原manifest成员**确定完整性，对被选完整组调用原`validate_resolution_groups`，保持原摘要与门槛 |
| 触及组但未选齐，含完整组＋部分组混选 | 在科学执行、provenance捕获和证据写入前拒绝，列出缺失ID，不自动补选、不发布科学PASS |
| 只选非组case | 保留限定逐case检查，组摘要为空；不能当完整矩阵签收 |
| 未知ID | 原科学入口的明确拒绝保持；`--unit-test`仍是manifest检查，不是科学验收 |

这是有意收紧科学验证选择语义，不保留旧单个组成员选择的兼容路径。若将来需要独立诊断用途，应另行明确；本批不添加模式。既有`resolution_groups`保持`resolutions/orders`结构，完整矩阵消费者继续核对全部manifest及原组摘要，不放宽为接受子集。

最小main级检查：隐式／显式全选；完整组正对照；逐case误差可接受但CPU或CUDA组阶数失败；部分／混合选择预执行拒绝；非组限定结果被完整矩阵消费者拒绝；未知ID及缺失／非有限科学指标不能写成功证据。复用已有time/order、final/all及完整矩阵测试，不据不可能的返回路径新增通用防御校验。

验收先运行现有工具owner的定点unittest。mock仅验证入口控制流，不新增科学PASS；R4.3再接真实短组。回退只撤本包工具／测试／文档改动；原选择缺口随之重新开放，不能将回退状态记为已修复。

**测试路径须绑定当前工作区**：现有CPU／CUDA构建的`CTestTestfile.cmake`仍将该工具测试绑定到`/home/shiroakane/ARCH/tests/...`。R4直接用`work` Python运行本工作区的对应测试文件；不能用旧构建的CTest通过代签修改后的runner。只有注册源码路径与本工作区一致时才复用CTest，无需为Python检查另做配置或构建。
