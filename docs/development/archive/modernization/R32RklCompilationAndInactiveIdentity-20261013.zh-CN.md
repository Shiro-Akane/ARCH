## RKL：成本主要在设备代码生成与汇编

复用R2原NVCC 12.3／g++-12命令、`sm_86`、`-O3`及全部严格浮点选项，旁路ccache。136项项目编译依赖逐文件与当前worktree核对相同；仅将输出移至新目录，并增加`--time`、`--keep`、`--keep-dir`和`-v`。原源码、时间戳及已接受执行物保持。

`cicc + ptxas`合计401.408秒，占NVCC报告阶段时间91.236%。外层护栏启动至命令退出为428.107秒；**阶段累计与外层wall口径不同，不能将该占比当作wall分解。** 原CSV最初八行来自`--dryrun`的管理计时，已明确排除，原文件仍保留。R2的392.041秒包含原目标链接，本轮为增加观察开关的单TU编译，不构成跨版本性能对比。

原链接库哈希核对一致；链接0.586秒，原完整RKL叶子测试1.577秒退出0，仍执行冻结Host权威、EOS失败、算子／步长、RKL阶段和Native输出检查。该结果只重新确认此叶子，不扩张为全工程非回归。观察产物对象哈希与R2不同，不能宣称字节一致；生产CPU／CUDA主ELF未重建。

### 模板矩阵与一次有界消融

保留产物有24个PTX kernel、19个device function。十一份EOS特化的扩散kernel占全部PTX定义字节约94.20%，直接RKL首阶／递推两核约1.05%。按包含相关device helper的家族统计，Tabular3D约27.39%、Tabular4D约27.05%、IdealGas约25.96%、StellarOverride约16.65%。这些是**代码量**，不能据此分配编译时间，也不能把成本单独归咎于表插值。

第二次且最后一次诊断只在`output/modernization/r32-20261013/rkl-profile-2/`副本删除`verify_tabular_diffusion_latch(eos3, 2)`和`(eos4, 4)`两条调用；保留所有include、函数定义、原数值预算和编译选项，观察上限300秒。原完整测试不改，消融版不运行、不链接为科学验收，也不会采用为优化实现。

| 诊断前后（各一次） | 原完整TU | 移除两条调用的副本 |
| --- | ---: | ---: |
| 外层wall秒 | 428.107 | 208.784 |

两条Tabular调用对应的六个特化已从副本产物中消失，PTX kernel由24变18，IdealGas／StellarOverride及十三个其他kernel保留。消融支持该特化矩阵是此TU的重要成本贡献者，**不代表删测试可作为优化，也不证明拆分后的总构建收益**。两次均在各自600／300秒上限内完成，无资源截断；诊断到此停止，不追加第三次试验。

**归因决定：** 已定位到本测试TU内多EOS扩散kernel的设备生成／汇编成本；预处理不是本轮主耗时。RZ／AMR／gravity传递包含和Host-only lambda告警存在，但没有测得其独立成本，不能直接以头文件扇出为由拆共享数学。通用传导率的运行时选择也不能仅凭产物体积改成新模板层。

后续可评估按测试职责分开Tabular失败／恢复与常用IdealGas／RKL叶子，使常用路径按需编译；落点优先现有`tests/cuda/numerics/`及`cmake/tests/CudaTests.cmake`。是否值得拆分须测相关编辑的增量成本、全部测试构建总成本及RAM，保留全部检查和原预算；本轮没有证明拆分会降低全工程冷构建或运行成本。

源码入口：[原测试](../../../../tests/cuda/numerics/test_diffusion_rkl_parity.cu)、[目标归属](../../../../cmake/tests/CudaTests.cmake)、[设备扩散kernel](../../../../src/cuda/diffusion/DiffusionKernels.cuh)、[共享通量](../../../../src/numerics/diffusion/DiffFlux.h)。不为测试编译另复制一套公式。

## 未活动配置：区分审计身份与重启控制

| 身份 | 当前实际职责 | 本轮判断 |
| --- | --- | --- |
| raw／lexical摘要 | 保存原输入文本；注释、显式字段或文本变化可改变摘要 | 保留，不能用它代表物理等价 |
| typed configuration record／effective摘要 | 记录最终typed存储及实际解析执行策略；包括未活动存储和输出控制 | 保留完整审计记录；变化本身不是数值错误，也不等于重启不兼容 |
| checkpoint provenance＋`StateControlIdentity` | 实际重启分别核对模型／EOS／网络等来源及20项数值控制，控制格式revision为3 | 三个已测未活动数值控制仍会触发保守拒绝；值得后续单独判断其维护收益 |

`dt_init`、`ode_solver`、`ode_rtol/atol`都是Burn条件必填、无输入默认。未活动且省略时inspection的resolved/source为null，typed存储仍有初始化值；合法显式值则保留parsed／resolved及`source=input`，同时显示not-applicable。八项原CPU ELF静态检查确认了该区别；**not-applicable不等于删除显式值，更不能将初始化称作活动科学输入默认。** 其他六项内部ODE工作控制属于登记辅助默认，不能把它们与rtol／atol混称一类。

### 真实加载与重启的最小对照

新增诊断程序仅置于本机output目录，调用现有`RuntimeParams::LoadText`、配置记录、执行计划、checkpoint provenance及实际`read_chk`，不复制身份算法。复用九个同源GCC13对象；`-O0`仅用于这个控制诊断TU，不改变RKL／生产构建选项。输入从既有BurnOneZone验证输入派生为ideal EOS，禁止模型构造；生成一份18,760字节人工单块checkpoint，不是原模拟数据。

| 对照 | 实际结果 | 意义 |
| --- | --- | --- |
| 未活动三键省略，原配置恢复 | 加载与重启通过，0→1块 | 人工fixture可被真实reader接受，拒绝不是无效fixture造成 |
| burn关闭，分别显式改变`dt_init`／`ode_rtol`／`ode_atol` | 三项加载通过、加载边界完整、ODE计划none、provenance相同；配置记录及控制向量不同，重启明确拒绝；均保持0块 | 合法未活动输入确实影响重启控制，在拓扑修改前失败；不是仅用原始C++字段突变推断 |
| burn关闭，改变`ode_solver` | 配置审计记录不同，控制向量相同，重启通过 | solver字符串不在该数值向量，不应泛化为全部ODE字段均拒绝 |
| 仅改变输出目录 | 配置审计记录不同，控制向量相同，重启通过 | 完整审计身份与轨迹控制身份各有用途 |
| 两项原始存储突变 | `RequireLoadedValues`拒绝未声明修改，配置记录不可取得；控制比较也不同 | 仅为不可达raw负对照，不能当作受控入口可静默改配置的证据 |
| 激活burn的正向区分 | 配置可加载，ODE不再none，来源／控制不同，不能恢复原非burn fixture | 条件语义并未统一降为忽略 |
| 四项未活动非法值／选项与一项活动cfl缺失 | 五项加载均明确拒绝 | O7缺项和错误拒绝保持；没有用默认掩盖错误 |

合计14项预期诊断行为通过，另有8项原ELF静态inspection。首次探针将RuntimeParams的ENUC禁用警告写入尚未结束的JSON行，记录解析失败；原源码、对象、日志和失败身份保留。一次定点修复仅使整行记录在调用结束后发布，警告保留，未改输入或生产逻辑；复跑后完成上述验收。诊断通过不授予新的燃烧／Hydro数值验收。

### 维护决定

保留完整审计记录与当前严格拒绝，不以过滤所有未活动字段来“统一身份”。将R3-A04从抽象假设更新为**已复现的保守重启限制**：以后调整未活动存储初始化，或用户仅修改这些非burn控制时，可能改变恢复资格。

若后续确有需求，评估仅为重启控制建立按活动条件的投影，复用现有物理条件来源；保持活动值、非法值及缺项拒绝。必须先冻结适用字段、revision及正／负对照；变更受保护重启契约须按已保留决策处理，旧格式可直接拒绝，无需兼容层。本轮不改变20项向量、revision、默认、格式或准备校验；所测输入及身份对照未出现静默补默认，不据此宣称全仓所有数值路径无回退，也不开放整套配置重写。
