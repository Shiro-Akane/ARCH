## O7：是否仍有静默回退

在本轮核验范围内，未发现活动关键科学配置的静默回退。CPU／CUDA 两个生产二进制分别对 70 个必需或条件必需键 执行缺项负对照；显式错误、未知方法、退役键、缺失资源及重启失败均被拒绝。25 项登记的辅助默认、具名模型定义和显式 auto 按现有契约保留。关闭模块后的存储值仍参与身份比较，属于后续身份维护候选；旧输入缺项会硬失败，不能把回填生产默认当作修复。

| 动态范围 | 实际结果 |
| --- | --- |
| 95个标准键 | 两个binary均为19常规必需、51条件必需、25登记辅助默认；与[Core注册表](../../../../src/core/config/StandardParameterEntries.inc)一致 |
| 70个关键键×两个binary | 140次活动条件下删键：退出3、对应`MISSING_PARAMETER`、resolved/source为空；第三轴用真正3D输入激活 |
| 88类显式坏类型／选项×两个binary | 176次明确拒绝；包括关闭模块的坏输入和带允许默认的字段，没有用默认替代错误 |
| 25个允许默认×两个binary | 50次省略检查仍完整；missing/parsed为空，resolved值来源为`documented-default` |

| 其他静态对照 | 语法、重复、未知、退役与case缺项／坏值均拒绝；合法零和false保留。以上合计440次inspection |
| 20次实际运行入口对照 | 18次预期失败：缺关键项、未知方法／键、缺配置文件、显式CUDA无设备／未编译、缺EOS表、缺checkpoint；无演化H5或完成宣称。另2次短`auto`运行选择CPU并记录真实原因 |

缺项／坏输入的早期拒绝没有建立输出目录；资源拒绝可保留诊断日志。静态inspection按契约不检查表／checkpoint是否存在，也不承诺完整模拟可运行，资源问题由实际入口负对照补查。

源码独立复核的关键锚点：

- [输入解析](../../../../src/core/config/InputResolution.h)只应用登记默认，显式输入包括坏输入始终优先，不被模型提供值覆盖；[配置聚合](../../../../src/core/config/ConfigurationInput.h)在模型构造前拒绝已知错误及未完成声明。
- [SimConfig::Get](../../../../src/data/GlobalDefs.h)的legacy fallback参数仅供读取跟踪，缺失／未声明／标准键读取直接抛错；[SetupChecked](../../../../src/interface/ProblemGenerator.h)拒绝未声明的配置改写，运行快照不能从未完成配置直接构造。
- [策略解析](../../../../src/driver/dispatch/PolicyDescriptor.h)只有`UnknownPolicyBehavior::Error`；[后端解析](../../../../src/driver/dispatch/capability/BackendCapabilities.h)对显式CUDA不可用抛错，显式`auto`才可选择CPU并写原因；[EOS](../../../../src/physics/eos/eosdispatch.h)与[checkpoint](../../../../src/io/chk/CheckpointCompatibility.cpp)维持资源／身份拒绝路径。

有两类后续维护事项，均不应误写为当前活动配置静默回退：

1. 关闭burn后的`dt_init`／ODE等存储初始化值仍参与配置／重启身份，而inspection显示not-applicable／null。当前非burn步长不受`dt_init`限幅；未来改初始化值可能影响身份，应在阶段3评估，不能把条件必填改成允许默认。
2. 六份R2.2旧Hydro输入及新增发现的`simulation/Cellular/CellularFlash2D.par`仍缺明确声明，当前加载会硬失败。保留原输入和拒绝证据，后续区分活跃模板与历史比较；不在本轮借补默认恢复运行。

Gaussian的空间组分由模型定义，显式外部组分在API中标为not-applicable；这沿用已有V3测试。未活动的合法字段可以保留；有无科学消费与词法合法性分开。原始`SimConfig{}`存储值不能绕过受控运行入口，`auto`写入plan sidecar已满足记录契约；无需为这些事实增加新的兼容层或重复输出。
