## 控制参数与输入迁移

标准目录从 90 项调整为 88 项：删除 `enforce_mass_conservation`、
`burn_verbose_level`、`ode_use_numerical_jac`、`ode_freeze_jacobian` 和
`timeintegrator`；登记已被运行时使用的 `dt_init`、`dt_min`、`tstep_change_factor`。
旧键会报 `RETIRED_PARAMETER`，不会悄悄转成自定义算例参数。
`BurnConfig::ignition_temp` 和 `burn_tol` 没有实际消费者，已删除。

参数仍按物理归属存储：ODE 精度在 `BurnConfig::odeconfig`，密度/内能界限在
`NumericsConfig`，引力控制在 `GravityConfig`。Core 和文本输入没有 `AdvancedConfig`
或高级标签。GUI 是否隐藏某个现有参数由 GUI 负责人决定。
`gravity_G` 保留现有 CGS 默认值和身份；自引力尚不支持，不添加没有消费者的 MG 选项。

`ConfigValidation.h` 集中检查有限性、正值、上下界、组分数量与 `smallx` 的关系，
以及时间步、燃烧、扩散、引力与网格控制的交叉约束。配置检查和实际 Setup 后验证复用它。
配置合法仍不等于 EOS 有效域覆盖算例，也不等于模拟已经具备运行条件。
初始化触发下限修复后重新检查 EOS 的温度、压力和声速，避免把修复后越域的状态发布为初始解。

## 小值处理的职责

| 对象 | 实现和边界 |
|---|---|
| 密度 | 物理下限使用 `sml_rho`；叶函数使用真实正密度，不再私设 `1e-12` 或将低密度格子关闭 |
| 比内能 | 使用 `min_eint/max_eint`；正但偏低的可解析状态可以兜底，超上界和消减后无法解析的热能拒绝 |
| 温度 | 燃烧工作态使用 `smallt`；`nuclearTempMin` 仅控制激活，不再用作内部阶段温度下限 |
| 组分 | 网络初始化复用 `smallx`；Hydro 允许合法零组分；全零输入不再变成均匀混合物 |
| EOS | 不用伪造声速、Cv、gamma 或理想气体回退把无效查询变成成功 |
| 时间 | ODE 停滞按 `t + dt == t`、非正/非有限步长判定；不使用固定秒数门槛 |
| 线性求解 | 稠密 LU 使用按行尺度选主元，拒绝零/非有限主元；整体缩小的良态矩阵不因绝对主元阈值被拒绝 |
| 算法容差 | PPM 相对曲率、ODE 无量纲控制、表格反解残差等保留在算法内部，不扩充用户参数面 |

`StateAdmissibility.h` 统一恢复速度、动能和比内能，使用动量与速度乘积，避免先平方
极小密度或动量。热能与总能量/动能消减误差同阶时直接失败；P1.5 没有额外双能量字段，
也没有把高马赫数下丢失的热能称为可恢复状态。

Timmes 原始反应闭合中的摩尔丰度 `1e-30`、反应率保护和 NSE 收敛标准保留其来源数学语义，
没有机械替换成质量分数 `smallx`。这类内部保护不等于允许任意低温/低密度核反应模型外推。

## 守恒、错误传播和重启

Hydro 在重构和共享面通量处使用保守限制，所有守恒分量与组分共用同一面系数，
限制后的面通量再进入 AMR 通量寄存器。局部 Lax–Friedrichs 中间态的凸组合给出
Cartesian Euler 更新的充分条件；源项、任意表格 EOS 和 AMR 粗细界面不能仅据此宣称正性定理。

CFL 的单元候选加入双面因子，相同输入 CFL 下允许步长通常比旧式更小。
这会影响步数和运行成本，属于明确的数值行为变化，不能把旧吞吐基线直接作为本版性能承诺。
接受阶段、扩散、燃烧以及 reflux 后还会验证候选状态；失败不产生成功完成凭证。
CPU 工作者将异常传回主线程，避免从 OpenMP 区域直接退出整个进程。

正值兜底保持速度和组分，记录体积加权质量、动量、总能量和物种质量改变量，
包括有符号量、绝对量、次数及一个触发位置/阶段/时间。
RK 各阶段贡献按最终解权重累积，次数保持实际事件数；失败宏步不能导出为有效重启态。
运行目录的 `state_repairs.txt` 与检查点保存账本。

检查点格式提升至 5，必须包含状态控制身份、修复账本和科学来源身份。
恢复前检查输入完整状态和组分，随后才替换 AMR 网格；旧格式和不一致控制明确拒绝。
修复账本不是严格守恒证明，必须结合物理算例的体积分预算判断。

输出还有独立的 EOS 有效性检查：即使所选 plot 字段没有温度或压力，也要求温度、压力和
Gamma1 有限为正。检查点同样检查物性，不能把返回 NaN 的 EOS 查询静默保存为可用结果。
它在已有输出 materialize 之后读取 Host 数据，不增加逐格设备传输，但会增加输出时的 EOS 查询成本。

## EOS 和配套退役

- 删除规范化 HDF5 的旧 direct 表示、缺省模式猜测、缺省组成猜测、宽松越域回退与旧无界反解。
  随旧路线失去全部消费者的 `finite_difference_dp_drho_e`（包括其绝对 `1e-300` 扰动兜底）一并删除。
- 保留严格自由能 3D/4D、原生 EOSDriver、baryonEOS、Helmholtz 和 IdealGas 的现行路线。
  原生 EOSDriver 的字段表示与已删除的规范化 direct 格式不同。
- 规范化源要求明确 schema、秩、自由能模型和物理成分/NSE 元数据。
  4D owner 只管理自由能导数字段及有效节点掩码；3D 只以 native 状态区分两种现行来源。
- Helm 温度/压力反解受源表范围、迭代次数和残差约束；直接在温度坐标做有界 Newton，避免 `exp(log(T))` 损失已有根的精度。退化到几何二分，并仅在残差合格时接受浮点收缩到极限的区间。低于简并压力下界的输入现在会失败。
- 删除 `IGravityPolicy::update_field` 的无效接口和稀疏燃烧旧别名头文件。`GravityNone` 保持原行为并入 `GravityDispatch.h`，不再保留独立的 28 行文件。
  现行求解器和 KLU/cuDSS 的算法实现保留。

旧行为的成功测试改为明确拒绝测试；现行路线继续保留解析/独立物理参照，
CUDA 的字段长度、错误锁存、移动语义和异步生命周期检查迁移到现行表示。
不得用删除现行路线或放宽误差预算代替修复。

## 验证证据与复现

`validation/low_density/manifest.json` 固定密度尺度与验收预算；`run.py` 执行真实 ARCH，
读取输出检查点检验解和账本。它需要 Python、NumPy、h5py；这些仅为验证工具依赖。

```sh
python3 validation/low_density/run.py --arch bin/ARCH \
  --backend cpu --output-root /tmp/arch-low-density-cpu
```

当前 72 个 CPU/CUDA 算例覆盖三种重构的三档网格/四档密度尺度、独立双稀疏波参考、
外引力解析解、主动触发下限与重启、AMR，以及 `10^6/10^12/10^18` 密度对比、
五种通量实际推进、三档主动下限的全域/固定区域扰动预算、三档非活跃下限敏感性、RKL1/RKL2 组分扩散解析衰减。
叶函数另覆盖至 `rho=1e-100`，并验证 Fourier 热通量、CFL、LU 与异常输入。
完整推进的极低密度证据针对 IdealGas；表格 EOS 必须遵守各自源数据域。

CPU 通过后运行相同 GPU 矩阵、受影响 CUDA 回归和内存/竞争检查，并记录真实设备、
编译开关、诊断传输量与性能。CUDA 状态检查复用已有阶段内核和紧凑状态汇总，
不引入逐格主机传输。每次 Hydro 阶段下载每块 `(10+2*N_species)*8` 字节的修复汇总；
AMR reflux 在原有同步点增加 4 字节状态读取。新增并发测试让 1,025 个单元同时触发修复，
覆盖原子累加与末尾不足一块的线程。对应的 GPU 数值、跨块计数和并发内存/竞争验证已运行，完整记录随本次封包保存。

## GUI 合并边界

本轮不修改 `studio/`。GUI 应重新读取 Core 的 88 项目录，删除五个旧键的控件，
按物理分组保留现行参数。配置/预览仍是 CPU 路径，CGS 单位继续作为统一契约。
严格 EOS 和初始化失败可能使以前依赖静默回退的预览显示错误；GUI 应呈现 Core 诊断，
不能自行填入被退役的默认物理值。历史响应快照与当前接口示例必须明确区分。

## 内部数值保护的保留范围

球坐标涡量诊断的 `sin(theta)` 极点保护、Löhner 无量纲正则、PPM 相对曲率、
Helm/表格反解残差和 Timmes 来源反应率保护仍归算法所有。它们没有被统一成有量纲的
密度/温度下限，也没有变成新增用户配置。`dt_min` 约束宏步，ODE 内部以浮点可推进性和工作上限停止。

严格自由能和原生表格反解的回代误差改为目标值/回代值的相对尺度；不再使用
至少一个 CGS 能量单位的绝对容差。`1e-30/1e-100` 的合法根与无根拒绝有独立测试。

HLL/HLLC 的波速包络现在包含左右两端与 Roe 波速。独立 `roe_reference.py` 按同一已声明包络
用 70/90 位精度、Euler 跃迁条件和线性方程重算参照；同时用谱投影和 Mach 多项式独立验证 SW/VL 路由；Roe 参照与既有数值误差预算保持。
原先依赖绝对截断或非物理测试态的测试改为有效输入与明确失败检查，没有采样程序输出来更新真值。

当前 CGS 默认 IdealGas 的参照从旧 SI 热容快照迁至长双精度解析方程；自定义组分的既有冻结参照保留。
表格错误锁存夹具采用可精确插值的自由能多项式，避免把多根歧义表误用为成功控制组。
这些迁移同时保留无效域、失败锁存、跨块隔离、移动生命周期和真实 Host/Device 精度检查，
没有采样新程序结果来刷新通量真值。

### CUDA 构建的 CPU 检查接口

最终回归发现，启动时直接链接 cuDSS/cuBLAS 会在 CPU 检查接口施加限额前映射
1,124,072 KiB 虚拟地址空间，已经超过原定 1 GiB 限额。改为在首次稀疏求解构造时
统一加载配置的库并解析函数；设置限额前的地址空间降至 300,780 KiB。
限额和 GUI API 测试保持不变，实际 cuDSS 求解另行验证。版本检查、残差门槛和 GPU
数值实现保持原有契约；验证身份同时记录 provider 归档和运行时库。

CUDA 状态边界测试保留 PI 的内部无量纲阈值，但要求任意有限正 Cv 原样保留；
LU 的旧绝对 `1e-20` 拒绝测试迁至解析单方程解。时间步归约保持逐位的串行候选最小值检查，
不再把已退役的 `1e10` 截断当作正确答案。微小 ODE 区间的工作预算失败与真正不可表示的
步长停滞分开验证，失败状态、NSE 重试次数和原状态保持都必须匹配契约。

CI 将 `low_density_math` 列为必需发现项，并在完整 CPU CTest 后运行 72 个实际推进算例。
固定科学预算不变，验证依赖 NumPy/h5py；报告保存指标、输入和日志，不上传生成的 HDF5。
本轮本地验证了工作流 YAML/脚本语法与同一运行器；远端 CI 的状态须以该提交的实际任务为准。

最终 CUDA 构建的全部 129 个 CTest 分成 113 项已冻结目标与 16 项最后完成的燃烧策略目标运行，
合计无遗漏、失败或跳过。相同 Release 程序在 CPU/GPU 的 72 次推进中，流体字段与修复账本
完全一致，组分最大差为 `1.5543122344752192e-15`；各自同时满足独立物理参照。
16 次 sanitizer 对应八个当前可执行文件的 memcheck/racecheck；记录核对了实际二进制身份。
P1.5 到此完成，P2 尚未开始。旧检查点 v4 不再兼容；当前格式为 v5。

封包时保留了 Windows 的 import-library 直接链接方式；延迟加载用于 Linux/WSL 的受限工作进程。
重新构建后的全部 Linux 可执行文件与验收时逐字节一致，相关稀疏归档身份同步更新。
本证据不宣称完成 Windows 原生运行验证。
