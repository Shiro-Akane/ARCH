# 曲线坐标引力功的单元侧存储修正

当前维护者统一负责 Core、数学、物理、接口和最终科学验收。本节点记录已执行的修复及其实际范围。

曲线坐标下，面加速度可以由相邻单元共用，能量功系数还包含各自的单元势和体积。原实现把左右两侧系数写入同一个物理面槽，后一次写入覆盖前一侧。真实宏步的独立逐单元功核对首先发现此问题；原失败证据和门槛均保留。

共享公式保持 `w_low/high = ±2 A/V_i (Phi_f-Phi_i)`。例如相邻径向区间 `[1,2]`、`[2,3]`、轴向长度为1、中心势输入 `Phi=r²`，原面值行取两个中心的平均 `17/4`。左侧 high 系数为 `-16/3`，右侧 low 为 `-16/5`。共用一个槽产生的总功偏差为 `+16π/5·dt·Frho`，属于实际存储错误。

`GravityPatchView` 现在提供按同一 padded cell offset 访问的 `work_low`、`work_high`。曲线坐标复用原六个单元侧行及 Host RowsWork，通过独立拓扑 gather 写入六个分量数组；物理面加速度的布局保持。Cartesian 两个指针仍指向原 lower face 和偏移后的 upper face，计算值及顺序不变。CPU/CUDA 消费同一视图和原功函数，旧 `work_faces` 接口已退役。分配前检查总数组长度及整数乘法范围。

现有 `self_gravity_lifecycle` owner 中增补二次势的实际 Host 行和新 gather 检查，覆盖轴／离轴、相邻单元、混合 AMR、padded/inactive 槽和非法元数据拒绝。原线性势检查及误差门槛保持，没有增加 CI 测试项。实际 owner 编译13.199秒、运行11.071秒通过。

真实 uniform Euler 观察批次使用被动宏步、同次只读观察宏步、真正 accepted Current 后场及工作前故障，共四个实际求场。修复后277.692秒通过；连同原125.691秒失败累计403.383秒，在预定600秒内。七数组 bitwise 透明性、逐单元功／质量、原能量收支、完整故障回滚均通过，未修改源、G、rtol/atol、最大迭代数或科学容差。生产与可执行文件的晚观察身份记录在结束后保持一致；该时间记录并非启动前检查。

此结果签收存储修复和同次计算账本。点势端点的总能量科学状态仍为 `UNVERIFIED`：真实 `L-Q≈0.107445`，`S-B_G≈-589111.286`，后者需要分别核算离散残差交叉项、边界／内部 Green 缺陷及点势和体平均势的差异。大势能基值和小账本误差不能替代该出口。混合 AMR 总能量、实际反应四模块、CUDA 科学／加速、长时与公开 Native 能力仍按总体计划验收。
