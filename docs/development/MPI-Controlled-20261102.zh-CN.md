# MPI 最新主线整合与通信验收（2026-11-02）

本轮完成最新 main 整合、受控测量，以及由测量支持的 X 面通信修改。完整数值回归通过；
最终性能以本报告的应用前后对照为准。AMR 兼容、GPU 求解与 checkpoint/restart 不在本轮范围。

## 实现与边界

- 已整合朋友仓库 main 2e05e66e（v1.4.1）；整合提交 be858c6d。
- 814b8118 修复 MPI 开启时单进程 CLI 错误退出丢失缓冲 JSON 的问题；多进程仍按原方式中止。
- X 面交换仍位于现有 GhostExchange::ExchangeRemoteRootFaces：在原有四段工作缓冲区中先提交两次接收、两次发送，再立即 MPI_Waitall。原有计数检查和散射顺序保持不变。
- 请求是函数内局部变量，返回前全部完成；没有计算与通信重叠，也没有新增 MPI 管理器、内存池或分区抽象。
- 全局 CFL 的单次 12-word Allgather 保持原样。对照上游，src/core、src/numerics、src/physics、src/amr/storage、src/amr/transfer 无改动。

## 运行条件与测量方法

CPU 主机 gen-989544 提供 4 vCPU；开发/启动主机 gpu-273312 提供 32 vCPU，CPU 型号为 Xeon Gold 6338。
单机性能组在 CPU 主机运行；双机组在两台主机等分进程，明确使用 TCP 和 150.65.181.0/24 网络。
GCC 14.4、Open MPI 5.0.11；每进程一个绑定核心。GPU 主机存在其他服务，未宣称资源独占或测得物理网卡带宽。

每种配置预热一次、测量五次，交替执行顺序，不剔除慢样本。主指标是 max_rank(driver_seconds - output_seconds)；
启动器总耗时、输出耗时、每 rank 峰值 RSS、绑核及 CPU tick 也保存在 JSON。各 rank 峰值 RSS 之和不是同时内存峰值。
PMPI 观测单独运行，不进入性能中位数；MPI 时间包含等待，不能将各阶段最大值相加。只在同一主机内对齐单调时钟。

## 为什么保留这项通信修改

观测到二维面消息为 24 KiB、三维为 192 KiB。原有两次 Sendrecv 在两个方向上顺序等待。
独立消息实验保持相同缓冲区和标签，双机并发提交的耗时约为原来的 35%–47%；这只是筛选候选方案的证据。
最终验收依赖上面的真实求解对照。观测器确认修改前后逻辑发送字节和交换次数完全相等，
修改后每轮两次 Irecv、两次 Isend 和一次 Waitall，且无 Sendrecv；未减少计算步骤或输出内容。
