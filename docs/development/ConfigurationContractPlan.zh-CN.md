# 配置输入契约

[参数参考](../Reference.zh-CN.md) · [Core API](../../src/api/README.md) · [算例接口](../guides/SimulationCase.zh-CN.md)

配置解析将“未提供”与合法的零、`false`、空值分开记录。Core 的参数声明规定类型、单位、适用条件与允许默认值；命令行、inspection、初始预览和实际运行使用同一套规则。

## 参数来源

| 类别 | 处理规则 |
| --- | --- |
| 必填 | 必须由输入提供，缺项报告键名和预期类型 |
| 条件必填 | 根据已解析的后端、模型和物理开关判断；上游选择未知时保持未解析 |
| 登记默认 | 只有明确声明允许默认的参数可使用登记值，并保留其来源 |
| 算例定义／派生 | 由对应的准备接口生成并记录来源 |

完整键表和单位见[标准参数](../Reference.zh-CN.md)。存储初始化值和界面模板推荐不构成输入来源；数值等于默认值也不能说明它是否由用户提供。

## 解析与准备

`ConfigParser` 保留输入 token 与位置，拒绝重复键和非法格式。标准参数、所选 case 和组分声明共同决定可消费的键；未识别的键报告错误。运行时配置只在相应条件检查完成后进入准备和执行流程。

Setup 需要的网格、材料和算例输入应在调用前满足要求。实际材料登记区分模型常数、已解析输入、网络表和适配器常数。无 species 的合法模型保持无 species；材料的 A、Z、gamma、Cv 与质量分数归一化具有各自的语义和来源。

EOS、网络、引力和执行后端按显式配置选择。`compute_backend=auto` 等登记自动策略按其契约解析；显式 CUDA 选择失败、EOS 求值失败或不支持的方法组合报告错误。

准备阶段维护来源和诊断，数值循环消费解析后的数值视图。缺项判断、字符串和来源记录不进入逐单元数学与 CUDA kernel。

## 诊断与界面

诊断包含参数键、类型、条件、模块、单位及已有的输入位置。未知的上游选择不会被猜成某个物理模型；补齐该选择后，再检查它的下游条件。

配置 API 扩展版本 3 发布必填条件、适用性、允许值、登记默认和模板建议。缺失值保持 `null`。界面可以展示部分输入及其诊断；Preview 与 Run 根据各自的完整性和环境要求决定是否可用。

配置 inspection 负责声明输入和组合条件，文件系统、EOS 表、设备可用性及实际初始化由后续执行入口检查。重启还需满足检查点中的科学与控制身份。

## 维护与验证

修改参数声明时，同步其加载、消费、schema、Host 类型、参考手册及示例。测试应覆盖缺项、条件切换、非法值、重复／未知键、登记默认来源，以及命令行与 API 的一致性。数学单元可使用只包含所需字段的数值视图；应用级测试使用完整的具名配置。

参数默认、物理定义、误差阈值和科学身份的变化属于行为变化，应有明确理由及对应的数值验证。
