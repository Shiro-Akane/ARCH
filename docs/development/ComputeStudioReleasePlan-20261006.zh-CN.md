## Core规则与科学验收

1. 优先采用最新已确认的 Core 契约及接口版本，而不是仅按提交日期选整份文件。新规则必须包含双方已验收功能；旧的正确约束不可因重构丢失。
2. 同一物理规则只由一个 Core 模块维护，配置解析、API、GUI 都从它取得结果。以最新配置完整性 v3 的显式必填、条件必填、退役参数拒绝和来源记录为基础；O8 已验收的用户边界规则迁入同一入口。
3. 两份规则冲突时，记录原版本、取舍、物理/接口理由及对应测试。无法证明合理性的变化保留待确认，不能借“更新版本”放宽门槛。
4. 合并提交仅代表集成节点。计划纳入 release 的功能必须完成实现、真实接线、错误/拒绝路径、演化与实际 checkpoint 续算，以及必要后端验收。私有 fixture 的通过不等于公共 simulation 可用。
5. 不完全的功能不能自动标为非阻断。若不能补齐，必须在正式 release 冻结前由项目明确调整范围，并保持代码拒绝、API 能力和文档一致；本轮不会自行把未完成项从 release 范围删去。

本轮允许修正必要的数学与物理实现。密度、能量、组分、角动量及 CGS 单位继续按既定契约处理；CPU/CUDA 共用数学。既有科学门槛保持不变，参考解与生产实现保持独立，缺少可信参考的点保持未验收。不得用加热、软化或丢弃近轴单元来隐藏缺陷。

## 共享实现与验证收束

RZ 的扩展沿用了已验证的 `(r,phi)` 密度汇集、既有的 Poisson/MG、梯度与字段发布路径，差异限定为实际的 chart、全环 V/W 量度及物理分量。原有的 EOS 精确缓存、拓扑/几何/reflux 行缓存、批处理和共享的 CPU/CUDA 数学持续保留。需检查新消费者是否绕开这些入口，或在每个块/单元重复构建、全域扫描、分配与下载；优化改变了执行和数据复用方式，独立的物理参考、源项与误差预算保持不变。

先完成受影响模块的常规检查，失败时只增加定位所需的最小观测或反例；通过后补足确有缺口的边缘稳定性覆盖。新增断言放入既有owner，不增加平行的测试程序。数学、调用路径和输入身份未变的记录可复用；源码冻结后执行一次完整CPU清单，并验收对应CUDA消费者、同物理终点计时及长程。常规检查失败时暂停依赖该结果的重验证，可并行继续无依赖的只读审查。完整清单的缺项、跳过或失败仍拒绝签收。

常规owner用于定位接口和执行问题；独立解析／守恒参考用于发现共同实现错误。
数据处理完成后清理成功原始输出，保留输入、日志、字段摘要、身份及失败证据；仓库只接收处理后薄摘要。

## Plot／Preview与Studio

完整 `plt_XXXX.h5` 是科学数据权威；Studio 只读。可选 XDMF 是第三方桥接，可重建 `archidx` 是查询索引，不复制一套默认 FP8/FP16 科学数据。viewport 查询使用有界分辨率/LOD与缓存，Inspector 回查 native leaf cell；完整文件关闭并发布后才读取。本地 worker 克制使用资源，远端保持 data-local。当前实现与此目标的差距必须由真实 writer/reader 对照测试和说明记录，不将旧 mock 或文件读取成功当成最终科研布局验收。

Studio为可选组件，其配置、初始化、场图、AMR、演化控制和Plotfile支持分别按真实Core响应及producer身份验收。桌面交付保留原生选择器、参数／绘图／AMR交互、操作反馈和桌面关闭期间真实作业行为的检查；已有Host自动链路通过不代替完整原生交互。构建与运行环境见[Studio环境指南](../guides/StudioEnvironment.zh-CN.md)。

整套O阶段实施、必要物理数学修正、接口迁移和旧实现退役由当前维护者完成。公共RZ与CUDA能力依据最终科学出口开放，私有候选须经真实公共入口验证。当前分支允许节点提交和推送，合入main与正式发布由项目负责人控制。
