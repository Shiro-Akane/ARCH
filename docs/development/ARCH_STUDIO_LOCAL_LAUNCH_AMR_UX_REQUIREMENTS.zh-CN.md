# ARCH Studio 下一阶段需求：本地启动、初始 AMR 与参数表达

本文供 Studio、Host 与 Core 协作使用，描述下一阶段的功能、分工和验收方式。Host 指本机负责文件、编译和调用 ARCH 的服务，Core 指 ARCH 的 C++ 部分。

评审基准：`studio/phase2f-plot-presentation`，tag `studio-phase2f-v0.13.0`，commit `e97e571ba98641384aee44425a29b83255401856`。本次 Core 增量交付到 `codex/studio-core-ui-contracts`，前端接入按下表执行；文内功能描述包含已就绪接口和待完成交互。

本轮面向个人 PC / workstation，先沿用现有 WSL/Linux 本地执行环境。目标是从终端直接打开独立 Studio 窗口，调整参数，查看可缩放的初始 AMR 网格和各层级资源规模。网格展示实际完成的细化状态，资源数字用于规划，不判定未来 MPI / OMP 部署是否会 OOM。系统单位约定统一为 CGS，包括 IdealGas；本轮已对齐字段标签和 IdealGas 回退比热。SSH、集群调度、运行时 plotfile 渲染和完整 C++ 编辑器留给后续阶段。

## 2. 从终端打开当前项目

### 2.1 用户操作

建议提供一个安装后可直接调用的命令，例如以下形式。命令名称和参数拼写可以由实现方调整：

```sh
arch-studio
arch-studio --case Sod --config simulation/Sod/Sod.par
arch-studio --source /path/to/case.cpp --config /path/to/input.par
arch-studio --project /path/to/ARCH --binary /path/to/build/bin/ARCH
```

第一种从当前目录寻找所属项目；无法确定项目时，打开项目选择界面。`--source` 表示打开并关联源码，`--case` 表示选择二进制中已注册的名称，二者承担不同作用。

正常启动应直接打开独立的 ARCH Studio 应用窗口，有自己的标题、任务栏入口和文件对话框。桌面启动器负责本地服务启动、就绪检查和窗口生命周期；用户无需启动 npm、抄端口或配置 Chrome / Edge，也不依赖默认浏览器。

现有 React 界面可以继续使用，由桌面容器加载打包后的界面资源。本地 Host 通讯可以暂时保留在程序内部；如果仍使用本地端口，端口选择和连接由启动器完成。已有会话可复用，但必须核对项目身份。

首次使用缺少构建目录、二进制或运行依赖时，界面显示具体缺项及下一步。已有可用二进制时直接使用；打开窗口不自动触发长时间编译。提供清楚的“编译 / 重新编译”和“停止本地服务”入口。

安装说明需要交代如何获得这条命令以及支持的本地环境；日常使用说明只需项目打开、编译、载入参数和预览四步。

本轮可优先验证 Electron 封装：它自带 Chromium 和 Node.js，可在独立窗口加载本地页面，因此不依赖用户安装哪种浏览器。结合当前 React + Node Host，我判断这条路线改造较直接；代价是需要随应用分发运行时，并维护桌面安装包。[Electron 说明](https://www.electronjs.org/docs/latest/)、[独立窗口加载](https://www.electronjs.org/docs/latest/api/browser-window)

Tauri 也可实现独立窗口，使用系统 WebView；Windows、macOS、Linux 的渲染组件不同，现有 Node Host 还需要单独安排分发或适配。可以作为备选，由合作者根据打包和跨平台验证结果确定。[Tauri 进程模型](https://v2.tauri.app/concept/process-model/)

桌面窗口与 Core 的运行系统分别处理：Linux 桌面可直接调用本机 Host；Windows 窗口应对接本机 WSL 内的现有 Host，保留 Linux 构建和路径语义。封装成桌面窗口不等于已经实现 Windows 原生 Core。浏览器模式可以保留作可选入口，本轮默认入口是独立窗口。

### 2.2 模型列表以所选二进制为准

Core 已增加 `ARCH --list-cases` 只读查询，列出该二进制实际注册的 case。Host 当前配置中的固定列表需要逐步替换为这份结果。

每个 case 分别显示：注册名称、可用的初始场预览、可用的初始 AMR 预览，以及支持的维度和坐标系。**已注册与可预览是两个状态。** 一个 case 可以已编译、可选择，却暂时没有预览接口。

文件名也不等于注册名。例如当前 `Cellular.cpp` 注册的名称是 `CellularDet`。界面以注册名选择模型，以文件路径显示源码关联；不能根据文件前缀自动决定运行哪个模型。

界面左上方常驻显示：当前 case 名称、`.par` 完整文件名、未保存标记和编译状态。完整路径可以展开查看。允许载入任意 `.par`，沿用配对提醒和覆盖保存确认；文件名或目录不同只作为提示依据。

### 2.3 打开尚未编译或已修改的源码

| 当前状态 | 界面表达与操作 |
|---|---|
| 二进制包含该 case，且构建记录确认输入一致 | 可用当前二进制预览，显示构建身份 |
| 已有关联二进制，但源码或已跟踪依赖发生变化 | 显示“源码已修改，尚未重新编译”；提供编译入口 |
| 新源码尚未加入项目构建，或构建后仍没有相应注册项 | 显示“尚未纳入构建 / 未注册”，提供具体原因 |
| 没有可用二进制 | 可以查看源码、编辑和保存参数；预览等待构建完成 |
| 无法确认源码与二进制对应关系 | 显示“对应关系未确认”，保留二进制路径和已知构建信息 |

新源码即使暂时没有注册名称，也能作为待构建文件打开。放在项目外的 `.cpp` 不会因为被打开就自动成为编译输入；Host 应先检查它是否属于项目构建规则，再说明需要加入项目的位置或步骤。

源码改变后，已有图保留并明确标为旧结果。若用户选择继续使用旧二进制，应持续显示“使用上次构建”，不能让图看起来已经反映新源码。编译失败保留编辑内容、旧结果和错误信息；编译成功后重新查询模型和能力，再允许生成新结果。

对应关系的依据由 Host 保存，至少关联项目、源码、构建配置和二进制。只检查 `.cpp` 修改时间或 Git commit 不足以证明一致：头文件、构建选项及未提交修改也会影响程序。跟踪范围不完整时如实显示，避免给出“完全一致”的结论。

本轮可以继续在外部编辑器修改 C++，Studio 提供文件查看、打开编辑器和变更提示即可。

## 3. Grid 中的 AMR 控制

在 Grid 下增加可展开的“自适应网格（AMR）”区域。AMR 的直观说明为“在需要更多细节的位置使用更小的网格”。保持入口位置稳定，关闭时也能找到。

这些参数已有 Core 定义，本轮主要补充分组、说明和状态反馈：

| 界面名称建议 | 现有参数 | 操作说明 |
|---|---|---|
| 最低细化层级 | `lrefinemin` | 当前实现用于限制粗化的最低层级；不承诺自动将全域提升到该层级 |
| 最高细化层级 | `lrefinemax` | 允许继续细化到的层级；层级越高，局部网格越细 |
| 根据哪些场细化 | `refine_var` | 按当前 Core 支持范围选择密度、压力等，可多选 |
| 细化阈值 | `refine_threshold` | 指标超过此值时请求细化；不是密度或压力的绝对数值 |
| 粗化阈值 | `derefine_threshold` | 指标较低时允许合并细网格，应小于细化阈值 |
| 网格块容量 | `max_blocks` | 可容纳的块数；当前实现也会据此预分配内存 |
| 运行中检查间隔 | `regrid_interval` | 正式运行每隔多少步检查网格；放在二级选项中 |

层级输入为整数，并校验 `0 ≤ 最低层级 ≤ 最高层级 ≤ Core 上限`；当前实现上限为 15。阈值按 Core 规则校验。`regrid_interval` 必须为正整数，它不是“初始细化次数”。

可提供“启用细化”开关：关闭对应最低、最高层级都为 0；重新开启恢复用户此前的有效层级，或要求填写有效值。已有其他 AMR 设置保留。不能只把最高层级设为 0 而留下非零最低层级。

`refine_var` 的可选项、当前是否适用以及被忽略的原因由 Core 提供。界面可以提前指出无效选择，但不能自行换成密度细化。对只支持部分 case / 维度的 AMR 预览，显示具体支持范围。

## 4. 初始 AMR：实际格子、2:1 过渡与资源规模

### 4.1 用户看到的流程

保留当前初始场预览，增加“AMR 网格预览”。主要回答两个问题：实际细化到了哪些格子、是否集中在预期位置；选择不同最高 Level 时，网格和存储规模大致怎样变化。

显示采用常见 AMR 网格图：块边界使用较粗线条，块内计算单元使用细线，层级可用颜色区分。二维中每次细化沿两个方向二分，一个块对应四个子块；共面的相邻块层级差至多为 1，展示网格尺寸 2:1 的过渡。

缩小时先显示块轮廓，放大后显示块内单元线。支持缩放、平移、层级显隐，以及查看所选块的层级、坐标范围和单元尺寸。缩放只调整已有几何数据的显示，不重新调用初始化，也不改变科学配置。

资源表与网格图分别提供：网格标明本次实际完成的层级，资源表列出所选各 Level 的规模估算。预览可取消；修改参数先标记旧图过期，不随每次按键自动重跑重型任务。沿用现有一维、二维显示，三维交互另行安排。

### 4.2 Core 返回真实拓扑，Studio 负责绘制

实际格子需要来自 Core 已完成的初始细化流程，包括 EOS、边界数据、细化指标、相邻层级平衡和粗细网格数据转换。`RefinementIndicatorMath.h` 的指标与 `AmrTree::RippleCheck` 的 2:1 平衡复用现有实现；API 组织调用和输出，前端不根据场图颜色自行画“应当存在”的格子。

为避免完整模拟的启动副作用，Core 需要在初始细化阶段提供独立、可停止的 CPU 入口。若本次预算只能完成部分细化轮次，返回最后一次完整提交、满足平衡约束的网格，标明“初始细化尚未全部完成”。不能为满足显示预算随意丢弃部分子块或中断一次平衡提交。

返回内容以轻量几何为主：每个叶块的逻辑身份、层级、物理边界、各轴单元数或间距，以及快照完成状态。块身份使用层级和逻辑坐标等稳定信息，不能只依赖可复用的内存池编号。规则块内的单元线可由 Studio 按这些数据生成，无需返回每条线段。

网格、背景场、标记和坐标轴共用同一物理坐标到屏幕的变换。按可见区域和缩放级别控制绘制密度；隐藏过密的线条只是显示优化，不能改变原始网格数据或块数统计。

网格与背景场必须关联同一 case、参数副本和构建。若背景仍使用现有初始采样，Inspector 保留其采样标记；只有 Core 同时返回实际细化单元值时，才标为该单元的实际场值。

粗略细化趋势图仍可作为更轻的可选模式，但要与实际 AMR 网格分开命名和标记。仅提供趋势色块不满足本轮查看真实格子和 2:1 过渡的要求。

### 4.3 按 Level 给出资源提示

资源表建议包含：Level、该层网格尺寸、全域达到该层时的叶块数、网格状态存储估算，以及本次已生成网格的各层块数。全域假设与实际快照统计分列；可选粗略模式得到的数量另标为估计。

当前每次细化将各活动方向二分。对于基础叶块数 `B0`、活动维数 `d`，全域达到 Level `L` 的叶块数为 `B0 × 2^(d×L)`。每增加一级，全域叶块数在一、二、三维分别乘 2、4、8。该公式用于计算规模，不实际分配这些块；计算中检查整数溢出。

建议名称为“全域细化到此 Level 的网格存储估算”。它给出明确假设下的规模参考，不等于整个程序的最大峰值内存。Core 说明纳入哪些状态数组、组分和辅助单元；EOS、临时副本等另列已知项或未计入项。

`max_blocks` 另列为“当前配置的块池容量与基础存储”。如果全域细化所需块数超过容量，只提示“全域细化假设超过当前块容量”，不能因此判定实际局部细化配置无效。

### 4.4 MPI / OMP 的边界

本轮报告统一以“单份全域网格数据”和“当前单进程实现的存储布局”为基准，不判断未来多少节点、多少 rank、多少线程的部署是否会 OOM。

集群中每个 rank 拥有多少块、是否各自预分配块池、负载不均衡、复制的 EOS 表、通信缓冲和线程工作区都会影响单节点峰值。节点数不能用来直接平分全域内存，线程数也不能机械乘到全部内存上。未来执行计划明确后再增加分节点估算，不由当前 GUI 猜测。

界面用“资源估算”“全域细化假设”“当前容量”等说明，不给出“这组配置必然 OOM”或“已保证可运行”的结论。资源提示不阻止配置编辑与保存。

### 4.5 预览本身保持有界

资源提示与保护本次预览是两件事。预览采用独立的块数、时间和返回大小上限，不照搬巨大配置的整个内存池。达到上限时报告实际完成状态，保留最后一份完整网格及层级资源表；在没有完成基础初始化时只返回资源信息。

当前 `MemoryPool` 按 `max_blocks` 预分配三份流体状态。以本次编译常量为例，三维、2,000 块仅六个基础数组乘三份状态就约为 **4.94 GiB**，还没计入其他数据。只减少返回的网格线并不能减少分配。Core 需检查分配开销，并提供受预览预算限制的存储方式；如使用更小的工作容量，应明确记录，并在容量不足时返回未完成状态，保持 `.par` 原值。该数字为代码布局推算，未执行大内存配置。

Host 继续使用独立的 CPU worker，并约束其资源和生命周期；执行模型或载入表之前建立限制。预览超限、取消或失败只影响本次任务，不丢失编辑内容，也不据此宣布科学配置会 OOM。无法安全执行初始化时仍可返回无需执行模型的层级规模表。

本轮不通过启动完整 simulation 再外部中断来获取数据，不进入时间推进、CUDA 初始化或正式输出。受限预览仍使用相同的科学初始化与网格操作，不改变细化阈值或用新的采样值替代正式的粗细网格数据转换。


## 5. 参数界面整理

### 5.1 一个含义只显示一个选项

下拉框根据 Core 的规范值和别名合并选项。例如 `rk2`、`RK2`、`ssprk2` 映射到同一个显示项，写回值仍遵守 Core 定义。

载入别名时选择正确的显示项，不另外插入一个“loaded spelling”选项。只打开文件不改写原拼写；用户实际修改时才写入规范值。无法识别的原值保留并提示，不自动选择列表第一项。

界面名称可以展开较难理解的缩写，例如当前 `bd` 对应 **Bader–Deuflhard（BD）**。RK2、RK3、ROS4 等常用名称可以保留，说明放在旁边或提示中。显示名称、提交值和可接受别名分别管理。

### 5.2 友好名称与一句话说明

普通表单使用可读名称，例如 “Maximum steps / 最大步数”，不必显示下划线。原始参数键保留在详情、提示和搜索中，便于对照 `.par`。

**RuntimeParams 管理的全部标准参数都需要描述。** 至少提供名称、简述、类型、有效范围、默认值、关闭语义及适用条件。说明回答“它控制什么、什么时候生效”，不只是重述参数名。Core 维护语义和限制，Studio 负责文字布局、翻译和控件。当前目录有 90 个标准键，别名共用描述，以目录覆盖检查避免遗漏。

覆盖 Grid、AMR、EOS、Network、Gravity、Diffusion 和 Runtime；不是只给当前可见的几项写提示。例如 `ode_rtol` 是相对误差容限；`ode_atol` 当前涉及混合状态，说明其控制对象，即使没有一个统一标量单位，也不能省略功能描述。

### 5.3 按参数性质显示单位

| 参数性质 | 界面表达 |
|---|---|
| 有已确认物理单位的数值 | 单位紧邻输入框或图例，例如 `cm`、`g/cm³` |
| 比例和其他无量纲数 | 必要时说明“无量纲”，不显示缺少单位警告 |
| 步数、块数、层级 | 使用“步”“块”“层级”等含义说明 |
| 布尔值、枚举、路径、名称 | 不显示单位栏 |
| 随坐标或模型变化 | 读取当前 Core 提供的单位，随配置更新 |
| 未取得可靠单位的 custom 数值 | 暂不显示单位标签，不自动标成无量纲，也不堆放未知含义提示 |

标准参数保留功能说明；custom 参数只显示原名、数值和能够确定的单位，不要求生成意义描述。普通表单不显示 `Unit not provided`、`unclear definition par` 一类占位文案。

### 5.3.1 全系统采用 CGS，包括 IdealGas

项目约定统一为 CGS，不随 EOS 切换。坐标长度用 `cm`，时间用 `s`，密度用 `g/cm³`，压力及能量密度用 `erg/cm³`，比内能用 `erg/g`，温度用 `K`，比热用 `erg/(g·K)`；角坐标用 `rad`，比例等仍为无量纲。输入、初始化、计算、输出与 GUI 按同一约定解释。

IdealGas 的数学形式可以在其他一致单位下成立，不代表 ARCH 向用户开放任意单位模式。本轮应由 Core 统一返回 CGS 单位，更新对应文档、示例和测试，前端读取结果；不能只在前端覆盖旧的 `code_*` 标签。

v0.13.0 的以下旧内容已在本轮 Core 修正：

- IdealGas 的单位分类已由 `code` 改为 `cgs`。
- 无组分时的空气模型回退比热由 SI 数值 `718.0` 改为等价 CGS 数值 `7.18e6 erg/(g·K)`；Species 的比热单位同步。依赖回退值的旧模型温度结果会改变，用户显式提供的 Cv 不自动缩放。
- Sod 显式注册了 `Cv = 1.0`，未使用上述回退值。它可以被定义为 CGS 下的模型比热，具体参考温度与测试应据此确认，不能仅因数值小就认定必须转换。

CPU 测试已核对 300 K 与 2.154e9 erg/g 的双向转换，以及 Sod 显式比热下的初始转换。本轮不进行 CUDA 编译或 GPU 验证。

### 5.4 EOS 路径放在一个区域，保留两个用途

当前两个路径不是同一参数：

- `eos_table_path`：当前 EOS 使用的主表。
- `eos_helm_table_path`：部分 Tabular 主表缺少电子 / 正电子部分时，用于补全的 Helmholtz 表；为空时还可能采用 Core 默认路径。

建议统一放在“EOS 数据文件”区域：常规显示主表；补充表放在可展开的高级区域，由 Core 的适用状态说明是否需要、实际使用哪一路径。单独使用 Helmholtz 时不把补充表显示成第二个必填项。

需要读取主表才能确定补充表需求时，显示“读取主表后确认”。隐藏暂不适用的字段不删除原值，也不将两个键互相覆盖。

路径预检要与实际加载器采用相同的引号和相对目录规则，避免“Core 能读但 GUI 报不存在”。输出目录可以尚未创建，不能与必须存在的输入表使用相同检查。

### 5.5 将关闭哨兵值转换为开关

对于 Core 明确定义了关闭含义的字段，使用“开关 + 数值”：

| 操作名称建议 | 参数 | 开启后的数值 |
|---|---|---|
| 限制最大步数 | `max_steps` | 正整数；关闭表示不按步数限制 |
| 按步数定期输出 | `plt_dstep` | 正整数 |
| 按时间定期输出 | `plt_dt` | 正数，单位取当前时间约定 |
| 按步数保存恢复点 | `chk_dstep` | 正整数 |
| 按时间保存恢复点 | `chk_dt` | 正数，单位取当前时间约定 |

这些项在当前执行逻辑中以大于 0 为启用条件，非正值表示不启用该条件。用户明确关闭时可写入约定值 `-1`；载入原有 `0` 等拼写时先正确显示状态，未编辑则保留原文。

开启后恢复此前有效正值；没有可恢复值或 Core 推荐值时，要求填写，不随意生成一个运行间隔。步数拒绝小数，时间间隔允许小数。按步数和按时间的条件可以同时启用，不能擅自改成互斥选项。

上述开关应标明“定期输出”：正式计算的初始输出有独立逻辑，关闭周期条件不等于关闭所有文件输出。

不要对所有负数机械套用关闭开关。例如当前 `max_blocks ≤ 0` 会回退到容量 10,000，`regrid_interval ≤ 0` 则非法。开关转换规则需逐项由 Core 确认。

### 5.6 Diffusion 与 Burn 使用一致的模块开关

Diffusion 区域常驻显示“启用扩散”开关；现有 `.par` 的正式键名是 `use_diffusion`。关闭时收起该模块的数值设置，开启后再展开，不继续铺开全部无效控件。

展开后先区分“指定常量”和“物理模型计算系数”两条路径，再按热扩散、黏性扩散和组分扩散组织相关开关与参数。用户所称的 conductivity 路径，在本次评审版本由 `diffusion_math.hpp` 和 `DiffFlux.h` 实现。这里的“模型计算”指系数来源，与 RKL1 / RKL2 等时间积分方法分别显示。

在 Core 允许指定常量的路径下，勾选某个子项才展开对应数值框：

| 子项开关 | 数值输入 | 显示名称 | CGS 单位 |
|---|---|---|---|
| `use_thermal_diff` | `alpha_therm` | 热扩散率 | `cm²/s` |
| `use_viscous_diff` | `nu_visc` | 运动黏度 | `cm²/s` |
| `use_species_diff` | `D_spec` | 组分扩散系数 | `cm²/s` |

未勾选的子项收起数值框。输入范围和零值含义由 Core 提供，不能把这三个参数都套成正整数输入。

物理模型路径下，上述常量输入框不出现；热扩散率由导热系数及当前状态换算得到。不要把 `alpha_therm` 标成导热系数，两者含义和单位不同。

当前实现尚无独立的“常量 / 模型”参数开关，路径由 EOS 和实际状态决定。Core 应输出当前系数来源、允许的来源及各子项支持情况；GUI 先显示实际模式，只在 Core 确实支持切换时提供可操作的选择。不能做一个只改变表单外观、却不改变 Core 路径的下拉框。

当前模型计算分支只计算热扩散率，`nu_visc` 与 `D_spec` 在该分支保持默认零值，不能把它们显示成已获得物理模型计算结果。对应子项的可用状态需要 Core 明确给出，UI 按支持情况禁用或说明。

关闭只改变启用状态，保留已载入或已编辑的相关参数值；重新开启恢复原值。字段收起不删除 `.par` 内容，不自动插入全部默认项。若 Core 仍会检查某个已保存值，并报告错误，在折叠区域摘要中提供定位和展开入口，避免用户看不到报错字段。

切换到不允许常量键的模型路径与普通的“关闭子项”分开处理。当前 `use_diffusion=true` 且 EOS 为 Helmholtz 时，只要 `.par` 显式含有 `alpha_therm`、`nu_visc` 或 `D_spec` 就会报错，即使值为 0、对应子项未勾选也一样。

载入已有冲突文件时，显示具体冲突键并提供“移除不适用的常量项”操作；不静默修改。用户切换来源后，也要列出必要的工作副本变更，移除冲突的有效赋值并保留撤销及常量草稿值。已保存文件仍由用户保存操作更新。发送 Preview 的文本中不能继续携带这些被禁止的键，也不能用写成 0 的方式代替移除。

Burn 的运行参数沿用相同交互。跨模块仍需要的设置依据实际依赖保留，例如 `network_name` 可能用于准备初值和 EOS 所需的组分，不能单凭 `use_burn=false` 一起隐藏。

### 5.7 Preview 的 Linear / Log 显示与零值

坐标轴比例与场值比例分别提供 Linear / Log 选项，可以组合为全线性、半对数或双对数。二维场的颜色比例单独控制，不与坐标轴混用。上下限、显示截断范围放到各自的高级选项中。

当前反馈：Preview 切换 Log 时，数值为 0 也被报成“负数”。需要分别统计零值、负值和非有限值。普通 Log 只显示严格大于 0 的值；零值与负值在图上留空或使用专用遮罩，曲线在无效位置断开，不能跨越空缺连线。提示例如“Log 隐藏了 12 个零值、3 个负值”，不将它们认定为配置错误。

不对原始数据取绝对值、不悄悄加 epsilon，也不覆盖数据源。Inspector 始终显示原值；切回 Linear 后恢复原始数值。若没有正数，显示“当前范围内没有可用于 Log 的正值”，保留切回 Linear 的入口。Log 的手动范围下限和上限均须大于 0，且上限大于下限；显示截断只能作用于副本，并与无效值遮罩分开。坐标为 0 时同样适用，不应移动真实坐标。

验收覆盖：全零、正数含零、正负混合、全部非正、单一正值、NaN/Inf，以及 Linear → Log → Linear。缩放和平移后图形与坐标同步，二维无效像素有明确表现。此项由 Studio 实现，Core 继续返回未经显示变换的原始场值。

## 6. Custom 参数与现有模型接入

用户继续编写自己的 C++ 和 `.par`，无需另写参数声明。表单保留 custom 参数原名，只显示值和单位；无量纲显示“无量纲”。标准参数继续显示 Core 提供的功能说明。

### 6.1 统一检查入口

Host 调用 `--inspect-case`，读取本次实际用到的参数、类型、默认值、文件值和采用值。修改未保存参数后可以重新检查，保留原有取消和旧结果淘汰流程。此入口已覆盖 Sod、CellularDet、Gaussian、Sedov、RT、SmoothAdvection、ExternalGravity、DiffusionMode、BurnOneZone、BurnGradient、CooperativeHotspots。

模型检查、完整场图和 AMR 网格分别读取能力。新增入口提供少量真实初始化样本，适合检查参数和初始化状态；完整场图及 AMR 网格当前仍支持 Sod 1D / CellularDet 2D。其他模型可以载入、编辑、检查参数，并明确显示场图尚不可用。

检查会执行模型的初始化准备，部分模型需要读取 EOS 文件。Host 显示“正在检查初始化”，提供取消操作；按能力响应中的时间预算执行，不复用较短的 AMR 网格预算。初始化耗时随模型变化；Core 已复用同一检查请求内的 EOS 数据并在结束前核对来源，避免热点模型反复读取整张表。

### 6.2 单位展示

Core 已核对现有模型的数值参数单位。例如：

| 参数 | 单位显示 |
|---|---|
| Sod `x_pos`、CellularDet `radiusPerturb` | cm |
| CellularDet `noiseAmplitude`、组分输入 | 无量纲 |
| RT `amplitude` | cm/s |
| Sedov `explosion_energy` | 随 1D / 2D / 3D 分别显示 erg/cm²、erg/cm、erg |

单位证据与编译模型源码关联。源码或参数变化后重新检查；当模型源码改变而单位记录尚未更新时，旧单位不继续显示。无单位证据的输入留空，字符串和开关不显示单位警告。前端无需自行分析 C++、解释参数含义或维护模型单位表。

这轮单位来自 Core 核对的源码用法和已知组分读取规则。初始化探针同时记录真实读取和写入结果，但尚不执行任意 C++ 表达式的自动单位反推。前端使用响应中的证据状态区分即可；详细说明放在检查详情中。

### 6.3 编辑和图形绑定

整数参数拒绝小数及越界值；默认值和文件值分开显示。初始化失败时保留输入，定位接口给出的错误，并保留已获取的参数记录。

未观察到的参数可继续编辑；“本次未观察到”不等于错误或无用参数，不自动删除。无法匹配模型与参数文件时，仍按前面的常驻名称、警告和明确保存流程处理。

图形绑定独立于单位。继续使用已提供的 Sod 位置绑定；只有单位为 cm，不能决定该参数应画成位置、半径还是厚度。未来模型的显式图形关系由 Core 提供。

| 交付内容 | Core | Host | Studio |
|---|---|---|---|
| 本地一条命令启动 | 提供能力查询 | 启动服务、项目发现、WSL 路径关联、退出清理 | 桌面窗口封装、安装包、项目选择及缺项提示 |
| 已编译模型与源码状态 | 查询实际注册项和各项能力 | 构建输入跟踪、二进制身份、编译与刷新 | 模型列表、常驻名称、旧构建提示 |
| AMR 参数区域 | 提供有效范围、指标支持和说明 | 调用检查接口 | 分组、控件、错误定位 |
| AMR 资源提示 | 各 Level 全域规模、局部估计、块池开销及假设 | 提供本次预览自身的资源限制 | 层级资源表，不推断集群 OOM |
| 实际 AMR 网格 | 复用初始细化、2:1 平衡与数据转换，返回完整快照 | 独立进程、限制、超时、取消、响应上限 | 块 / 单元线、缩放查看、层级选择和完成状态 |
| 参数表达整理 | 为全部 RuntimeParams 标准项提供描述，确认别名、开关和依赖关系 | 路径解析与预检一致性 | 标签、选项去重、EOS 区域、Burn / Diffusion 启用与展开 |
| 全系统 CGS | 核对 IdealGas 比热、模型输入、metadata 与参考结果 | 关联新接口和实际构建版本 | 根据新契约统一显示 CGS 单位 |
| Custom 单位 | 统一模型检查、真实读取记录及与源码关联的单位证据 | 保持构建与结果身份关联 | 仅展示单位；不生成含义说明 |

建议先交付独立窗口启动、全部标准参数描述和 CGS 对齐；随后交付 AMR 参数区与层级资源表，再接入可缩放的实际网格。现有模型统一检查可同时接入；每项可以独立验收。

本轮接口只补充实际需要的信息：注册模型与能力、标准参数描述与单位、custom 单位及其证据范围、带假设的层级资源表，以及有数量和字节上限的叶块几何、单元布局和完成状态。可选近似模式另带标记。本轮字段、版本及实际响应见 API README 和 examples；旧场采样入口保持兼容。

Core 继续从冻结的 `main` 基线组织独立改动，复用已完成接口需要的明确提交。交接提供准确 commit/ref、README、成功和失败响应，以及相关测试结果；Studio 按需接入，避免为了同步接口引入整条前端分支历史。

## 8. 验收场景

### 本地启动与源码关联

- 一条命令打开独立 Studio 窗口，不依赖 Chrome / Edge 或默认浏览器；含空格路径、内部端口占用和依赖缺失都有清楚结果。
- 桌面安装包能加载打包资源，无需运行 Vite 开发服务；Windows 窗口能正确关联本机 WSL 项目、构建和路径。
- 新 `.cpp`、已修改 `.cpp`、已注册但不支持预览的 case 显示不同状态。
- 编译失败保留参数副本；成功后刷新注册列表和能力，不继续使用旧结果。
- 外部 `.par` 可正常载入，完整文件名常驻；配对提醒不自动改写文件。

### 参数表达

- `RK2`、`rk2`、`ssprk2` 只对应一个 UI 选项；打开再保存且未修改时保留原拼写。
- 关闭值正确显示为开关，重新开启需要有效数值；整数输入拒绝小数。
- `use_diffusion=false` 时收起扩散参数，启用后展开；关闭再开启保留原值，折叠内的真实错误可以定位，跨模块仍需的设置不被误藏。
- 常量路径中，三个扩散子项各自控制对应输入框，单位均为 `cm²/s`；模型路径隐藏常量输入，不把未实现的系数计算标为可用。
- 切换或载入 Helmholtz 扩散配置时，显式的常量键即使为 0 也能被定位和移除；未保存变更可撤销，发送 Core 的文本不遗留冲突键。
- 路径、枚举和布尔项不显示缺少单位；custom 参数只显示原名和值，可靠单位正常显示、无量纲明确显示，没有单位证据时留空。
- RuntimeParams 标准目录的全部参数都有简述，别名共用语义；Gravity、Diffusion、Network 高级项等也纳入覆盖。
- IdealGas、Helmholtz、Tabular 的字段标签遵守统一 CGS；比热、温度关系和参考初值完成独立核对，不能只验证标签字符串。
- 11 个已注册模型共用检查流程；参数采用值、默认值、来源和单位显示正确。更改已编译模型源码后，旧单位证据失效。
- 单位详情可查阅 Core 依据；常规网格初始化及时间推进不安装检查观察器，不增加逐单元追踪。
- 主 EOS 表与补充表分别保存；含引号路径的预检与实际加载一致。
- 界面标签改变不影响 `.par` 原始键，未编辑项和未知自定义键保留。

### 初始 AMR

- 对小规模 Sod / CellularDet 参考配置，比较预览与正式初始细化对应阶段的叶块边界、层级和数量；完成状态相同时应一致。
- 构造含粗细交界的参考配置，检查共面相邻块层级差不超过 1，二维单次细化的四子块完整，块轮廓与单元线显示正确。
- 放大后可查看块内单元，平移 / 缩放时网格、场图、标记和坐标轴一致移动；缩放不重新执行初始化，不更改网格统计。
- AMR 关闭时只显示基础网格；改变有效指标或阈值可更新实际网格，改变最高 Level 会更新全域规模表。
- 每升一级，全域块数按当前活动维数乘 2、4、8；表中明确全域假设、局部估计和当前池容量的区别。
- 很高的正式层级或很大的 `max_blocks` 不会直接触发等规模预分配；预览有独立上限，参数文件保持原值。
- 达到预览限制时返回最后一份完整、平衡的快照及未完成状态；不显示半次细化的残缺子块，不以此判定未来集群会 OOM。
- 用小预算验证超限、超时、取消及恢复；不通过耗尽整机内存验收，不进入时间推进、CUDA 初始化或正式输出。
- 返回数据与绘制数量有上限；旧响应不能覆盖新参数或新构建的结果。

## 9. Core API 实施与交接清单

继续使用现有 CLI + stdin 参数文本 + JSON 响应，不要求前端接入 C++ 头文件，也不建立一个包办全部功能的 `DriverGUI.h`。`src/api/` 管理应用入口、数据整理和协议；初始化、AMR、EOS 的科学实现保留在原所属模块。

### 9.1 本轮接口与调用

- `--config-schema` / `--inspect-config`：配置扩展版本 2；presentation、Diffusion 与 AMR 适用状态，CGS 单位。
- `--list-cases`：注册模型发现；不执行 Setup。
- `--amr-resources CASE --config-stdin`：单份全域网格按 Level 的资源规模，无 EOS/网格分配。
- `--inspect-case CASE --config-stdin`：11 个现有模型的统一参数与初始化检查；读取类型、默认值、来源、单位证据及少量真实 Init 样本。
- `--preview-amr CASE --config-stdin`：真实初始网格；只支持当前已验证的 Cartesian Sod 1D / CellularDet 2D。与旧场采样分开调用，并按相同参数和构建身份叠加。

网格默认块预算 512、工作存储预算 128 MiB；返回实际采用的 workingCapacity，不改 `.par` 中 max_blocks。根网格超限时返回空快照及 limited；细化中超限时返回最后完整平衡快照及 limited。AMR 的 Linux/WSL 子进程有 1 GiB 地址空间和 30 秒 CPU 限制，Host 仍负责墙钟超时、取消、回收与失败展示；这些限制不是整机内存预测。模型检查使用单独的 300 秒 CPU / 360 秒墙钟预算，由能力查询返回。

### 9.2 本轮没有交付的内容

桌面安装包、启动命令、源码和二进制关系追踪、具体网格绘制、Preview 比例与零值处理由 Studio/Host 接续实现。Core 此次没有增加 SSH、集群计划或运行时 plotfile 渲染。

现有模型可直接接入统一检查和单位结果。修改或新增模型仍使用同一入口；未覆盖单位显示为空并返回状态。任意表达式自动反推尚未发布。

### 9.3 接入和验收资料

代码、最新响应示例与 scoped test 位于本轮交付的 ui-contract 分支。2026-09-21 CPU 构建通过，15 组相关测试最终通过；包括两种模型的预览与正式初始化 t=0 网格逐块对照。未运行 CUDA 编译或 GPU 测试。现有 v0.13.0 接入方只摘取 `5e96d4f0` 之后的本轮增量即可，重建 CPU binary 后开始 Host/Studio 接入。完整字段、限制、兼容性和测试说明见 `src/api/LOCAL_WORKFLOW_HANDOFF.md`，具体 commit 在交接消息中提供。
