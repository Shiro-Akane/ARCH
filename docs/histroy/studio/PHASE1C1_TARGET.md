# ARCH Studio — Phase 1C.1 Control Semantics & Config UX Polish Target

> 目标：在已经完成并冻结的 Phase 1C 参数面板信息架构基础上，做一轮 **控件语义、文件选择、状态反馈和表单产品化** 整理。  
> 本阶段不增加新的科学功能，不进入 `Setup()+Init()`、真实 IC Preview、Build/Run、AMR、SSH、Tauri 或远程执行。  
> 核心目标是把目前仍带有“浏览器默认控件 / 开发原型痕迹”的左侧配置面板，整理成更接近正式科研工具 / DCC Editor 的参数编辑体验。

---

# 0. 冻结基线

Phase 1C 已完成并封箱，基线 tag：

```text
studio-phase1c-v0.4.0
```

```bash
git switch -c studio/phase1c1-control-polish studio-phase1c-v0.4.0
```

5. 不在已封箱分支继续开发。

# 1. 一句话目标

把当前参数栏从：

> **“正确但仍有浏览器默认控件和工程调试信息痕迹的原型”**

整理为：

> **“控件类型明确、文件操作统一、状态反馈克制、科研用户一眼能理解的正式工具 UI”**

本阶段主要解决四类问题：

```text
1. Open Config 原生文件选择器样式混乱 / 本地化文字混入
2. number input 原生 +/- spinner 不符合参数语义与整体视觉
3. 底部大量开发/实现说明长期占据界面
4. 已知 enum / bool / numeric 参数仍大量以自由文本框呈现
```

# 2. Open Config 文件选择 UI

当前浏览器原生：

```text
选择文件    未选择任何文件
```

会受系统语言影响，并且视觉样式与 ARCH Studio 不一致。

## 要求

隐藏原生 `<input type="file">` 的默认可见 UI，只保留它作为底层系统文件选择入口。

界面改成 ARCH Studio 自有控件：

### 未加载配置时

```text
CONFIG FILE

No configuration loaded

[ Open Config... ]
```

### 已加载配置时

```text
CONFIG FILE

sod.par

[ Open Config... ]
```

点击：

```text
Open Config...
```

仍然调用浏览器 / 系统原生 file picker。

## 限制

- 不绕过浏览器安全机制；
- 不自动扫描磁盘；
- 不自动记录任意本地路径；
- 不伪造“已打开可写文件句柄”；
- 不增加拖放文件功能，除非实现成本极低且不扩大依赖；
- 所有 ARCH Studio 自己绘制的 UI 文案保持英文，不受操作系统中文文件控件文案影响。

# 3. Config 状态不要堆成长文本

当前类似：

```text
Download requested: sod-phase1c_modified.par.
Original unchanged; working copy retained.
sod-phase1c.par
Config: dirty
```

这类信息不应长期作为左栏主体内容。

## 主界面只保留高价值状态

建议：

```text
sod.par
● Dirty
```

或：

```text
Config
sod.par                Dirty
```

状态至少：

```text
Saved
Dirty
Invalid
```

## 短期操作结果

例如：

```text
Save As requested
Export prepared
Config reverted
Open failed
```

优先使用：

- toast / temporary notification；
- Status Bar；
- 非阻塞提示；
- tooltip / info popover。

不要把操作历史永久堆在 Parameters Panel 顶部。

## 科学边界提示

当前：

```text
Mock preview is not connected to ARCH initializer.
```

这类信息重要，但不需要长期占整行。

改成：

```text
MOCK PREVIEW
```

Badge + tooltip：

```text
Not generated by ARCH Setup()/Init().
```

真实 Config 模式同理：

```text
REAL CONFIG
```

保持来源清楚。

# 4. 删除 / 降级开发者实现信息

以下信息对普通科研用户不需要长期显示：

```text
0 raw lines preserved unchanged.
Original unchanged; working copy retained.
Save in place unavailable.
```

## 处理原则

### `0 raw lines preserved unchanged`

移入：

```text
Raw .par
```

详情中，或 Parameter Info / Debug info。

默认主界面不显示。

### `Original unchanged`

可以只在：

-首次打开真实 `.par` 时短暂 toast；
- Save As tooltip；
- help/info；

中解释。

不要重复常驻。

### `Save in place unavailable`

不要作为一整条 disabled button 永久占空间。

主操作区只保留：

```text
[ Revert ] [ Save As... ]
```

若需要解释：

```text
ⓘ Browser mode exports a new file; original is not overwritten.
```

放 tooltip / info popover。

# 5. Number Input 原生 Spinner

浏览器原生 number input 右侧的上下白色箭头：

```text
▲
▼
```

在 ARCH Studio 当前视觉语言中不一致，而且默认 `step=1` 对很多科学参数并没有明确语义。

## 默认策略

> **隐藏浏览器原生 number spinner。**

Numeric Input 保持：

- 键盘直接输入；
- Tab / focus；
- ArrowUp / ArrowDown 行为只有在明确 step contract 时保留；
- scientific notation 支持；
- 高精度输入不被 UI 强制四舍五入。

## 不允许

不要因为：

```text
value = 0.4
```

就默认：

```text
+/- 1
```

也不要默认：

```text
step = 1
```

除非参数 contract 明确要求整数步进。

---

# 6. Slider 使用规则

Slider 继续严格遵守 Phase 1B 的规则。

只有当真实 ARCH contract / schema 明确给出：

```text
min
max
```

并且范围适合 Slider 时，才允许显示：

```text
[────────●────────] [0.400]
```

即：

> **Slider + Numeric Input**

而不是 Slider-only。

## `[0,1]` 参数

明确 `[0,1]`：

```text
min = 0
max = 1
```

优先：

```text
Slider + exact numeric input
```

## 已知其他有限范围

例如：

```text
min = 0
max = 100
```

是否启用 Slider，应结合：

- 参数语义；
- 调整频率；
- 范围跨度；
- step / precision；

决定。

Phase 1C.1 不要自动把所有 finite range 都改 Slider。

## 无明确 Range

继续 Numeric Input：

```text
[ 0.4 ]
```

不显示 Slider。

---

# 7. Integer 参数控件

对于明确整数参数，例如：

```text
max_steps
nblocks
level
```

使用：

```text
Integer Numeric Input
```

如果真实 contract 明确：

```text
step = 1
```

允许：

- ArrowUp / ArrowDown；
- 自定义轻量 +/- stepper（可选）。

但不要使用浏览器默认白色 spinner 破坏视觉一致性。

若该参数存在特殊 sentinel，例如：

```text
-1 = unlimited
```

需要：

- 保留精确值；
- 在 tooltip / help 中说明（仅在源码 contract 已确认时）；
- 不因为 UI 限制误禁止合法 sentinel。

---

# 8. Known Enum → Dropdown

目前大量类似：

```text
geometry       [cartesian]
solver         [HLLC]
reconstruct    [muscl]
time_integrator[RK2]
boundary       [outflow]
```

如果 ARCH 源码 / schema 已明确给出有限合法选项：

> **必须优先改为 Dropdown / Select。**

例如：

```text
Geometry
[ Cartesian ▼ ]

Solver
[ HLLC ▼ ]

Reconstruction
[ MUSCL ▼ ]

Time integrator
[ RK2 ▼ ]

Boundary
[ Outflow ▼ ]
```

## 重要约束

- Enum options 必须来自真实 ARCH contract；
- 不凭经验补选项；
- 不根据 README 示例推断全部合法值；
- 不删除当前文件中的合法但 UI schema 未知值；
- 如果当前值不在 Studio 已知 schema：
  - 保留 raw value；
  - 显示 `Unknown / raw value`；
  - 不擅自替换。

---

# 9. Known Bool → Checkbox / Switch

像：

```text
use_burn
```

如果 `ConfigParser` / RuntimeParams 已确认是 bool：

使用：

```text
[ ] Enable burning
```

或：

```text
Use burn    [ OFF | ON ]
```

要求：

- true / false round-trip 正确；
- 不改变原始参数键；
- 若 ARCH 还支持第三状态，例如 `auto`，则不能使用纯 boolean switch，应改为 enum select。

---

# 10. Numeric vs Free Text

参数控件映射优先级：

```text
明确 bool
→ checkbox / switch

明确 enum
→ dropdown

明确 integer
→ integer numeric input

明确 float + known suitable range
→ slider + numeric input

明确 float，无 range
→ numeric input

string / path
→ text input

unknown / custom without metadata
→ conservative text/numeric fallback
```

## 最终目标

减少：

> “所有东西都是用户自由输入字符串”

但绝不能以牺牲真实兼容性为代价。

---

# 11. Custom Params 仍保持保守

Custom Parameters 如果没有 metadata：

- 不自动变 dropdown；
- 不自动变 slider；
- 不猜 unit；
- 不猜 range；
- 不猜 role；
- 不猜科学含义。

如果 Parser 可以可靠判断：

```text
numeric literal
```

可以使用 Numeric Input。

否则保留 Text Input。

Raw key 必须可查看。

# 12. Help / Parameter Info


Parameter Info / Tooltip。

可包含：

```text

Source line
Allowed values
Range
```

主界面不需要把这些全部常驻。

# 13. Raw `.par`

Phase 1C 已有只读 Raw Source，继续保留。

它应该承担：

- source line；
- unknown lines；
- raw key；
- comments；
- preserved text；

这些高级 / 调试信息。

不要再把这些信息搬回普通 GUI 表单。

# 14. Action Area

Parameters Panel 底部操作区精简为：

```text
[ Revert ] [ Save As... ]

Raw .par >
```

可根据 ConfigState：

```text
Saved
Dirty
Invalid
```

调整按钮 enabled state。

不显示：

```text
Save in place unavailable
```

大面积 disabled action。

如果 Config Invalid：

```text
Save As...
```

按 Phase 1B 现有安全规则禁用，并通过 tooltip / error summary 解释。

---

# 15. Error / Validation 显示

Parameter invalid 应：

- 对具体控件做红色/警告边框；
- 附一条简短原因；
- 顶部可以显示：

```text
Config invalid · 2 issues
```

不要把完整 validation log 全部常驻在左栏。

如需要详细错误列表：

```text
View issues
```

按需展开。

---

# 16. UI 文案语言

ARCH Studio 自身 UI 统一使用英文。

避免出现：

```text
选择文件
未选择任何文件
```

这类由浏览器原生输入控件暴露出来的系统语言文字。

系统 File Picker 本身使用操作系统语言是允许的。

也就是说：

```text
Studio UI → English
OS dialog → system locale
```

是正常行为。
