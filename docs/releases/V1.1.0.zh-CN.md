# ARCH v1.1.0

英文原文：[V1.1.0.md](V1.1.0.md)。

本次更新重点提升动态自适应网格细化（AMR）下的 CUDA 执行效率，同时继续让
CPU 和 GPU 共用一套数学与物理实现。源码目录、文档和验证入口也完成了整理，
方便用户查找配置方法、理解结果并自行复现。此版本以源码形式提供：需要在本地
构建 ARCH，并通过 `git lfs pull` 获取所需的运行时表数据。

## 主要更新

- **CUDA 批量执行。** 在存储布局允许时，流体、扩散和小网络燃烧的一次计算核
  启动可以处理多个网格块；设备工作区和主机交换缓冲区在时间步之间复用已有容量。
- **AMR 场数据保留在设备侧处理。** CUDA 计算细化指标并执行守恒迁移；CPU 继续
  管理共用的网格树、Morton 排序及细化／粗化决策，不另建 GPU 专用的细化算法。
- **一致的多物理耦合。** 燃烧、扩散与流体沿用共用的推进顺序和物理策略。
  燃烧能量、组分闭合及稀疏求解残差验收使用统一的数学实现；执行完成状态与
  场版本检查保证数据交换、状态读取和重启之间的一致性。
- **更清晰的验证和文档入口。** 用户指南介绍如何配置程序和理解实测性能；
  各模块的验证摘要先解释方法与误差，再提供详细证据。源码仍包含可复用的
  测试和工具，方便用户检查自己的构建。

## 实测性能

验收所用平台为 **H100-20C 20 GiB vGPU**，以及提供 32 个 vCPU 的 Xeon Gold 6338
虚拟机。微物理耗时取一次预热后五次正式运行的中位数；CPU 对照从 1、8、16 线程
中选择实测最快的配置。耗时包含初始化与输出，不是单独的 GPU 计算核耗时。

| 工作负载 | 实测 CPU/CUDA 加速比 |
| --- | ---: |
| 流体、aprox13 燃烧、完整输运和动态 AMR；128 个初始网格块 | 六种 ODE／输运组合为 2.88–5.08 倍 |
| aprox13 燃烧；128 个初始网格块 | 三种 ODE 方法为 1.98–2.61 倍 |
| 扩散；128 个初始网格块 | RKL1 基本持平；RKL2 为 1.35 倍 |
| 二维 Sedov 与动态 AMR；两档网格规模 | 1.59–1.67 倍 |

最高结果来自 BD 燃烧、RKL2 输运与 Helmholtz 状态方程的耦合配置：
**CPU16 耗时 423.55 秒，CUDA 耗时 83.35 秒，加速比为 5.08 倍**。
这里的加速比是同一算例的 CPU 耗时除以 CUDA 耗时。小规模问题仍可能更适合 CPU。
算例定义、规模变化和测速方法见
[性能报告](../../validation/backend/results/hpc-cuda-optimization/README.md)。

**大反应网络需要单独判断性能。** 已测生产路线的 150／200 核素配置通过了数值
对照，但其小规模完整程序算例在 CUDA 上的耗时约为 CPU8 的 5.0–10.3 倍。
相近工作负载建议优先使用 CPU，除非代表性测速已经显示 GPU 收益。稀疏求解的
进一步加速属于后续优化；aprox13 的约五倍结果不适用于这些大网络。

## 验证情况

保留明确源码身份的优化验收包含 **1,188 次微物理运行和 1,155 次通过的对照**，
流体／AMR 与大网络另有独立记录。集成检查覆盖共用 AMR 契约、实际触发的燃烧
能量限步、耦合输运、检查点续算，以及 CUDA 的定向内存／竞争检查。
[Validation 索引](../../validation/README.zh-CN.md)区分数值精度、后端一致性与
性能证据，并注明每项检查实际使用的源码和可执行文件。本次发布整理不重新
运行整套性能实验，也不把先前的结果改写成新测量。

本轮定向检查确认，CPU 和 CUDA 在一维、二维及三维下的 AMR 结果保持不变，
整理前生成的检查点可以继续计算。本轮选定的 AMR 测试也通过了内存与竞争检查。

## 构建与使用

可以从[构建指南](../guides/Build.zh-CN.md)和
[算例指南](../guides/SimulationCase.zh-CN.md)开始。纯 CPU 构建不需要 CUDA 工具链；
启用 CUDA 的构建同时支持 CPU 和 GPU 执行。启用 CUDA 或测试套件都会增加编译
时间和主机内存需求，应根据可用内存选择并行数，不为某一台开发机降低运行时
的数值设置。

小型燃烧系统使用共用的 DenseLU。自动选择时，稀疏系统在 CPU 上使用 KLU，
在 CUDA 上使用 cuDSS；显式指定不支持的后端／求解器组合会报错。
pynucastro 生成网络继续通过文档所述流程接入，其可用规模和计算成本取决于
网络本身及可用资源。

此版本不包含预测式 AMR／GNN 的数据采集或推断，常规动态 AMR 不受影响。
参数文件只需保留[参考手册](../Reference.zh-CN.md)中列出的 AMR 配置；实验性的
`predictive_amr_*` 设置应移除。内部配置和网格块的数据布局有所调整，因此应从
发布源码重新构建，不要混用先前的目标文件、库与当前头文件。本次清理不改变
检查点格式。

ARCH 代码以及科学代码／数据各自适用的条款见
[第三方说明](../../THIRD_PARTY_NOTICES.md)。发布附件不包含预编译 CUDA 库、
模拟产生的 HDF5 输出或内部实验归档；必要的科学表数据继续按照文档中的
Git LFS 分发方式和来源说明提供。
