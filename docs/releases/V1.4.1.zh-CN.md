## 构建与安装

Linux 和原生 Windows 均提供 Core、带 CUDA 的 Core，以及对应的 Studio 构建预设。准备依赖、CMake 配置和编译各使用一条命令。启用 CUDA 的构建仍保留 CPU 执行能力，运行时通过 `compute_backend` 选择计算后端。

- 依赖准备步骤为所选编译器 ABI 选择或构建 HDF5，并复用 HighFive 与 KLU 的共用配置入口。显式指定的依赖路径会与实际选中的安装核对。
- Windows CLI 与 Studio 共用配置时选定的编译器和运行库环境，生成的启动器提供所需本机工具与运行库。
- 普通源码修改后，Studio 复用锁定的 npm 依赖；删除 `node_modules` 后，构建入口会恢复依赖。

[构建指南](../guides/Build.zh-CN.md)集中说明前置环境、预设、工具路径、离线准备和高级选项。已有的直接 CMake 配置方式继续可用。

## Studio 与文档

不带参数运行 `arch-studio` 会打开项目选择页；也可用 CLI 选项直接指定已有构建、模型和参数文件。旧的机器专属构建 profile 已由明确选择项目构建目录的方式取代。

README 分开介绍 Core 的依赖准备、配置、编译和运行；其中的 Studio 部分说明如何为已有 Core 构建添加桌面组件。Linux 和 Windows 的完整编译细节统一放在 Build 指南。图解 Studio 指南依次介绍项目选择、Config、参数调整、Preview、Run 和 Plotfile 查看，并说明 `.par` 内路径与工作目录的关系。

文档导航集中指向持续维护的使用说明、实现说明和科学验证材料。失效计划、进度报告及中间调试记录已从分发文档中移除。

## cuDSS 与运行检查

普通 CUDA 构建继续将 cuDSS 作为可选依赖。CUDA 流体计算和使用 DenseLU 的小型燃烧系统无需 cuDSS；CMake 能力摘要会明确显示 GPU 稀疏求解是否可用。

Core 的 `--check-run` 查询与 Studio 的 Run 准备共用后端选择逻辑，在构造网格前显示请求后端、实际后端、线性求解器及回退原因。显式选择 CUDA 且需要不可用的 cuDSS，或显式指定不可用的 cuDSS 求解器时，会拒绝启动。后端和求解器均为 Auto 时，若 CPU KLU 路线支持当前配置，则允许选择该路线。

Windows 已链接 cuDSS 的构建会在准备好的启动环境中检查所需 DLL。Linux 仅在所选计算路线需要时加载供应商库。`ARCH_REQUIRE_CUDSS=ON` 与 `arch-check-cudss` 目标用于严格 GPU 稀疏验收；GPU 不可用会使检查失败，不会以跳过代替通过。

## 兼容性与验证

数学实现、内存池以及科学文件读写实现保持不变。继续推荐 Linux；原生 Windows 提供对应的 CPU／CUDA 与 Studio 工作流，已测试配置和限制见[平台支持](PlatformSupport.zh-CN.md)。

针对性验证包括 Run API 契约（Linux 9 项、Windows 8 项）、各平台适用的 Studio 测试（Linux 464 项、Windows 29 项），以及两平台各 4 项严格 cuDSS GPU 测试。实际 CUDA Sod 和 DenseLU 运行通过；Linux 还通过移走测试专用 cuDSS 库副本，验证普通 CUDA 计算仍可运行、需要 cuDSS 的请求会被拒绝。

构建检查覆盖 Linux Core／Studio 预设及完整链接的 CUDA 程序，以及 Windows 依赖准备、项目配置、本机辅助程序和 MSVC／CUDA 程序增量构建。大网络 Auto 转向 KLU 的选择由能力用例结合本机运行时探测验证，本次验证范围不包含新的完整大网络演化。科学验收标准与可复现算例继续由[验证索引](../../validation/README.zh-CN.md)维护。
