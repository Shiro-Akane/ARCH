# ARCH v1.2.0

英文原文：[V1.2.0.md](V1.2.0.md)。

本次更新正式引入以整个计算域为对象的自引力，并整理 CPU/CUDA 共用的执行路径。
Driver 按运行时、计算阶段与输入输出职责拆分；旧配置和旧 EOS 路线退役，
低密度状态的处理规则也变得明确。发布标签才标识正式发布的源码快照，
本文本身不代表已生成发布包。

## 物理与数值方法

- **复合 AMR 自引力。** 无全域稀疏矩阵的泊松算子和多重网格求解器作用于
  当前 AMR 层级。每个需要引力的流体阶段从对应密度状态求解、发布势与面力，
  动量和能量源项共用同一套数学实现。引力不借用燃烧 ODE 的 KLU/cuDSS 求解器。
- **CPU/CUDA 原生坐标。** 已验收笛卡尔一至三维周期域、三维孤立域，
  一维柱／球对称孤立域，以及受测的二维、三维完整方位角柱／球坐标域，
  包括原点、轴线和极点接合。动态 AMR、重启与代表性的流体、燃烧、
  热扩散耦合已有相应验证；[GravityBox](../../simulation/GravityBox/README.md)
  和 [SNIaCoupled](../../simulation/SNIaCoupled/README.md) 提供可复用输入。
  后者是碳氧热点示例，不是完整白矮星爆炸模型。
- **低密度可靠性。** 密度与比内能界限复用现有 `sml_rho`、
  `min_eint/max_eint`。被接受的兜底修复记录状态改变量；无效 EOS 状态和
  无法解析的热能明确失败。面通量限制和 CFL 边界也已收紧，旧版本的步数
  与耗时不能直接用作本版的数值基线。

## 源码与接口整理

- Driver 的运行时、计算阶段、调度、分发和输入输出代码按职责归类；
  AMR、CUDA、引力和数值模块也明确二级目录归属。CPU/CUDA 继续共用物理
  公式与求解控制，后端分别负责存储、kernel 和完成状态。
- 用户算例通过 ARCH 构建契约包含 `<UserInterface.h>` 和
  `<GlobalDefs.h>`。Core 提供配置 schema、检查和有界 CPU 初值预览接口，
  供 GUI 使用；配置检查不等于算例已能运行。Studio 前端单独维护。
- 保留严格自由能 3D/4D 表格 EOS；旧规范化 direct 表示、宽松 EOS 回退
  和无消费者的引力接口已退役。共用 EOS 与反应网络减少重复工作，
  不改变已记录的物理状态接受标准。

## 从 v1.1.0 迁移

- 移除 `enforce_mass_conservation`、`burn_verbose_level`、
  `ode_use_numerical_jac`、`ode_freeze_jacobian`、`timeintegrator`。
  这些旧键现在报告 `RETIRED_PARAMETER`；已登记的 `dt_init`、
  `dt_min`、`tstep_change_factor` 保留原有实际用途。旧算例应复查低密度
  下限和 EOS 表来源，详见 [P1.5 迁移记录](../development/P1_5ImplementationReport.zh-CN.md)。
- **检查点格式 6 不读取 v5。** 新格式记录状态控制、修复账本、引力策略及
  控制量。重启时从已保存的密度重建势和力；CPU/CUDA 使用同一格式。旧运行
  需用原版本执行文件完成，或从合适的初始数据启动新运行。内部头文件和
  构建目标归属已调整，更新源码后应重新配置并编译。
- ARCH 输入输出仍统一使用 CGS，包括 IdealGas 和 Core/GUI 配置契约。
  单位与算例编写方式见[算例指南](../guides/SimulationCase.zh-CN.md)。

## 验证范围与已知限制

[引力验证索引](../../validation/gravity/README.md)链接独立泊松／面力检查、
复合 AMR 收敛、源项与能量预算、重启、曲线坐标接合和 CPU/CUDA 对照。
[低密度记录](../../validation/low_density/results/p1_5-20260922/README.md)
覆盖下限与失败语义。代表性的四模块运行和本机 GPU 加速有明确的源码、
输入与硬件记录；它们不等于所有策略组合都已验收，也不保证任意规模都加速。

自引力尚不支持曲线域的部分方位角、域外质量源或 Jeans AMR 指标。
Helmholtz 恒星输运目前只有热传导，没有黏性与组分扩散。
表格 EOS 燃烧／NSE 的可恢复试探失败契约仍待验证。切换已验收配置前，
请查看[方法组合规则](../Reference.zh-CN.md#方法与物理模块的组合)
与[已知限制](../Reference.zh-CN.md#已知限制)。
