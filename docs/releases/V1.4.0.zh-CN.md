# ARCH v1.4.0：Windows 原生支持

[English](V1.4.0.md) · [发布索引](README.md) · [构建](../guides/Build.zh-CN.md) · [Studio](../guides/Studio.zh-CN.md)

软件发布日期：**2026-10-27** · [GitHub release](https://github.com/Shiro-Akane/ARCH/releases/tag/v1.4.0)。Windows 原生支持通过 [PR #21](https://github.com/Shiro-Akane/ARCH/pull/21) 合并；Zenodo 继续暂缓，不声称已有 v1.4.0 Zenodo DOI。

## 主要更新

ARCH 在既有科学范围内提供与 Linux／WSL2 对应的**原生 Windows11 x64 CPU／CUDA CLI 与 Studio 完整功能**。推荐 Linux；Windows 适配较新，仍可能存在不稳定性与 bug。

- CPU／OpenMP 使用 GCC/UCRT64 与同 ABI HDF5／KLU；原生 NVIDIA CUDA 使用独立 MSVC／NVCC 和 Windows SDK。两条路线构建同一 ARCH 目标，CUDA 程序可在启动时选择 `cpu`、`cuda` 或 `auto`。
- 共用 Host 提供配置、Build、真实初始场／AMR Preview、独立终端 Run／Restart，以及只读 Plotfile metadata、原始样本、native point 与显示 LOD。两侧窗口、便携包共用生产源码及许可复制流程。
- 路径、进程监督、输出锁／发布及有界 worker 已有原生平台支持；求解器、数学 owner 和科学格式继续共用。
- 使用说明整理了注册模型与 C++ 源码的区别、参数 Help／Inspector、工作副本保存、Plotfile 导航和跨系统 `.par` 路径。相对路径从计算工作目录解析，不是从 `.par` 所在目录解析。

## 依赖维护

本版包含此前审核的 Vite8.3.4 与 Electron44.9.1 更新。打包核对依赖声明、锁文件及已安装 Electron，消除旧二进制版本单独写死的问题。两侧真实44.9.1包已受测；CI 跳过 Electron 下载，不能代替原生打包／窗口验收。

最后审计发现 ESLint React Hooks 工具链中的开发用传递依赖 Zod4.6.2。锁文件仅将该包更新为既有范围内的 **4.6.7**，同步 MIT 许可清单，对应修复起点为4.6.6的 [GHSA-mrhx-c7xc-m3w5](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5)。这不等于发生安全事故，也不证明桌面存在对外输入路径。当前审计／回归另见[发布准备记录](../histroy/release/V1.4.0ReleasePreparation-20261027.zh-CN.md)。

## 验证与保留范围

[26类最终对照](../histroy/build/WindowsNativeCudaQualification-20261027.zh-CN.md)记录142项原生 Core 契约、37个规范后端算例／9个分辨率组、8条 CPU／CUDA AMR restart 路由／9项比较、真实 Host GPU Run／Restart／Plotfile 与原生 h5py 对照，以及原完整几何目标的0错误／0泄漏 memcheck。代表性同后端续算按0／0阈值通过；Linux 记录72项 CPU CTest、12项受影响 CUDA／真实 fixture 测试、453项 Studio 测试，Windows 记录95项 Studio 与7项链接证据测试。W3 人工对话框／显示／正常关闭与新 GPU 程序化证据分开保留。

实现提交 `dd42d4fa479a262920c7c772794a898c42665e70` 已通过 [ARCH CI #88](https://github.com/Shiro-Akane/ARCH/actions/runs/40430379002)，CodeQL 比较门成功且无 annotation。后续发布／依赖提交必须取得自身准确 head 的结果，不将旧结果改签给新提交。

此前批准的 A12–A18 只解决分类入口、声明标签、Host／Device 布局注解、与冻结 Linux 逐位相同的742个 Helm 节点及失败数组赋值。公式、误差预算、拒绝检查、池分配／容量／所有权保持；本发布准备阶段不再改数学、池或科学读写。

MSVC/CUDA 完整依赖／loader 新鲜度仍为 `unknown`；Windows 资源指标与 Linux 语义不同。合格终端使用 Windows Terminal，独立控制台 Win32 5 和冷元数据超时保留。原 Jeans／JENS GPU、SNIa 及其他科学组合限制继续适用；不新增 MPI、HIP／AMD、Apple Metal 或一般辐射输运。
