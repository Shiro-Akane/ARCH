# ARCH v1.2.1 update notes

[中文](V1.2.1.zh-CN.md) · [Feature list](../Features.md) · [Parameter reference](../Reference.md) · [Acceptance record](../../validation/gravity/flash/O6ControlsAcceptanceReport.zh-CN.md)

This update reduces repeated work in CPU, multiphysics and self-gravity execution and completes configuration, checkpoint and source-package checks. CPU and CUDA continue to share physical and numerical formulas. Fluid faces retain full EOS queries, conservative limiting remains active, and both burning calls in the Strang split are preserved.

## Computation and execution

- EOS and reaction-network results are reused for **exactly identical** states within an unchanged stage. Distinct states are evaluated independently; failed ODE/NSE trials follow the existing recovery and acceptance rules.
- All five fluid-flux policies share a CPU face traversal and limiter preparation, while CUDA invokes the same face mathematics. CPU isolated-gravity boundaries use dynamically assigned small tasks to balance unequal face costs; each face retains its physical formula and summation order.
- Release application and dispatch targets use `-O3` and supported link-time optimization. Strict floating-point evaluation, finite-value checks and subnormal handling remain in place.

## Configuration additions

| Parameter | Default | Purpose |
| --- | --- | --- |
| `hll_wave_speed` | `roe` | Select `davis` signal speeds for HLL/HLLC across supported reconstructions. |
| `eos_coulomb_mult` | `1` | Scale the Helmholtz ion Coulomb term and its derivatives within `[0,1]`; a nondefault value changes the physical model. |
| `dt_max` | `-1` | Optional physical macro-step cap in seconds; `-1` adds no cap, while another value must be at least `dt_min`. |

The parameters use the existing Runtime/EOS groups. `dt_max` does not relax CFL or burning limits; a nondefault Coulomb fraction requires Helmholtz, and a nondefault wave-speed choice applies only to HLL-family fluxes. The [reference](../Reference.md) gives the full constraints and units.

## Restart, packaging and documentation

Checkpoint state-control identity now includes these controls. Tests cover round trips and restarts with the current identity, explicit rejection of earlier identities, and rejection of damaged data. Failed reads preserve the live mesh; validation failures before writing preserve an existing file. Continue an earlier trajectory with its originating executable or initialize a new run with the current version. Reconfigure and rebuild after updating the source.

The build guide distinguishes EOS-table preparation in Git checkouts and source archives. A clean source-archive CPU build, Helmholtz and checkpoint checks, and the Sod entry case were exercised. The project README now maps the `src/` modules and presents the development roadmap. The [feature list](../Features.md) identifies current capabilities; the [reference](../Reference.md) owns low-density states, input migration and self-gravity boundaries. Completed migration process notes remain in the development archive.

## Validation and measured scope

The source passed 61 registered CPU checks, 135 registered CUDA checks and 42 production coupling/restart records. In paired full-process measurements of the three-dimensional cylindrical four-module AMR case, the tested host completed 7.53% faster with eight threads and 4.14% faster with sixteen threads after the boundary-scheduling change. On the same RTX 3060 Ti system, the two-dimensional four-module case achieved a 1.61× CPU/CUDA full-process ratio; the tested CPU configuration remained faster for the three-dimensional case. These measurements apply to the stated hardware, inputs and physical endpoints.

The [cost and accuracy record](../../validation/gravity/flash/O6ControlsAcceptanceReport.zh-CN.md) and [release follow-up](../../validation/gravity/flash/results/release-readiness-20260927/README.md) retain inputs, error budgets, source identities and timing samples. Long-duration multiphysics reliability and equal-error cost comparisons across codes require separate validation.
