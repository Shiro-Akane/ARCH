# ARCH v1.2.1 candidate

[中文](V1.2.1.zh-CN.md) · [Detailed acceptance record](../../validation/gravity/flash/O6ControlsAcceptanceReport.zh-CN.md)

This performance-patch candidate reduces repeated EOS, reaction-network and
backend execution work while retaining the shared CPU/CUDA mathematics, full
face EOS, conservative flux limiting and both Strang burning half steps.
This round closes the current implementation scope while recording engineering
validation separately from cross-code cost and accuracy limits. The original
uniform two-times-FLASH target remains unmet; further numerical methods are
discussion topics. These notes do not publish a tag.

## Execution and numerical controls

- Exact state reuse and grouped EOS/network queries reduce repeated work within
  an immutable stage. Failed trial states still follow the existing ODE/NSE
  recovery contract; required and accepted states retain explicit checks.
- CPU isolated-gravity boundary tasks use dynamic chunks to balance variable
  tree traversal and near-field integration costs. Per-face physics and summation
  order remain shared with CUDA.
- All five flux policies share one CPU face traversal and limiter preparation.
  CPU and CUDA consume the same face mathematics and mean-state view.
- `hll_wave_speed=roe|davis` selects acoustic bounds for HLL and HLLC with any
  supported reconstruction. `roe` remains the default; both choices retain full
  thermodynamic closure. This is a numerical-method choice, not a universal
  accuracy or performance improvement.
- `eos_coulomb_mult` scales the Helmholtz ion Coulomb contribution and its
  derivatives consistently. The default is the full correction; changing it
  changes the physical model. Electron/positron completion is independent.
- `dt_max` optionally caps the physical macro timestep. Controls belong to the
  existing EOS/Runtime configuration groups; advanced visibility is a GUI concern.
- Release application and dispatch targets share `-O3` and supported LTO/IPO.
  Host code disables unused libm errno side effects while retaining strict
  floating-point evaluation, finite checks and subnormal values. Global
  fast-math remains unsupported.

## Migration and limits

The configuration catalogue contains 95 standard keys. Checkpoint format 6 now
requires state-control identity revision 2, including the three new controls.
Current-identity round trips and restarts, old-identity rejection, and damaged
payload rejection are covered by the maintained checkpoint tests. Errors identify
incompatible controls separately from corrupt data; rejected reads preserve the
live mesh and validation failures before writing preserve the existing file.
Earlier identities are not silently migrated. Rebuild the application and
continue old calculations with their original executable or start from
appropriate new initial data.

Face-EOS approximations did not meet the preregistered scientific error budget
and are not included. The default thermal closure, ODE tolerances, CFL stability
bound and AMR criteria remain in force. CPU/CUDA gains depend on workload and
hardware. Earlier three-dimensional CPU timing increases prompted a paired
source-version investigation and a boundary scheduling fix; the
[release follow-up](../../validation/gravity/flash/results/release-readiness-20260927/README.md)
separates confirmed scheduling costs from run-to-run variation. Representative
coupling checks do not establish universal GPU speedup or long-duration
reaction-flow equivalence with FLASH. See the
[Reference](../Reference.md) and linked acceptance record for the measured scope.
