# ARCH V1.0.0

Source release with the existing CPU/CUDA solver architecture, hosted CPU/tooling
CI, component-aware tabular EOS loading and data-driven generated-network NSE.
Build locally and fetch runtime tables with `git lfs pull`; prebuilt executables
and CUDA libraries are not release assets.

## Highlights

- One EOS dispatcher manages source recognition, rank, component dependencies,
  caching, restart identity and supported coupling checks. No Shen-specific
  physical policy or second CUDA macro system is introduced.
- Normalized 3D/4D free-energy tables declare existing components. Missing
  electrons/positrons and photons are added once during loading. Strict queries
  use a single interpolating potential and reject unsupported states or
  nonunique inverses.
- Original EOS2/EOS4 positive-temperature baryon tables are included through
  LFS under their authors' CC BY 4.0 license. Processed HShen tables are not
  included; their EOSDriver interface has been checked separately.
- Eligible pynucastro networks use shared, nuclear-data-based NSE. `use_nse=auto`
  selects by capability; it and explicit enablement use identical temperature
  and density thresholds. Unsupported automatic NSE retains kinetic ODE
  burning; unsupported explicit NSE is rejected. Existing aprox/iso routes remain.

## Verification and boundaries

The extension passes all 37 CPU Release tests, 307 tooling controls, three
real-generated-package/registry checks and four focused CUDA tests with their
host fixture. Strict 3D/4D owners and the native HShen owner pass focused
memcheck with zero errors/leaks. Both original baryon tables pass bounded
source-node/interior checks, two uniform application runs and eight startup
rejection controls. See the [evidence and reproducible inputs](../../validation/eos/results/tabular-extension-20260908/README.md).

These new checks do not rerun or replace the previously identified full CUDA
physics/restart campaign. Raw-table support covers a validated subdomain, not
the entire source grid or arbitrary astrophysical formats. Nuclear-equilibrium
tables cannot be combined with independent kinetic burn/NSE energy sources.
Generated NSE eligibility does not extend to arbitrary weak, screened or
excited-partition-function equilibrium models. Tabular electron diagnostics
also limit automatic stellar transport and eta-dependent weak-rate coupling;
see the [EOS contract](../../src/physics/eos/TabularEOS.md) and
[NSE model limits](../../src/physics/nse/README.md).

The source release retains historical failed and successful validation evidence
with its original identity. Third-party data and Timmes-derived material retain
their separate [notices and terms](../../THIRD_PARTY_NOTICES.md); ARCH's code
license does not relicense those assets.
