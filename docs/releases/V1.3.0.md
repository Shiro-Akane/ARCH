# ARCH v1.3.0

[中文](V1.3.0.zh-CN.md) · [Studio guide](../guides/Studio.md) · [Configuration reference](../Reference.md) · [Acceptance record](../../validation/backend/results/release-readiness/REL6CandidateAcceptance-20261020.json)

This source release adds ARCH Studio, completes the architecture modernization, and replaces silent fallback for critical configuration with explicit validation. CPU and CUDA retain shared physical and numerical mathematics.

## ARCH Studio

The optional desktop interface brings grouped parameter editing, Configure/Build, real Core initial-field and initial-AMR previews, confirmed Run/Restart in an independent terminal, and read-only Plotfile inspection into one cohesive workflow. The Inspector reports stored native-cell values, units, and producing-run identities. Preview provides bounded initialization; actual runs retain Core startup and scientific checks. See the [illustrated Studio guide](../guides/Studio.md#workspaces). The scientific executable remains independently usable.

## Architecture and configuration

- Common numerical, state, Grid, and curvilinear owners serve both backends; device storage and execution remain in CUDA adapters. Geometry stays independent from optional gravity. Axisymmetric cylindrical r-z uses the existing Grid/curvilinear infrastructure, retains rotation and conservative AMR, and avoids a parallel RZ implementation.
- Critical missing values, invalid options, and unsupported active combinations now fail explicitly. Documented defaults and automatic selections retain their recorded origin; permissive compatibility aliases and silent conversion of retired inputs are removed. Update old inputs from the current examples and [configuration contract](../development/ConfigurationContractPlan.zh-CN.md).
- Shared curvilinear pressure balancing removes the high-pressure near-zero momentum discrepancy on the tested original inputs. Numerical tolerances and strict floating-point rules are preserved.
- Build/test responsibilities, source comments, and ownership maps are clearer; routine CI has bounded, explicit coverage. Current guides are consolidated, with historical material under `docs/histroy/`. Runtime installation includes the declared example inputs, tables, and notices; system dependencies remain required.

## Verification and use

The [acceptance record](../../validation/backend/results/release-readiness/REL6CandidateAcceptance-20261020.json) maps all 16 public models to applicable evidence. It covers clean CPU/CUDA builds and relocated installs, affected numerical and restart checks, a real generated network with all three ODE methods and NSE on/off, and the actual Studio workflow. The 388 Studio tests pass without skips. Existing long scientific evidence is retained with its original scope.

Supported execution remains Linux/WSL2; CUDA qualification here uses RTX 3060 Ti/sm86. SNIa admission combines the accepted main endpoint/conservation/restart with approved repeated-AMR supplementary evidence; the original main repeated-AMR FAIL and thermal GAP remain recorded. Hotspot functional endpoints do not establish a separate ignition-mechanism result. Full CUDA compilation remains costly; timings are retained without a general speedup claim.

Start with [build and first run](../../README.md#build), then the [case guide](../guides/SimulationCase.md). Rebuild after upgrading; retired chart identities and incompatible restart/output products are rejected explicitly. Required scientific tables retain their documented provenance and Git LFS delivery; use matching existing local copies when available. This follows the prior source-only release model: no prebuilt Core/CUDA libraries or raw simulation outputs are attached. See [third-party notices](../../THIRD_PARTY_NOTICES.md).
