Release date: **2026-10-27** · [GitHub release](https://github.com/Shiro-Akane/ARCH/releases/tag/v1.4.0). Native Windows support was integrated through [PR #21](https://github.com/Shiro-Akane/ARCH/pull/21). Zenodo remains deferred; no v1.4.0 Zenodo DOI is claimed.

## Main update

ARCH provides corresponding **native Windows 11 x64 CPU/CUDA CLI and Studio functionality** alongside Linux/WSL2, within the existing scientific scope. Linux remains recommended; Windows support is newer and may still have instability or bugs.

- CPU/OpenMP uses GCC/UCRT64 and matching HDF5/KLU. Native NVIDIA CUDA uses a separate MSVC/NVCC ABI tree and Windows SDK. Both build the existing ARCH target; the CUDA executable selects `cpu`, `cuda` or `auto` at startup.
- The shared Host provides configuration, Build, real initial-field/AMR Preview, terminal Run/Restart and read-only Plotfile metadata, raw samples, native point and display LOD. Native windows and portable packaging use the same production sources and license-copy flow on both systems.
- Paths, process supervision, output reservation/publication and bounded workers have native platform support. Solvers, mathematical owners and scientific formats remain shared.
- The guides explain registered models versus C++ source, parameter Help/Inspector, working-copy saves, Plotfile navigation and Linux/Windows `.par` paths. Relative paths resolve from the calculation working directory, not beside the `.par` file.

## Verification and retained scope

The [26-area qualification](../histroy/build/WindowsNativeCudaQualification-20261027.md) records 142 native Core contracts, 37 canonical backend cases/nine resolution groups, eight CPU/CUDA AMR restart routes/nine comparisons, actual Host GPU Run/Restart/Plotfile readback against native h5py, and zero errors/leaks in the complete original geometry memcheck. The representative same-backend restart used zero tolerances. Linux recorded 72 CPU CTests, 12 affected CUDA/real-fixture tests and 453 Studio tests; native Windows recorded 95 Studio tests and seven link-evidence tests. Dated W3 human dialog/display/normal-close evidence remains separate from programmatic GPU checks.

Implementation head `dd42d4fa479a262920c7c772794a898c42665e70` passed [ARCH CI #88](https://github.com/Shiro-Akane/ARCH/actions/runs/40430379002) and its CodeQL comparison gate without annotations. Later release/dependency commits require their own exact-head checks; previous results are not relabelled as tests of a new commit.

Approved A12–A18 changes address IEEE classification, declaration tags, Host/Device layout annotations, 742 Helm nodes bit-identical to frozen Linux and failed-array assignment. Formulas, thresholds, rejection checks and pool allocation/capacity/ownership retain their contracts. This release-preparation phase makes no further mathematical, pool or scientific I/O changes.

Full MSVC/CUDA dependency/loader freshness stays `unknown`. Windows resource limits differ from Linux counters; Windows Terminal is the qualified handoff, and the independent-console Win32 5 and cold metadata timeout failures remain recorded. Existing Jeans/JENS GPU, SNIa and other scientific limits continue to apply. MPI, HIP/AMD, Apple Metal and general radiation transport are not added.
