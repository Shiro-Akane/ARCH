# ARCH v1.4.0 — native Windows support

[中文](V1.4.0.zh-CN.md) · [Release index](README.md) · [Build](../guides/Build.md) · [Studio](../guides/Studio.md)

Released **2026-10-27** · [GitHub release](https://github.com/Shiro-Akane/ARCH/releases/tag/v1.4.0)

## Main changes

ARCH adds native Windows 11 x64 support for its CPU/CUDA command-line program and Studio desktop. Linux remains recommended; Windows support may still have platform-specific instability or bugs.

- CPU/OpenMP builds use GCC/UCRT64 and matching HDF5/KLU. CUDA builds use a separate MSVC/NVCC toolchain and Windows SDK, with matching libraries.
- Studio supports configuration editing, Configure/Build, real initial-field and initial-AMR Preview, terminal Run/Restart and read-only Plotfile inspection on both platforms.
- Native path handling, process supervision, output reservations, file publication and bounded workers support the shared scientific implementation and file formats.
- Linux and Windows use the same desktop packaging flow. Electron versions are checked against the manifest, lockfile and installed package.

## Dependencies

This release uses Vite 8.3.4, Electron 44.9.1 and Undici 7.30.1. The development-only Zod dependency is updated to 4.6.7, addressing [GHSA-mrhx-c7xc-m3w5](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5). Dependency versions and licenses are recorded in the Studio lockfile and inventory.

## Compatibility and validation

Windows and Linux share the numerical methods, physical models and HDF5 formats. Native portability fixes preserve the formulas, error thresholds and memory-pool behavior. Each compiler ABI requires its own build and dependency directories.

[Platform support](PlatformSupport.md) lists tested configurations, the CPU/CUDA/Studio comparison and Windows limitations. Full MSVC/CUDA dependency freshness remains unknown; Windows Terminal provides the supported independent Run/Restart route. Scientific combinations and model limits are described in [Features](../Features.md) and [Validation](../../validation/README.md).

## Distribution and citation

The release contains source, a SHA-256 checksum and `ARCHIVE_PROVENANCE.json`. Scientific table files retain Git LFS pointers; prepare their data using the [build guide](../guides/Build.md#source-archives-and-eos-tables). Core executables and portable desktop packages are built separately.

Use the release URL and version date when citing v1.4.0. A corresponding Zenodo version has not been published; the existing series DOI and v1.3.0 version DOI are listed in the [citation guide](../zenodo/README.md).
