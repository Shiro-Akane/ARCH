## 2. 参数面板

### UI-01：补齐 Network Advanced

**现象**：当前 Network 分类包含主要开关、阈值和 NSE 选项，但没有把 Burn 下的 ODE 配置纳入分类。即使 `.par` 写有这些配置，也会落到 Custom Parameters；文件没有写时则无法从完整参数列表中找到。

**需要补充的配置键**：

| 小组 | 参数键 |
|---|---|
| 求解器 | `ode_solver`、`linear_solver` |
| 容差 | `ode_rtol`、`ode_atol` |
| 迭代与子步上限 | `ode_max_newton_iter`、`ode_max_substeps` |
| 步长调整 | `ode_dt_safe_fac`、`ode_dt_fac_max`、`ode_dt_fac_min`、`ode_initial_dt_frac` |
| 高级计算选项 | `ode_use_numerical_jac`、`ode_freeze_jacobian` |

**期望**：使用易读名称，保留原始参数键供检索和查看。例如“相对容差 RTOL / ode_rtol”“绝对容差 ATOL / ode_atol”。这些项目可以折叠，但需要能被搜索到。Network 中其余 Burn 配置也纳入同一份覆盖清单，见附录。

**验收**：打开未写 `ode_rtol`、`ode_atol` 的配置仍可找到二者；能看到 Core 对该配置采用的默认值；修改后进入当前编辑副本，保存和再次加载后数值一致。

### UI-02：完整参数目录与分块展示

**核对结果**：按 `RuntimeParams.h` 中直接调用 `GetString/GetInt/GetDouble/GetBool` 的不同键统计，共 90 个，包含兼容别名；当前 `parSchema.ts` 已归类 63 个，未归类 27 个。这是配置入口覆盖统计，不包含任意模型的 custom 参数，也不代表这 63 个参数的所有控件和约束都已完善。

面板目前从 `.par` 已有的条目构建列表。仅补充 `parSchema` 分类，仍不能展示文件中省略的标准参数。

**期望结构**：

| 一级分块 | 内部内容 |
|---|---|
| Grid | 区域、维数相关配置、边界、AMR |
| EOS | 类型、相关常数、表文件 |
| Network | 网络与开关、阈值、NSE、ODE / Advanced |
| Gravity | 类型、对应参数 |
| Diffusion | 开关、扩散种类、系数与高级控制 |
| Runtime | 时间与步数、数值方法、计算后端、输出与重启配置 |
| Custom Parameters | 当前模型额外参数和仍未识别的原始键 |

界面同时区分“文件已设置”“使用默认值”“本次已修改”“当前条件下不适用”。查看默认值不应自动把所有默认项写进 `.par`；用户实际修改时再写入。原始键、表达式、注释和未识别的参数继续保留。

“全部参数”指公开可配置的输入。C++ 中的计算结果、缓存、报告字段、编译期常数和派生状态不自动变成输入框。例如 `BurnOdeReport` 是运行报告，`BurnLimits` 是程序限制；`BurnConfig::ignition_temp/burn_tol` 在当前 `RuntimeParams` 中没有对应读取入口，需要 Core 决定是否作为配置开放，前端不能只新增输入框就宣称生效。

**默认值来源需要统一**：当前结构体初值与解析回退值已有差异。例如 `ode_max_substeps` 的结构体初值是 100，而解析缺省值是 10000；`ode_initial_dt_frac` 分别是 `1e-14` 与 `1e-3`。GUI 应采用实际配置解析路径的值，由 Core 提供或核定，避免复制结构体注释后显示错误默认值。

**验收**：附录中的标准参数均有归属，文件省略的项目可查可编辑；界面区分输入值和 Core 实际采用的值；默认值显示与真实解析结果一致；保存不会无故扩写整份文件。

### UI-03：Gravity 与 Diffusion 分块

Gravity 需要收纳 `gravity_type`、`gravity_g_x/y/z`、`gravity_G`。Diffusion 需要收纳总开关、三个子开关、积分设置和三个系数，完整键见附录。

控件需要跟随当前选项显示适用性：

- 当前基线的 self gravity 尚未实现。可以展示其状态和已有配置，但不能把它呈现为已经可运行的选项。
- 当前 Core 明确禁止在 Helmholtz + diffusion 配置中显式设置 `alpha_therm`、`nu_visc`、`D_spec`，因为系数由物理计算给出。此时显示原因，已有冲突项明确指出；不要自动删除用户配置，也不要为显示默认值而插入这些键。
- 模块关闭时保留已有参数，可折叠或标为暂不生效。
- 这些分块首先用于配置编辑。初始预览成功不表示重力、扩散或完整 simulation 已经过运行验证。

**验收**：标准重力、扩散参数不再混入 Custom；开关和依赖关系清楚；受限制的组合在生成预览或保存前能被看见，并由 Core 作最终校验。

### UI-12：Grid 各轴保持同一级，按 blocks 展开轴内设置

**现象**：一维时，Y/Z 的 blocks、范围和边界条件一起被放入 Advanced。用户在 Advanced 中增大 blocks 后，维数改变，正在操作的控件又被移回普通区，容易丢失位置或输入焦点。`panelPresentation.ts` 的 `inactiveAxisKey()` 将 blocks 本身也列为非活动轴参数，是这次需要调整的分类依据。

**期望布局与交互**：

1. X/Y/Z 三个轴区块固定在 Grid 同一级，顺序保持不变。柱坐标、球坐标使用 UI-04 的对应名称，原始轴身份仍是 x1/x2/x3；维数改变导致名称改变时，区块本身不换位置。
2. 未启用轴显示紧凑的轴标题和 blocks 入口，可随时展开；blocks 不进入 Advanced。用户不必寻找高级选项才能从 1D 改为 2D/3D。
3. 某轴 blocks = 0 时，显示“未启用”，隐藏该轴的 min/max、两端边界条件（BC）等从属控件；已有值保留在编辑副本和文件中，不因界面收起而被删除或重写。
4. blocks 是合法正整数时，在该轴原位置展开 min/max、BC 等设置，形式与 X 轴一致。收起和展开不使当前 blocks 输入框消失或丢失焦点。
5. blocks 输入处于暂时空白或非法状态时，显示校验信息，维持最近一次有效的布局；不能把空字符串、NaN 或截断后的小数当作维度切换指令。

**启用阈值核对**：Core 使用 `nblockx2 > 0`、`nblockx3 > 0` 判断活动维度，因此 1 个 block 就已启用。界面应采用“0 关闭，整数 ≥ 1 启用”，不是必须 > 1。X 轴正常编辑要求正整数；Y/Z 关闭使用 0。负数作为非法块数提示，不替用户静默改为 0。

**轴之间的关系**：Core 不允许 Y/x2 关闭但 Z/x3 开启。用户尝试这种组合时，就地指出“启用第三轴需要先启用第二轴”；关闭第二轴时若第三轴仍开启，也需指出冲突。不要未经用户操作连带改动另一轴的块数、范围或 BC。先改成符合关系的配置，再接受新的维度状态。

**简化布局示意**：一维时显示“X blocks + X 范围/BC”“Y blocks = 0 · 未启用”“Z blocks = 0 · 未启用”；Y 改为 1 后，直接在 Y blocks 下展开 Y 范围/BC；Z 启用后同理。未启用轴的紧凑区块与 X 同级，始终可找。

**验收**：完成 1D → 2D → 3D → 2D → 1D，再重新启用轴；控件不跨区跳动，范围/BC 原值保留，Undo 能恢复块数及对应布局。分别覆盖 blocks 为 0、1、2、小数、负数、暂时空白，以及 x2 = 0 / x3 = 1 的冲突组合。曲线坐标下同样检查名称与轴身份的一致性。

### UI-13：统一输入拦截与文件路径预检

**现有基础与缺口**：`parState.ts` 已对当前文件中、且在 schema 中归类为 int 的参数执行完整 32 位整数校验，也已有浮点数、布尔值及部分关联条件检查。`NumericInput` 允许保留正在输入的原始文本，由校验层指出问题。这部分需要保留并补齐覆盖，而不是登记为完全没有校验。

当前新增到 `state.changes`、但原文件没有的键，仅在补充循环中检查换行、注释等字符，并未自动经历同一套类型校验。新增标准参数入口后必须补上，否则“原文件已有参数”和“新插入默认项”会出现不同的拦截结果。未归类的标准参数也应随 UI-02 补全类型信息。

**Core 侧补充核对**：`ConfigParser.h` 的标准 `GetInt/GetDouble` 尚未检查数值转换后的完整消费位置；因此输入拦截需要同时覆盖 Core，不能仅靠前端。该项由我们补齐格式检查及对应回归，具体分工见第 7 节。

**输入规则**：

| 参数类别 | 需要检查和提示的内容 |
|---|---|
| int，例如 blocks、次数、阶段数 | 只接受合法整数及 Core 规定范围；拒绝 `1.5`、`1.0`、`1e2` 等非整数文本写法、混入后缀及溢出值。不能截断或四舍五入后悄悄接受；不同字段的 0、负数含义按各自规则判断 |
| float | 接受 Core 支持的有限小数与科学计数法；拒绝 NaN、Infinity、非法后缀，并检查对应上下限 |
| bool / 枚举 | 检查 Core 实际接受的值；来源文件中的未知值保留并指出问题，不悄悄替换为下拉框第一项 |
| 坐标等表达式 | 按 Core 支持的表达式检查，例如 `pi`、`2*pi`；不能仅因包含字母就作为非法浮点数拒绝 |
| 一般字符串 | 按该字段的具体规则检查。名称、模型 ID、网络名不按文件路径处理 |
| 输入文件路径 | 如当前 EOS 需要的表文件、启用重启后的 restart_file：检查路径解析、文件是否存在、是否是文件、是否可读；格式和内容是否适用由 Core 后续确认 |
| 输出目录 / 新建文件目标 | 目标尚不存在可以合法；检查父目录、可创建条件及写入权限，不能要求所有输出目标事先存在，也不为预检创建文件或目录 |

**交互要求**：

- 区分正在输入的文本和已接受的有效值。错误贴近具体输入框，说明要求；保留用户输入供修正。非法值不能作为已验证参数进入保存、导出或 Preview 请求，也不能驱动轴布局和图形绑定。允许中途键入空白或负号，不代表已经接受它们。
- 鼠标拖动、键盘输入、粘贴、加载文件、插入默认项和图上绑定走相同校验；同时检查字段间关系，例如活动轴 max > min、轴启用关系、EOS 与 diffusion 的限制。
- 格式错误和已确认不符合 Core 约束的值就地拦截。路径检查失败说明具体原因；必需输入缺失时阻止依赖该输入的操作。保存配置与实际使用该路径分开说明，避免把“文件缺失”和“文件内容格式错误”混为一类。
- 路径由本地 Host 在实际执行环境检查，按与 Core 相同的基准解析，并显示解析后的目标。当前 Preview 从项目根目录执行，相对路径不能默认按浏览器或 `.par` 所在目录解释。
- Host 未连接或没有检查权限时显示“尚未检查 / 无法检查”，不冒充“路径存在”或“文件不存在”。路径检查不等于文件内容已经通过 Core 验证；输入改变后过期的检查结果不得覆盖当前状态。
- 模块关闭、路径字段不适用或允许为空时，按 Core 的适用条件处理，不强制用户填写无关路径。未知 custom 字段继续保留原始文本，不根据名称猜测类型或路径含义。

**验收**：已有和新插入的 int 项均拒绝小数、溢出与带后缀的数值；修正后恢复可操作。整数输入不会被静默取整。路径测试覆盖有效文件、缺失文件、目录冒充文件、不可读文件、项目相对路径、合法的新输出目标和未连接 Host；错误定位到具体字段，且不修改现有文件。Core 保留最终检查，前端提示与 Core 报错含义一致。

## 3. 坐标与单位

### UI-04：显示名称随 geometry 和维数切换

参数文件继续使用 `x1/x2/x3`。GUI 可以显示 `r 最小值（x1_min）` 这样的名称，坐标轴、区域上下界、边界条件和 Inspector 使用一致称呼。

当前 `Grid::GetAxisNames()` 的约定如下。尤其注意：本版本的两种二维曲线坐标都是极坐标平面。

| geometry | 1D | 2D | 3D |
|---|---|---|---|
| cartesian | x | x, y | x, y, z |
| cylindrical | r | r, φ | r, z, φ |
| spherical | r | r, φ | r, θ, φ |

径向、轴向坐标与角坐标的单位分别展示；角度按 Core 的弧度约定标为 rad。维数还未确定时保留中性原始名称，不先猜成常见的另一种二维约定。重力分量等相关标签也需由 Core 核对，不能直接套用可能过时的结构体注释。

**验收**：切换 geometry 或有效维数，名称同步改变但原始键不变；二维 cylindrical 不误标为 r–z。当前两个真实 Preview 仅支持 Cartesian，配置标签的完善与新增曲线坐标预览分别验收。

### UI-05：给标准物理量提供单位

**需求方向**：按项目的 CGS 使用约定给有明确物理含义的变量提供标签。Custom 参数尚无单位依据时继续显示“单位未提供”；已有明确单位或与已知坐标共享单位的 custom 参数可以显示对应单位。

CGS 场景下的目标显示表：

| 字段 / 内容 | 单位 |
|---|---|
| `DENS` 密度 | g/cm³ |
| `TEMP` 温度 | K |
| `PRES` 压力 | dyn/cm²，等价于 erg/cm³ |
| `VELX/VELY/VELZ` 速度 | cm/s |
| `ENER` 总能量密度 | erg/cm³ |
| `EINT` 单位质量内能 | erg/g |
| 空间长度 | cm |
| 时间 | s |
| 组分质量分数 | 无量纲 |

字段正式名称是 `TEMP`。`ENER` 与 `EINT` 的单位不同。无量纲与单位未知也需要分别表达。

**代码核对出的待统一项**：Helmholtz 和相关微物理已有明确 CGS 依据；当前仓库同时允许 IdealGas 模型使用自定单位，`IdealGasView` 还保留带 J/(kg K) 注释的比热回退值，Sod 设置了自身的比热数值。因此，“所有模型目前都已经统一为 CGS”还不能仅凭字段名从代码确认。Core 需要明确这些模型如何纳入统一约定，再提供相应标签；这不应交给前端靠数值大小判断。

现有 Preview API 的单位字段统一为 `null`，README 要求前端不自行推定。下一轮应同步修订 Core 返回内容、示例和该说明，使 Studio 按正式单位显示。这不要求使用者为每份 `.par` 额外写声明文件。

**验收**：CGS 已确认场景的坐标轴、图例、Inspector、参数说明使用同一套单位；单位未知与无量纲有区别；显示标签本身不改变任何数值。理想气体场景在约定明确后使用相应标签，不机械套用整表。

## 4. 预览交互

### UI-06：缩放只改变坐标轴的异常

**用户观察**：缩放 Preview 时，坐标刻度持续变化，内部渲染出的内容看起来保持不变。

**影响**：无法判断图中位置、宽度及 Inspector 选点是否仍然可靠。这是本次需要优先复现的显示缺陷。尚未定位根因，也尚未确认只发生于一维、二维还是两者；不要先归因于某个绘图库或缓存机制。

**期望与验收**：

1. 使用有明确断面或非均匀结构的场测试；分别验看 Sod 曲线和 CellularDet 二维图，不以均匀色块作为唯一判据。
2. 放大、缩小和平移时，数据内容、坐标轴、Sod 标记、选点标记与点击取值保持同一个位置关系。
3. 固定物理位置的采样点在缩放前后读数一致；放大后屏幕中的间距、裁剪范围有相应变化。
4. Fit / Reset 能恢复完整视图；窗口尺寸改变和切换字段后仍正常。

缩放是查看已有数据，不应触发参数修改、保存或重新运行初始化。

### UI-07：增加少量明确的制图选项

在绘图区附近提供可收起的显示设置，优先完成：

- **坐标轴设置区**：靠近坐标轴或独立的“坐标轴”面板，为空间 X 提供 Linear / Log；二维时为空间 Y 提供自己的 Linear / Log。
- **场值设置区**：靠近字段选择或图例，单独提供当前场值的 Linear / Log。一维图中它控制纵轴数值；二维图中它控制颜色映射，不改变空间 Y 轴。
- 两类设置必须放在分开的区域，各自清楚标注控制对象，不合并成一个含义不明的“Log”按钮。X 与场值的独立选择可组合出全线性、两种半对数及 Log–Log，见下表。
- 颜色表：保留当前 Viridis，增加 Hot 等少量选项；用户提出的 Vivid 风格可核对图库实际名称后纳入。选择时给出小型渐变预览。
- 两个设置区分别提供 **Advanced**，用于上下限和显示截断；Linear / Log 保持为直接可见的常用选项。

| 空间 X 比例 | 场值比例 | 一维图显示方式 |
|---|---|---|
| Linear | Linear | 全线性 |
| Log | Linear | 半对数：X 为对数 |
| Linear | Log | 半对数：场值为对数 |
| Log | Log | Log–Log |

二维时沿用同样的独立设置原则：坐标轴改变空间显示，场值比例改变颜色映射，空间 Y 的设置独立保留。

**Advanced：上下限与显示截断**

| 所属设置区 | 高级选项 | 行为 |
|---|---|---|
| 坐标轴 | 自动 / 手动范围、下限、上限 | 每个空间轴独立设置可见范围；与缩放、平移和恢复完整视图保持一致 |
| 场值 | 自动 / 手动范围、下限、上限 | 一维控制场值纵轴显示范围；二维控制颜色映射范围；不改变空间坐标范围 |
| 场值 | 下限截断、上限截断及阈值 | 可分别启用；明确标识超出阈值的数据如何显示。二维可使用色标端点饱和并标明低于/高于阈值；一维裁切超出视区的部分并提供边缘提示，避免将其误认为恰好等于阈值 |

每组设置可恢复自动范围。显示上下限与截断阈值使用原始数值及对应单位，即使选择 Log 也不要求用户输入对数后的数值；下限必须小于上限，Log 下相关边界和阈值必须为正数。默认采用自动范围，不额外启用数值截断。若截断阈值与显示上下限共用一个范围，界面明确说明其关系，避免出现两套互相矛盾的设置。

启用截断后，图例或绘图区持续显示“已截断”及所用阈值；Inspector、原始极值和 Core 响应仍保留真实数值，不能把显示范围外的数据改写成阈值或从数据源中删除。上下限、比例、颜色和截断均属于绘图设置，不写入 `.par`，也不触发初始化重算。

对数显示遇到零或负值时给出直接提示，并提供明确的处理方式，例如保持 Linear；不能悄悄取绝对值或改掉原值。图例显示当前比例和单位，Inspector 仍显示原始数值。显示设置与 `.par` 分开保存，不把改变颜色记作参数修改。

**验收**：X 和场值选项分别位于坐标轴与场值设置区；逐项验证表中的四种组合，改变一项不会连带改动另一项。二维图另外检查空间 Y 与颜色映射互不混淆；Advanced 覆盖自动/手动上下限、仅下限截断、仅上限截断、双侧截断、非法范围与恢复默认，所有截断均有标识且取值保持原始数值。切换显示选项即时生效且不发起新的 Core Preview；同一点的原始值保持一致；切换字段后颜色范围和比例的适用性会重新检查。

## 5. 模型、文件与旧结果的对应关系

### UI-08：左上角常驻显示模型与完整参数文件名，配对疑点提供警告

**用户场景**：选中 Cellular 相关模型/源码，却打开 Sod.par。当前提示可能仅为“parameters changed”，用户容易认为只需修正参数，继而开始修改本来属于另一模型的文件。这个提示原本是在说明“画面来自旧的预览”，需要与文件配对提示分别表达。

**已明确的界面要求**：左上角固定显示当前 config 对应的注册模型名称，以及 `.par` 的完整文件名。字体比普通参数标签稍大、适度加粗；模型和文件在两个稳定的行或栏目中，不能仅放在悬浮提示里。建议显示标签为“当前模型”“参数文件”，避免把源码、模型和参数文件都统称为 Config。

例如当前仓库的实际组合可以显示：

- 当前模型：**CellularDet**
- 参数文件：**CellularPreview2D.par**
- 辅助信息：源码 `simulation/Cellular/Cellular.cpp`；参数位置 `simulation/Cellular/CellularPreview2D.par`。

主名称使用注册名 `CellularDet`，由 Host / Core 的当前模型关联提供，不从 `.cpp` 文件名截掉后缀后猜测。完整 `.par` 名称包括扩展名、版本和参数后缀；长名称允许换行或展开查看，不只显示丢失关键后缀的省略名称。同名文件通过下方路径区分，完整路径可查看、复制。Host 未取得真实路径时标明仅导入文件副本，不能伪造路径，也不能执行目录比较。

常驻名称本身始终醒目；出现配对疑点时再附黄色图标和具体原因，普通状态不一直着警告色。切换模型、打开文件和另存为后及时更新名称。未保存修改另用状态标记表示。图中保留旧结果时，单独显示“当前选择 CellularDet；图中仍是上次 Sod 结果”，不把旧图名称挪成新模型名称。

**命名与位置检查的评估建议**：以下规则用于提醒用户核对，不形成强制命名规范，也不禁止配置复用。

| 线索 | 能说明什么 | 建议呈现 |
|---|---|---|
| 文件名前缀与模型/源码有关 | 便于用户辨认，但不能证明内容适用；模型注册名与源码名本来就可能不同 | 作为辅助线索，接受项目已有别名和参考配置；不要求三个名称完全一致，不据此显示“已验证正确” |
| 当前模型 CellularDet，文件名明确指向另一个已知模型，例如 Sod.par | 有具体的配对疑点 | 黄色提示“当前模型为 CellularDet，文件名提示它可能用于 Sod，请核对” |
| 文件名为 1.par、test.par 等，无法推断模型 | 关联信息不足 | 中性提示“关联未确认”；不因通用命名而持续报警或反复弹窗 |
| `.cpp` 与 `.par` 不在同一目录 | 可能误选，也可能是归档、参数扫描或共享配置的正常组织方式 | 显示两个路径；单独的目录差异只作位置提示，不升级为错配或强制确认 |
| 项目已保存的配对关系与当前选择冲突 | 比名称、位置更直接的关联证据 | 明确告知原关联与当前模型，允许用户继续使用、切换或重新关联 |
| 用户已明确确认这组模型和配置是有意组合 | 用户的使用意图已明确 | 对同一组合不重复相同的命名/目录警告；这不表示 Core 已验证数值或运行正确性 |

目前 `Cellular.cpp` 注册为 `CellularDet`，参考参数文件是 `CellularPreview2D.par`。这组实际名称说明，直接拿注册名作为唯一前缀匹配条件会误报。目录相同也不能证明正确，复制到同目录的 Sod.par 仍可能被误用。名称和目录两项都不同，也不能直接当作已经证实的错误。

**建议的交互顺序与确认方式**：

| 用户动作 | 提示与执行方式 |
|---|---|
| 选择模型 / 打开 `.par` | 更新左上角名称与必要的配对提示；不自动修改文件。替换未保存副本时沿用现有保存/放弃/取消流程 |
| 编辑参数 | 提示持续可见，允许继续编辑；普通输入不反复弹窗 |
| 首次用有明确配对疑点的组合生成预览 | 一次确认“使用 CellularDet + Sod.par 生成初始预览？”并说明不保存文件；提供“切换配置”“继续预览”“取消”。名称或目录疑点不能导致预览永久禁用 |
| 覆盖保存有配对疑点的配置 | 展示当前模型、完整目标路径和“将用当前编辑内容覆盖该文件”；提供“另存为”“覆盖保存”“取消”。不使用笼统的“是否继续”按钮 |
| 另存为新配置 | 明确显示新文件目标；当前接口要求目标不存在，不应把该动作写成覆盖，也不暗中放开对已有目标的覆盖 |
| 下载副本 | 说明导出的是新副本；浏览器管理实际下载目标，不宣称覆盖了 Host 上的原 `.par` |

一条覆盖提示可以表达为：“当前模型：CellularDet。即将覆盖：……/simulation/Sod/Sod.par。文件名提示它可能用于 Sod；保存会将该文件内容替换为当前编辑内容。”按钮直接写“覆盖保存 Sod.par”。覆盖 `.par` 不涉及覆盖 `.cpp`；预览和编译也不应显示这个文件覆盖提示。

**减少重复打断**：可提供“本项目记住这组配对”，由 Studio / Host 保存关联，使用者无需添加声明文件。近期可先采用会话内确认：以项目、注册模型、源码身份、参数文件路径为范围，常规参数修改不触发相同警告；换模型、换目标或出现新的关联冲突时重新判断。用户对预览的确认不等于对覆盖保存的确认。首次明确确认某组目标的覆盖用途后，后续普通保存沿用现有流程；文件被外部修改时的冲突保护仍独立生效，不被配对确认取消。

**警告的边界**：文件命名、目录和关联疑点是可继续的警告。实际数值格式错误、Core 明确不支持的维数/geometry、文件访问失败等仍按各自校验处理，并同时给出核对模型/文件的入口。配对警告不能代替或解除这些校验。Core 初始化成功也不能证明用户没有打开错文件。

**验收**：覆盖正常 Cellular 组合、CellularDet + Sod.par、1.par、异目录归档、同名不同路径、有意复用配置、浏览器导入但路径未知、配对确认后多次修改与保存，以及外部文件变更。左上角身份完整且及时更新；名称/目录问题不会禁止继续；预览提示不误报覆盖；覆盖确认指出准确目标；旧图仍显示它实际来自的模型和参数版本。

### UI-09：旧模型 metadata 与新编辑副本隔离

**代码发现**：`ConfigPanel` 当前只比较项目 ID，就采用最近一次 Core 成功结果中的参数 metadata。模型切换时并没有同步限制这份 metadata 的适用模型。

**待回归场景**：先成功预览 Sod，再在同一项目打开 Cellular 配置并切换 Model；在新的成功响应回来之前，旧的 `x_pos` 默认项可能继续出现在可编辑/可插入参数中，Inspector 也有类似的旧 metadata 读取路径。

**期望**：参数说明与默认值的适用范围至少对应当前项目、模型和编译版本。实际采用值及其来源还需对应产生该值的参数版本。同模型编辑时可以保留稳定的参数定义，但不能把旧输入对应的结果标为当前有效值。旧结果可以作为历史保留，不能驱动另一模型的编辑器或图形绑定。

**验收**：切换模型、打开另一配置、重新编译、请求失败或取消后，旧模型参数不会进入新模型的默认项或写回入口；同模型正常编辑、Undo 与 Sod 标记绑定继续有效。

### UI-10：Source 与 Model 同步；通用模型接入逐步扩展

当前 Host 的 Source 固定关联 `simulation/Cellular/Cellular.cpp`，Preview Model 则可选 Sod 或 CellularDet。于是“看到 Cellular.cpp、实际预览 Sod”在当前界面中可能发生。这与真正的模型/`.par` 错配需要分开定位。

**近期需要完成**：选中哪个模型，就显示它对应的源码与当前配置关联；如果某个 Source 面板只是项目级构建入口，要直接标明用途，避免看起来像当前模型源码。切换关联时保留并提示未保存编辑。

**后续通用化方向**：用户选择模型源码、配套配置和项目，Host / Core 提供注册后的模型身份及该编译版本支持的预览能力。单纯打开一个 `.cpp` 文件不代表该模型已经编入程序或支持 Preview；界面分别呈现“源码已打开”“需要编译”“可预览”。使用者不需要另外编写机器格式的 UI 声明。

当前先将 Sod 与 CellularDet 的对应关系做好，再扩展模型列表和本地项目入口。任意 C++ 的图形绑定仍通过模型明确提供的位置关系接入，不由前端猜测初始化逻辑。Cellular 的可编辑位置标记在当前交付中尚未提供；以后接入 `radiusPerturb` 时按实际轴向分界表达，不能按名称画成圆。

**编译状态沿用真实边界**：`.par` 修改通常只需更新初始预览；已跟踪源码修改后需要编译。现有构建清单仍标为 `dependenciesComplete:false`，尚不能据此宣称任意新源码和所有头文件的变化都已覆盖。

## 补充：Preview Log 零值处理（2026-09-21）

场值和坐标轴分别选择 Linear/Log。普通 Log 仅显示正值；零值、负值、非有限值分别统计和提示，不能把零误报为负值。无效点留空或遮罩，曲线在空缺处断开。没有正值时显示无可绘制数据；Inspector 和原数组保持原值，切回 Linear 后恢复。禁止悄悄加 epsilon 或取绝对值。范围和截断放 Advanced，Log 范围必须正值且有序。具体交接见最新本地工作流需求文档第 5.7 节。
