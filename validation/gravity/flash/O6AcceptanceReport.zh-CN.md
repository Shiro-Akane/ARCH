## 实现边界

本轮保留网络、严格 EOS 反解、BD/BE/ROS4 控制器、RK2、两个 Strang 燃烧半步、AMR 判据和所有原容差。变化在于共享计算与调度：

- 生成网络的 Jacobian 已经产生 RHS，现在一次返回二者；同次热耦合 Jacobian 只形成一份 Helm 热力学导数。
- Helm 反解只计算调用方需要的导数，在固定密度／组成的反解中复用插值因子。Host hydro、燃烧准备、CFL 块扫描和 AMR 判据各自的词法作用域内允许精确状态命中的反解复用；完整的状态键、EOS owner 和阶段寿命约束其有效性。
- CPU 燃烧把块内单元分为有限大小的任务，使用一层工作线程。每个半步内只有全部输入位相同的成功 ODE 结果能复用；失败结果不复用，自定义策略须明确声明该合同。
- 表格 EOS 的未提交 ODE/NSE 候选使用调用局部失败状态，交回原拒步或线搜索；初态、必要查询和最终提交保留严格异常／设备错误状态。
- CUDA 继续调用相同数学库，在执行适配层按完整输入分组求值、批量启动 CFL，并复用同阶段均值热力学。HLLC 的均值身份匹配通过共用借用视图执行，补齐原先 Host 容器限制导致的设备遗漏。设备结果仍通过逐单元检查后提交。

这些规则不含算例名、特定网格尺寸或人为停烧阈值。输入相同状态复用的收益取决于实际场的重复程度，不能外推到任意湍流或全域不同状态。

## 剩余差距与方法选择

细网格每次真实叶单元宏步累计量，ARCH／FLASH 为 4,337,664／1,441,280，约 3.01 倍。实际宏步 258／103；平均叶单元数仅约多 20%。两端重网格 cadence 均为 2，ARCH 按轴曲率最大值，FLASH 使用多维 Hessian 指标并保留父块信息，块边长也为 16／8。按块数直接等同成本会误判；直接复制对方阈值也不会生成相同叶覆盖。

最新 CPU8 首次样本中 Hydro 16.24 s、两次 Burn 合计 10.39 s、重网格 1.62 s、CFL 0.63 s。把全部 Burn 假设成零成本，整程仍约 21.8 s，高于 `2×FLASH≈18.52 s`。这是排除“仅删一次燃烧即可达标”的成本分析，不是证明余下实现已达最优。

另做的线程等待对照中，默认等待为 31.92 s、用户核时 198.87 s；关闭 OpenMP 自旋后
为 31.69 s、用户核时 182.01 s。墙钟差约 0.7%，未用单次探针替换正式中位数，也未
改变默认环境。即使把关闭自旋后的当前核时理想分摊到八核，也约需 22.9 s，仍高于
两倍线。这只是保持当前指令工作量不变的资源估算，说明等待设置本身不足以达标；
不能由此证明共享求值、数学执行或 AMR 工作量已无可优化之处。两次探针的终点、
拓扑和场检查通过，记录见[资源对照](results/o6-acceptance-20260927/probes/o6view_resources.json)。

ARCH 的 CFL 上界来自当前守恒正性限幅条件 `dt/V * sum_faces(A*a) <= 1`，对应 `CFL/(2*sum_axes(a/dx))`。FLASH 的 Unsplit 参考采用不同水动推进及限步定义。合法 `cfl<=1` 可做用户选择；去掉二分之一系数需要重新证明限幅／稳定性，不能作为线程或缓存优化偷偷修改。

[固定网格 CFL 扫描](results/o6-acceptance-20260927/probes/o6final_cfl.json)关闭 AMR 以分离步长和重网格时刻：CFL=0.1/0.2/0.4/0.8/1.0 分别走 491/255/138/79/68 步，均到相同物理终点且无状态修复。以 0.1 为细时间参考，CFL=1 的密度／温度／压强／速度／C12 相对 L1 偏差约为 0.146%／0.211%／0.194%／0.312%／0.262%。不同变量的偏差并非单调，不能把这次短扫描称为渐近时间阶数证明。先前冻结版本的细网格 AMR 合法 CFL=1 单次探针为 211 步、30.98 s，仍不足两倍线；它没有替换正式 CFL=0.8 的成绩。

对一般非交换的流体与反应算子，`B(dt/2) H(dt) B(dt/2)` 的对称分裂与 `H(dt) B(dt)` 的一阶分裂具有不同误差结构。FLASH 本次 burner 还固定每次调用的温度，ARCH 解热耦合温度方程。仅为了计时删除一个半步既不能覆盖当前差距，也改变了方法。本轮保留两半步及热闭合。剩余工程优化潜力仍需按实际热点判断，不把所有超额秒数归因于“物理更完整”。

### 初猜路线的否决证据

在临时头文件副本中，把固定初猜替换成气体／辐射温度估计，同时保留原括区间、残差
和迭代上限。[432 次有界探针](results/o6-acceptance-20260927/probes/o6inverse_hint_probe.json)的总 EOS 求值次数减少，但与
Cellular 对应的高密度高温子集由 770 增至 911。低温 `rho=0.01 g/cm³, T=10⁴ K` 的
三种 He/C/O 组成还出现不同能量根：现有 Coulomb 非正 P/e 保护会切换修正项，不能
从很小能量残差推断全域唯一温度。此探针不改变生产源码，不进入正式计时。
后续热启动必须先处理材料域／根分支合同；本轮不能仅增加一个初猜入口便宣称优化完成。

## 参数审查

已有 `ode_rtol/atol`、`ode_initial_dt_frac`、引力残差和扩散控制继续复用，没有加入算法微调开关。计划中的 `eos_coulomb_mult`、`burn_in_shocks`、`dt_max` 是候选项：当前两端 Coulomb 都为 1；激波停烧需要共用判据及物理误差检验；最大步长只会限制瞬态分辨率而不会减少运行时间。它们没有成为本轮性能补丁的一部分，不能声称已交付完整配置合同。现有 CFL 的文档范围已与实际输入校验统一为有限 `0<cfl<=1`。

## 复测入口与环境

`run_comparison.py` 复用已有输入，记录执行物摘要、CPU 绑核、MPI 启动器、实际后端、
每次总墙钟和 checkpoint 终点；运行不覆盖已有目录或清单。`--report-only` 只为已有
清单添加分析，不重跑模拟；通过可重复的 `--reference-manifest` 引用 CPU1/8/16 清单，
检查同输入、终点、拓扑和场后形成 CUDA 对最快 CPU 的比值。默认七点用于 CPU／FLASH；
`snia2d/snia3d` 指向现有四模块示例，仅用于 ARCH 后端对照，不借用 FLASH 分母。
Python 使用 conda `work`，FLASH 使用匹配其链接库的系统 OpenMPI；CUDA 在 CPU 计时全部
完成之后编译。正式计时不启用事件探针，也不与编译、其他模拟并行。

```sh
python validation/gravity/flash/run_comparison.py \
  --routes flash arch --prefix unique-run --output output \
  --manifest output/unique-run.json --helm-binary /path/to/helm_table.bdat
```

CPU 构建使用 GCC 13.3，CUDA 构建使用 NVCC 12.3.107／GCC 12.4；设备为 RTX 3060 Ti 8 GiB，驱动 610.47。CPU 与 CUDA 均为 Release，保留 FP64 和严格浮点设置；没有启用 fast-math、降低求解精度或按场景名称分派数学捷径。八核绑核列表为 `0,2,4,6,8,10,12,14`，已核对分别属于八个不同物理核；16 线程含 SMT。源码实际测量身份由各清单中的执行物摘要约束。

## 正确性与验收边界

最终 CPU 全量 CTest 61/61 通过。Cellular A、B、无燃烧和细网格各自的 21 个 checkpoint 数据集与 34 个输出数据集，均与第二轮 CPU 逐位一致；物理终点、AMR 拓扑与累计工作量未改变。公共 CUDA 燃烧失败测试已从可选 cuDSS 注册条件中移出；普通 CUDA 构建也会执行稠密与 ODE 恢复检查，cuDSS 专属部分在依赖存在时仍完整保留。该轮构建未找到 cuDSS，因此没有执行其专属 provider 检查。后续确认库一直在项目依赖目录中，缺少的是 CUDSS_ROOT 搜索前缀；重新接入的证据单列于[后续验收](O6ControlsAcceptanceReport.zh-CN.md)，不回填为本轮已测。

新检查覆盖 RHS/Jacobian 精确一致、所需导数字段与原完整求值一致、缓存全输入键／冲突／生命周期／失败不缓存，以及真实 3D/4D 表格域失败后的 BE/BD/ROS4 重试与 NSE 热修正恢复。NSE 恢复测试使用可独立求根的制造平衡投影；它验证热修正器错误语义，真实核平衡数学仍由既有网络测试承担。

最终 CUDA 已完成重新构建；完整 CTest 132/132 通过，真实 Helm 分组的 70 个重复／不同状态及尾部 lane 与原设备求值逐位相同，必要失败仍锁存。生产兼容矩阵 42/42 通过，包括外部／自引力、AMR、燃烧＋扩散和跨后端 v6 重启。跨代码反应流还有热闭合差异，本轮不按已经观测到的场偏差倒推一个“共同科学预算”。通过成本线不等于已经证明两个不同反应推进方案具有相同误差。

## CUDA 前序冻结结果与归因


[第一组 CUDA 三轮清单](results/o6-acceptance-20260927/earlier/o6final_cuda.json)记录 A、B、无燃烧、Jeans128 和细网格的
中位数分别为 18.43、19.37、14.00、8.13、79.32 s。各模型与最快 CPU1/8/16 的比较均为
负收益。全部实际终点和 AMR 拓扑相同，主要场相对 L1 最大约 3.4e-13。
它们比旧 CUDA 版本快，但不能据此沿用旧版本的 GPU 正收益结论。

独立事件探针在无燃烧输入上记录设备核时间约 11.18 s，其中面通量 7.95 s、逐块 CFL
2.58 s、AMR 热力学 0.29 s。事件探针逐次等待核完成，只用于归因，不代替整程速度。
这些数据表明需要先消除设备侧重复工作与小块串行启动，不能把异步传输 API 的等待
简单归为 PCIe 成本。对应实现复用 CPU 已有的均值热力学计算，并把 CFL 单元计算
按块批量启动；数学公式、NaN 策略、块内归约顺序和错误状态均保持原合同。
后续结果单列，保留本组失败记录。


批处理第一段的[单次筛查](results/o6-acceptance-20260927/probes/o6batch_cuda_probe.json)为无燃烧 10.54 s、A 14.04 s、
细网格 54.79 s，三组终点、AMR 拓扑及场检查通过。这些是收益筛查，不是最终中位数。
对应第二次独立事件探针将 CFL 候选从约 2.58 s 降到 0.20 s；面通量仍约 5.76 s，
均值热力学另约 0.85 s。因此继续检查面查询，发现 CUDA 检查包装层没有转发共享
Helm 的成对 Roe 导数及 IdealGas 的 Roe 直接表达式，造成已在 CPU 生效的优化未在
设备生效。补齐接口转发、可选探针的精确输入分组和面端点复用，不引入另一套 EOS。
该版本完整回归通过，[三轮清单](results/o6-acceptance-20260927/earlier/o6release_cuda.json)的 A/B／无燃烧／Jeans128／细网格中位数为 13.57／13.98／9.59／7.45／51.60 s，五点仍未胜过新版最佳 CPU。后续共用 HLLC 视图的最终结果见上表。


Jeans128 的现有阶段账本另外记录 221 次场求解、1159 次总迭代，两端迭代数相同。
CUDA 的 Poisson 阶段约 7.11 s，CPU 约 4.76 s；设备累计 399539 次核启动与 17258 次
同步。粗层周期投影中，原分块归约经常已只需要一个线程块，却仍拆成多次启动。
本轮将这一情形的归约／投影合并到同一线程块，调用原 `Reduction` 与 `ProjectWork`，
保留补偿求和分块与次序。此项属于通用执行组织，CPU 数学、MG 周期及收敛门槛均不变；
现有 CUDA 归约测试追加尺寸边界与尺度／非有限值控制并逐位通过。Jeans128 核启动降到 265095，迭代与同步数未变，残差／目标最大值仍为 0.493333；Poisson 单次诊断约 6.67 s。归约启动减少没有消除求解器的所有标量同步。
