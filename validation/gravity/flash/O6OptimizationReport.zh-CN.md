**两个预登记 Cellular 点的 CPU 整程成本子目标已达到，CUDA 在本机对实测最快 CPU 配置有正向收益；O6 尚未完成科学与功能出口。**

## 版本和改动

- Helm 平均状态的压强与声速合并取自一次严格温度反解。原 EOS 有效域、真实残差、导数和高阶候选失败回退仍在；通用 EOS 路线保留原标量调用。CPU/CUDA 共用 `InvariantDomainFlux.h`，没有另写一份设备热力学公式。
- `ode_initial_dt_frac` 的缺省值从 `1e-3` 调为 `1`，先试完整反应区间；BD、ROS4 和 BE-NR 原有误差拒绝及内部缩步不变。此值由标准配置表、解析、API 样例与手册同源给出，用户仍可显式调小。
- Driver 新增 CPU 同步阶段时间表 `cpu_stage_timings.tsv`，分别计 AMR、重力、步长、两次燃烧、扩散和 Hydro。它们不包含准备、输出和其他 Driver 成本，不得相加当作总墙钟；CUDA 异步 enqueue 不伪装成设备执行时间。

正式环境为 Intel i7-10700（8 个物理核／16 逻辑线程）、RTX 3060 Ti 8 GiB、CUDA 12.3。
Conda `work` 升级到 Python 3.12.14，NumPy 2.5.3、SciPy 1.18.1、h5py 3.16.0；
`pip check` 无依赖冲突。升级前 `work` 的完整副本在

cuDSS 未被本机构建发现，CUDA 稀疏 vendor 路线因此不在本次实测范围；KLU 可用。

## 完整任务计时

`/usr/bin/time` 记录进程开始到退出，包括启动、推进与输出。FLASH 用用户归档中的 4.8 Cellular
二进制，`eos_coulombMult=1` 与 ARCH 当前 Helm 完整物理项对齐；未改 Fortran 源码。
A 是 64×32 cm，B 是预先登记的 96×32 cm 不同热状态点；均为纯 He、Helm＋aprox19、
HLLC/MC、动态 AMR、完整温度耦合反应，终点分别与 FLASH 实际输出时间相同。
同资源主线将 FLASH MPI8 与 ARCH CPU8 固定在本机 8 个物理核上；CPU16 使用所有 16 个逻辑线程，
GPU 使用 1 个主机线程。每组重复三次，按总墙钟中位数判断，不以单步或去掉输出后的时间替换。

| 算例／执行配置 | 三次总秒数 | 中位数 | 与 FLASH MPI8／最快 CPU 的关系 |
| --- | --- | ---: | ---: |
| A FLASH MPI8 | 8.85、5.48、5.92 | 5.92 | 参考；第一轮较冷 |
| A ARCH CPU8 | 51.08、50.70、50.71 | 50.71 | FLASH 的 **8.57×** |
| A ARCH CPU16 | 41.51、41.22、42.29 | 41.51 | 最快 CPU 配置 |
| A ARCH CUDA | 40.45、40.33、37.95 | 40.33 | 对 CPU16 **1.03×** 加速 |
| B FLASH MPI8 | 6.01、6.60、5.87 | 6.01 | 参考 |
| B ARCH CPU8 | 57.68、56.82、57.15 | 57.15 | FLASH 的 **9.51×** |
| B ARCH CPU16 | 48.39、48.36、47.53 | 48.36 | 最快 CPU 配置 |
| B ARCH CUDA | 41.90、40.74、39.86 | 40.74 | 对 CPU16 **1.19×** 加速 |

历史资源线 A：FLASH MPI1 为 5.23／5.00／4.93 秒，中位数 5.00；CPU16／MPI1
为 **8.30×**。这是任务成本记录，资源不相等。A/B CPU8 与 MPI8 均低于 ≤10 目标，
但 B 离门槛较近；本报告不把这两个点推广为所有物理配置均达标。
GPU 对 CPU8 的整程加速分别为 **1.26×**、**1.40×**。A 对最快 CPU 的收益仅约 3%，
本机 FP64 性能和样本波动需要一并展示；GPU 绝对时间依然是约 40 秒，不等于“已经很快”。

A/B 的 ARCH 和 FLASH 宏步分别为 138／62；最终均有相同的 5,120／6,144 个有效单元，
但块长为 ARCH 16、FLASH 8，细化历史也不同。按各步实际活跃叶单元积分，A 为
ARCH 651,264、FLASH 271,360 个单元宏步（2.40×）；B 为 792,576、334,848（2.37×）。
因此总时间差不能直接当成相同算子的单元吞吐差。两组 CPU8 中 Hydro 分别占 31.91／38.26 秒，
两次 Burn 共 15.54／16.06 秒；输出在 A/B 分别约 0.77／0.93 秒，非主要热点。
关燃烧的 A 控制组 CPU16 为 25.41 秒，说明完整热耦合增加明显成本；
小型理想气体 Sod CPU1 中位 0.24 秒，没有观察到持续的大幅退化。

## 数值与验证边界

- A/B 的 CPU 与 CUDA 均为 138 步、相同终点和 AMR 叶拓扑，所有复跑零下限修复。所有主场复跑的 CPU 输出逐位一致；GPU 对 CPU 的密度、压强、温度相对 L1 在 `10^-15` 量级，核放能约 `3.2–3.4e-13`。CUDA 更快的第三次运行没有少做步数或改变场。
- 三种 BurnOneZone 求解器均在新默认及显式旧值 `1e-3` 下到达 `1e-10 s`、20 步且零修复。BD 末态主要热力学量相同；ROS4／BE-NR 温度相对差低于 `1.4e-13`，微量 He4 的相对差低于 `6.4e-9`。新默认不是宽松容差；各求解器性能变化并不一律为正。
- 升级后的 `work` 环境执行 CPU CTest **61/61**；CUDA 精选回归 **5/5**，覆盖候选 EOS 失败恢复、Host／Device EOS、燃烧控制与策略、网格度量。现有 `check_cuda_compatibility.py` 也通过，42 条记录涵盖外引力、自引力、独立解析物理、AMR、四模块耦合、失败必须拒绝和 CPU↔CUDA 重启；摘要在 `output/o6_gravity_cuda_compat/summary.json`。CUDA A/B 生产整程运行及末态对比另行通过。
- 原 A/B 最细 `dx=0.5 cm` 对 FLASH 的初始压强相对 L1 分别为 `1.99e-6`／`1.54e-6`。终点 A 的密度、温度、压强、速度相对 L1 为 1.59%、3.22%、1.98%、2.66%；B 为 1.22%、3.45%、1.69%、2.62%。这些差值是诊断量，**不是预先证明的允许误差**。

空间加密 A 到 `dx=0.25 cm` 时，原 `radiusPerturb=12.8 cm` 落在细单元内部。
ARCH 将父单元初态延拓，FLASH 在新细单元重新判定点火区域，于是初态多出／少掉整整一列细单元，
直接用末态差异评判收敛无效。另做同半径 13.0 cm 的对齐控制组：
粗网格双方的所有输出与原性能输入逐位相同；细网格双方初态密度、速度、He4 完全一致，
压强仍只有原 Helm 物性求值的 `1.99e-6` 相对差。
A 细网格终点的密度、温度、压强、速度差降为 0.91%、1.88%、1.13%、1.33%。
B 也用相同办法对齐并加密；初态密度、速度、He4 完全一致，压强相对差 `1.54e-6`，
终点四个主场的差分别降为 0.85%、2.36%、1.18%、1.95%。
两组 C12 差均未随之单调下降。细化后 FLASH 越过 `tmax` 的终点也与粗网格不同，
所以这些百分比是各自同时间跨软件的对照，不能直接视为严格同时间的空间收敛阶。
该控制诊断有利于识别 AMR 初值来源；单次加密与尚未完成的独立时间收敛仍不构成共同误差预算。

另在对齐初态的原网格将双方 CFL 从 0.8 降为 0.4，且每组 ARCH 都匹配对应 FLASH 的**实际**终点。
A/B 密度差分别为 1.41%／1.13%，压强 1.62%／1.44%，速度 2.35%／2.44%；
温度 3.23%／3.31%，C12 2.95%／3.65%。它们整体上下降有限，A 的温度／C12 几乎不变。
FLASH 会在最后一步越过 `tmax`，半 CFL 的物理终点与原性能组不同；
上述数值只能作为时间敏感性诊断，不能据它们虚构同一终点的收敛阶或许可误差。

原始计时／运行日志留在本机 `/tmp/arch_o6_*` 与
`/home/shiroakane/FLASH4.8/o6_cpu_case_*`，ARCH 场与阶段记录在工作区 `output/o6_*`。

## 未关闭的 O6 条目

共同反应流时间／空间误差预算还需覆盖两组代表点的前沿、温升、核素与能量；
目前不能把 ≤10 的**任务成本子目标**写成 O6 完整科学签收。
计划中的 `eos_coulomb_mult`、`burn_in_shocks`、`dt_max` 尚未落地；它们需要默认值、
解析／校验、CPU/CUDA 数值视图、重启身份和文档一并验收，不能为本次速度数字临时关闭物理。
已有 CompositeMultigrid 对拓扑和粗层因子有复用；还缺相同重力源项模型上的
CPU/GPU 专项成本与失效条件复核，不能把无引力 Cellular 的提速归功于 MG。
EOS 逆解热启动及更深层缓存也没有在缺少有效状态版本时冒险加入。
O6 因此保持**进行中**，O7 不应以本报告中的局部达标取代出口检查。
