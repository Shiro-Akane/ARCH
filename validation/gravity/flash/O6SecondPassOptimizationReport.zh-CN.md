# O6／O6+ 第二轮性能与正确性复核

2026-09-27，工作树 `compute/optim`。本报告接续[第一轮记录](O6PlusOptimizationReport.zh-CN.md)，使用固定输入、完整任务墙钟和**检查点实测物理终点**。逐次结果、执行物 SHA-256、活跃叶单元推进量、阶段耗时和逐字段旧版对照保存在[CPU/FLASH 原始清单](o6second_measurements.json)及[CUDA 原始清单](o6second_cuda_measurements.json)；本机原始日志在 `output/o6second_*`。CPU 计时使用单一冻结执行物 `/tmp/arch_o6_second_final_cpu`；设备编译修复只加预处理保护，最终 CPU 执行物 SHA-256 与冻结版完全相同。

**判定：第二轮移除了一个通用的重复 EOS 求值开销，但 O6／O6+ 的完整出口仍未通过。** Sod 和 Jeans 时间线达到约两倍以内；Cellular A/B、无燃烧和细网格分别仍需约 5.69、5.74、2.72、18.75 倍 FLASH 时间。CPU 数学测试 61/61 通过，物理终点全部相同。性能差异中确有固定算法工作量，但目前的证据不能证明超额秒数全部不可优化；不能把本轮标为达到 ≤2。完整反应流的双方共同科学误差预算也尚未建立。新版 CUDA 的数学／系统检查通过，但对本机最快 CPU 的五个代表点均未取得整程正收益。

## 同资源整程复测

第二轮在共享 HLLC 中加入 `F_HLLC(U,U)=F(U)` 的精确一致性路径：只有两侧全部守恒量与物种分数逐项相同才进入，仍执行必要 EOS/声速验证；若与本 RK 阶段的单元均值逐项相同，复用已验证的均值热力学结果。无效状态仍按旧失败／限流路径处理。这是与算例名、方向、网格尺寸无关的通用规则；CUDA 不持有主机均值缓存，但使用相同的物理通量恒等式。对第一轮同输入 CPU 基线，A 35.361→29.074 s，B 38.723→30.590 s，无燃烧 18.111→12.384 s，细网格 210.138→171.621 s。A、B、细网格的 21 个检查点数据集和 34 个输出数据集与此前 CPU 轨迹逐位一致；无燃烧旧新版初始检查点逐位一致，终态只有约 `1–2e-15` 相对 L1 的差异，时间／拓扑一致。Jeans 128² 与旧 CPU 检查点逐位一致；Sod 同为 4497 步和同一终点，密度／能量／动量旧新版相对 L1 分别约 `1.25e-9`／`1.85e-9`／`6.27e-9`，与 4497 步后的舍入差传播相符；该点不声称逐位一致。未改物理开关、CFL、ODE 容差、FLASH 输入的快路径或既有测试的判据。

## 剩余成本的可证归因

| 模型 | ARCH／FLASH 宏步 | 两端累计活跃叶单元宏步 | 工作量比 | ARCH 首轮阶段耗时 s |
| --- | ---: | ---: | ---: | --- |
| Cellular A | 138／62 | 654,336／269,824 | **2.43** | Hydro 9.08；两次 Burn 15.30；CFL 1.45；重网格 0.94 |
| Cellular B | 138／62 | 795,648／333,312 | **2.39** | Hydro 9.37；两次 Burn 15.62；CFL 1.73；重网格 1.13 |
| 不燃烧 | 120／62 | 589,824／266,752 | **2.21** | Hydro 7.62；CFL 1.32；重网格 0.87 |
| 0.25 cm | 258／103 | 4,337,664／1,441,280 | **3.01** | Hydro 56.54；两次 Burn 95.91；CFL 8.89；重网格 6.04 |

累计活跃单元数按每步实际叶块积分，不把最终单元数当成整个运行的工作量。ARCH 每块 `16×16`，FLASH 每块 `8×8`；按单元而非块比较。无燃烧的时间比 2.72 对工作量比 2.21，说明剩余单位单元步成本约为 FLASH 的 1.23 倍；不能将整个 2.72 倍归因于 EOS 实现。A/B 的单位单元步总成本约为 2.35–2.40 倍，细网格约为 6.23 倍；这还混合了燃烧占比、推进阶段与初始化，不能当成单个 kernel 的速度比。

不可通过线程绑核消除的**固定工作量**：ARCH 当前保守正性 CFL 采用 `0.5/sum_axis((|u|+c)/dx)`，FLASH 水动候选采用各轴最大值并乘 CFL。Sod 因而走 4497/2265 步，接近两倍；二维的 AMR 叶单元步比为上表 2.21–3.01。直接抬高 ARCH 步长会改稳定性条件和数值轨迹，本轮未这样处理。ARCH 另用 RK2 两个水动阶段及 Strang 两个半步烧核；FLASH 的受测 Unsplit/Cellular 走一轮 Hydro/Burn、面 EOS 原设为关闭、每次 burner 内固定 T 更新反应率。这些是实际计算语义差异。尤其细网格 ARCH 的 Burn 合计 **95.91 s**，远超该点 `2×FLASH=18.30 s` 的**整个目标用时**；即使其余 ARCH 阶段零成本，Burn 也至少需快 5.24 倍才能触线。保留自洽温度与双半步时，不存在把这 95.91 秒简单删除的正确优化。

对**可消除的工程开销**已作有界检查：最终优化版 A 的独立占用率探针墙钟 28.41 s、用户＋内核 CPU 时间 172.21 s，平均约占 **6.06/8 核**；即便保持所有工作不变而理想占满八核，上界约 **1.32 倍**，远不足以把 5–6 倍差距压到两倍。旧版绑核复跑 35.30/35.44 s 没有可靠收益；去掉一次 pre-burn 边界调用约 0.7% 且已撤销；线程局部通量缓冲复用的早期探针也无可重复收益并已撤销。新做的 20,000 次空嵌套 OpenMP 区域微探针约 0.0016 s，表明单纯创建内层团队不能解释十秒级 Burn 差距；此微探针**不**测真实负载不均衡。编译选项也未显出 ARCH 的劣势：ARCH Release `-O3`，FLASH 归档执行物报告 `-O2`。因此无需再把同一绑核／缓冲／输出路径反复尝试。

**归因的边界：**步数、阶段数、严格面 EOS 与热反馈是确认的设计成本；目前没有证明完整 5.69/18.75 倍都是不可缩小的下界。特别是 20 方程 DenseLU、热耦合 Jacobian 和 Helm 热力学调用仍可能通过保持同一残差／闭合的数学实现改进。FLASH 不烧核或跳过主要活跃燃烧的猜想已由 `useBurn=true`、aprox19、日志和初末燃烧区核对排除；但双方 burner 求解的是不同热闭合问题，不能将数值时间比直接解释为同精度效率。此前的初值、终态逐格差异和粗细网格检查见[第一轮报告](O6PlusOptimizationReport.zh-CN.md)；尚无独立预登记的反应流共同误差预算，本报告不补造一个。

## CUDA 与最终验收

最终源码的 CPU 全量 CTest **61/61**、重新构建的受影响 CUDA HLLC/EOS/网格 CTest **5/5**、现有 CUDA 兼容性脚本 **42/42** 均通过；后者覆盖外引力、自引力、AMR、物理耦合和 CPU↔CUDA 重启。本机兼容性摘要 `output/o6second_cuda_compat/summary.json`记录两执行物身份和 42 条结果。每个生产样本的 `backend_plan` 都确认 `resolved=cuda`；没有用“CUDA 可执行物实际回退 CPU”的样本计算加速。

| 模型 | CUDA 三次／中位数 s | 新版 CPU8 中位数 s | GPU/CPU8 速度比 | 最快 CPU 口径 |
| --- | ---: | ---: | ---: | --- |
| Cellular A | 30.976、31.129、31.379／**31.129** | 29.074 | **0.934** | 已慢于 CPU8，失败 |
| Cellular B | 33.838、33.210、33.161／**33.210** | 30.590 | **0.921** | 已慢于 CPU8，失败 |
| A 不燃烧 | 24.723、24.629、24.616／**24.629** | 12.384 | **0.503** | 已慢于 CPU8，失败 |
| Jeans 128² | 8.436、8.346、8.104／**8.346** | 5.362 | **0.642** | 已慢于 CPU8，失败 |
| Cellular 0.25 cm | 145.573、146.130、145.423／**145.573** | 171.621 | **1.179** | 新版 CPU16 中位 **125.361 s**，GPU/最快 CPU **0.861**，失败 |

GPU 速度比定义为 `T_CPU/T_CUDA`，大于 1 才是正收益。细网格 CPU16 的三轮为 125.361、125.115、125.606 s，与 CPU8 的物理终点和检查点全部数据逐位一致；CPU16 用 16 个逻辑线程，不参与前述同八核 FLASH 比较，只用于按既定最快 CPU 判定 GPU。CUDA 五点全部与 CPU 达到相同物理终点和 AMR 叶拓扑；主要输出场相对 L1 最大约 `3.4e-13`，无燃烧约 `1.7e-15`。A 另做一次解除单核亲和性的 CUDA 有界对照，为 **30.511 s**，比绑核中位略好但仍慢于 CPU8；单核亲和性不是负收益的充分解释。

设备轨迹在 A 记录约 38.5 MB H2D、4.4 MB D2H、8,418 次 kernel 和 2,242 次同步；细网格约 205 MB H2D、22 MB D2H、21,006 次 kernel 和 4,240 次同步。它们说明执行粒度与主机／设备交接仍有成本，但仅靠字节数不能算出耗时。Nsight 在本机 WSL 未取得 kernel 时间；先前 `cudaMemcpyAsync` 的约 30 秒 API 累计时间可能包含等待前序 kernel，**不是已证实的纯 PCIe 传输时间**。一次活跃运行中 GPU 利用率读数为 99%，同样不能独立证明是 FP64 算术、访存还是同步所限。因此未以猜测为依据删掉必要同步或改写共享数学。

**第二轮验收闭合状态：**实际运行、终点、CPU／CUDA 场、线程／亲和性与传输计数均已核对；没有待跑的第二轮短验收样本。CPU 时间线 3 个公共模型通过、4 个 Cellular 点失败；GPU 对最快 CPU 的 5 个点全部失败；完整反应流共同科学误差预算仍缺。固定方法的步数、RK2／Strang 阶段及严格热闭合不能在本轮通过省算消除；剩余热耦合 ODE/EOS 的等价实现优化潜力尚未得到下界证明。**因此 O6／O6+ 不签收，不把未达到的指标转移或改名为已完成。**
