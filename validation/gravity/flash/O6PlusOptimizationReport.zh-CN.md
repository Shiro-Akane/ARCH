# O6／O6+ 本轮优化与未通过项

2026-09-27，`compute/optim` 工作区；源基线为 `main` 的
`48f6d357d6b8085501d2012d70e923080bae3402`。本报告属于本轮工作树，
此前的 [O6 报告](O6OptimizationReport.zh-CN.md)保持原版本和原计时身份。
对应的[执行计划与尝试账本](../../../docs/development/ComputeOptimizationPlan.zh-CN.md)
会随验收状态回查。**目前不能签收 O6／O6+：完整 Cellular A/B 和 Helm 无燃烧
的同资源 CPU 整程耗时都没有达到 FLASH 的两倍以内，A/B 尚缺共同科学误差预算。**
这里的 `tmax` 是模拟的物理终点，以下「秒数」均为程序开始至退出的真实墙钟。
逐次原始时间、独立复测和五个实际执行物的构建身份／哈希保存在
[测量清单](o6plus_measurements.json)；输入文件与本机原始输出路径也在那里登记。

## 固定比较合同

本机 i7-10700 的 8 个物理核上，ARCH CPU8 使用 `OMP_NUM_THREADS=8`，FLASH 4.8
使用 MPI8，均限制到逻辑核 `0,2,4,6,8,10,12,14`；独立串行执行并计入初始化、推进、
输出和退出。下表每项至少三次，以中位数判定，列出范围以显示系统噪声；共同 CFL 为 0.8，
相同 CGS 物理域、终点和最细物理分辨率。动态 AMR 两端以相同的
`PRES,DENS,c12,ENUC` 指标进行 A/B 对照，但块长和细化历史不完全相同。
FLASH 使用归档中的原版 Cellular/Sod/Jeans 源码；A/B 原快路径的 `EOSforRiemann=false`
按实际输入保留，另行做 `true` 辅助对照，不能用较慢辅助路径替换原参考。
所有 FLASH Cellular 参考都设置 `eos_coulombMult=1`；
Jeans 的 `mg_maxResidualNorm=1e-10` 对应 ARCH `gravity_rtol=1e-10`。

针对离 2× 太近的 Sod 和 Jeans 128²，保持原构建、绑核及物理终点，再各做一组独立的
三次完整运行。Sod 的 ARCH／FLASH 中位数为 **5.457／2.656 s，即 2.0545×**，
三次范围分别为 5.420–5.463／2.630–2.699 s；第二组超过门槛，因此不能按首组
1.98× 宣称稳定通过。Jeans 128² 的第二组为 **5.472／2.863 s，即 1.9111×**，
范围为 5.471–5.487／2.806–3.032 s。十二个复测 checkpoint 的双方终点分别精确为
Sod `0.20004197244290714 s` 和 Jeans `0.1 s`；逐次数据及输出路径见测量清单。

Cellular A/B 的 ARCH/FLASH 分别走了 138/62 宏步；按实际 AMR 活跃叶单元累计，
ARCH 计算量分别为 FLASH 的 2.40／2.37 倍。同 CFL 不代表同一步长公式或同阶段数量。
源码还能直接解释同数值 CFL 的步数差异：ARCH `DriverUtils.h` 的候选步长为
`0.5 / sum_axis((abs(v)+c)/dx)`，FLASH `Hydro_computeDt.F90` 的水动候选
使用各轴波速比的 `max`，然后乘自身 CFL。对于 1D 相同波速，ARCH 的
宏步天然约为 FLASH 的一半；Sod 实测 4497/2265 步正与此相符。
这不是将配置中的 `tmax` 误认成运行时间，也不是同配置下少算 cell。
改变 ARCH 的稳定性界限会改变数值轨迹，不能仅为追求 2× 改掉。
ARCH 的 2D RK2、两次 Strang burn 半步、严格重建面 EOS 和每个反应试步的温度耦合
都属于已验收的物理/数值设计，不为本轮计时降低阶数、冻结温度或省略必要 EOS。
FLASH 原 `hy_uhd_getFaceFlux.F90` 在 `hy_EOSforRiemann=false` 时跳过 `faceStatesEos`；
`bn_burner.F90` 在每次 burner 调用开始时设置一次 `btemp=temp` 和网络率。
这是代码路径事实，不等于双方误差等价。

为了估计面 EOS 成本，保持 FLASH 其他物理、资源、终点不变，仅将其
`EOSforRiemann=true`：A 5.582/9.234/6.895 s（中位 6.895），B
5.704/5.449/8.946 s（中位 5.704），无燃烧 6.163/5.468/9.881 s
（中位 6.163）。ARCH 对这个辅助路径仍分别是 **5.13／6.79／2.94** 倍；
样本有明显系统波动，不能把这些比值当成面 EOS 的独占成本。
以原 FLASH 参考，A 的 2× 目标是 10.49 s，而 ARCH A 的 Hydro 单项就要
15.25 s、两次 Burn 合计 15.26 s；B Hydro 为 17.44 s、Burn 合计 15.79 s。
无燃烧 A 的 Hydro 13.25 s，仍高于目标 8.47 s。
已尝试的线程局部通量缓冲复用在探针中约为 9.84/9.89 s，未显示可重复收益并已撤销。
因此不能再反复围绕缓冲分配或输出开销试探；剩余差距需要在合法步长、通量/EOS 调用密度、
反应温度闭合和活跃单元工作量上取得可归因的科学与计时证据。

## 正确性和独立物理对照

优化后的 A/B/无燃烧 ARCH 末态与同输入的原接受轨迹逐位一致，步数分别为
138/138/120，所有复跑没有下限修复。两端 A/B 初始密度、速度和 He4 匹配，
压强相对 L1 分别相差 1.99e-6／1.54e-6；终态密度约相差 1.59%／1.22%，
温度约 3.22%／3.45%，压强约 1.98%／1.69%，C12 约 2.94%／3.70%。
这些是诊断差异，不能代替事先独立确定的前沿、能量、核素、时间/空间收敛误差预算；
所以即使 A/B 将来达到 2×，科学出口也仍须验收。

Jeans 算例扩充现有 `JeansWave` 用户例子，以 `standing_wave=true` 初始化与原 FLASH 4.8
相同的二维稳定引力波；64²、128² 两组公共输入分别在
[ARCH 64²](arch_jeans_o6plus.par)、[ARCH 128²](arch_jeans_o6plus_128.par)、
[FLASH 64²](flash_jeans_o6plus.par)、[FLASH 128²](flash_jeans_o6plus_128.par)。
固定网格 64²／128² 的初始密度相对 L1 仅约 1.1e-8／1.7e-8，主要是 FLASH plotfile
的单精度量化；初始速度全零。终点双方均准确为物理时间 0.1 s。
[独立对照脚本](compare_jeans_o6plus.py)按原生单元物理坐标逐格映射，要求每个比较格被覆盖一次，
并用线性 Jeans 关系计算模态波幅，而不是复用泊松求解器的残差公式。
该时刻解析波幅为 2949.238：ARCH 64²/128² 得 2872.737/2930.314，
相对误差 -2.594%/-0.642%，加密后约四倍收敛；严格 MG FLASH
为 2952.835/2951.002，偏差 +0.122%/+0.060%。两端终态密度相对 L1
约 6.01e-6／1.14e-6。ARCH 的 113／221 次引力求解全部通过原物理残差目标，
未改容差或省略当前密度右端。

本轮 CPU 执行优化复用了共享 Helm 状态、Roe 面状态代数和块级计划，避免静态 AMR
重复调度，并让 CompositeMultigrid 用**上一次已接受的势场**作为 FGMRES 初猜。
每次仍重新组装当前密度、边界和右端，并对原物理残差验收；失败解不得作为下一次初猜。
首步及 checkpoint 边界清除迭代历史，因为 checkpoint 不保存这一缓存。
针对重启逐位合同和全量 CPU CTest **61/61** 已通过。
最终 CUDA 程序编译通过，受影响的 EOS、燃烧控制、Hydro 失败语义及网格度量
CTest **20/20** 通过；`check_cuda_compatibility.py` 的 **42 项**系统记录
覆盖外引力、自引力、AMR、耦合和 CPU↔CUDA 检查点恢复，摘要保存在
`output/o6plus_cuda_compat_final/summary.json`。

## 最终 CPU16／CUDA 生产路径

受影响的 CUDA 数学和系统检查通过后，生产 A/B 与 128² Jeans 按相同输入和物理终点
各完成三次独立运行。CPU16 使用 16 个逻辑线程；CUDA 使用一个主机线程和
RTX 3060 Ti，`backend_plan` 均证实 `resolved=cuda`。下表速度比以该模型实测
CPU8/CPU16 中**最快的中位数**作分母；大于 1 才是本轮约定的整程 GPU 正收益。

| Cellular A | 29.821、29.627、29.963／**29.821** | 33.923、33.942、34.282／**33.942** | **0.879×** | GPU 负收益 |

[生产场对照](o6plus_backend_field_parity.json)检查最终物理时间、AMR 叶拓扑和全部输出场。

两种后端上的科学一致性，但不能把 GPU 对 CPU8 的 A/B 约 1.04/1.07 倍收益
误报成相对最快 CPU 的加速。Jeans 最初三次标作 GPU 的运行经 `backend_plan`
查出实际 `resolved=cpu`，已全部作废并以显式 CUDA 输入重测。

[逐格科学对照](o6plus_dx025_science.json)显示初始密度、速度完全匹配，初始压强
相对 L1 约 `1.99e-6`；终态密度、压强、温度、速度、C12 差分别约为
0.90%、1.15%、2.08%、1.52%、2.80%。相同终点并不消除两种燃烧温度处理的
科学差异；这些差值仍不是预先设立的合格误差。
CPU16↔GPU 的末态拓扑完全相同，密度、压强、温度、C12 相对 L1 约 `1e-15`，
ENUC 约 `3e-13`。CPU8 阶段表显示 Hydro 96.55 s、两次 Burn 合计 96.77 s、
重网格 6.01 s、时间步求值 8.85 s。Hydro＋Burn 已占驱动用时 210.59 s
中的约 **91.8%**。该输入的 2× 目标为 18.40 s，单是 Hydro 就超过目标
5.25 倍，Burn 合计也超过 5.26 倍；即便把输出、重网格、限步及其余开销都变成零，
Hydro＋Burn 合并仍至少要快约 **10.5 倍**才够。因此不能再把输出或单一调度优化
当作足以完成本轮出口的路线。这是现有阶段成本给出的必要条件，并非物理设计不可加速
的数学证明。
FLASH 日志确认 aprox19、`useBurn=true`、`useBurnTable=false`、
`nuclearTempMin=1e9 K`，故不能把此次差距简单称作关闭了燃烧。

## 尚未完成的 O6／O6+ 出口

- A/B、Helm 无燃烧的整程 ≤2 倍失败；不能用 Sod/Jeans 的通过平均冲淡。
  Sod 首组 1.98、独立复测 2.05，门槛不稳定；Jeans 128² 两组 1.95／1.91
  只证明该机器和规模的时间线。
- A/B 的共同反应流科学预算未事先建立；FLASH 冻结温度与 ARCH 自洽温度演化
  是实际算法差异，需要分别建立同误差能力，而不是修改 ARCH 物理流程凑计时。
- FLASH `ConductionDelta` 是温度依赖/常系数热传导，现有 ARCH `DiffusionMode`
  为双组分扩散，二者不是直接共同比较输入。独立燃烧单元也不能把 FLASH 固温
  ODE 直接当成 ARCH 自洽温度 ODE 的科学真值；不得虚列相应速度成绩。
- O6 计划中拟定的 `eos_coulomb_mult`、`burn_in_shocks`、`dt_max` 尚未完成整套
  参数注册/校验/API/CUDA/重启合同。本轮不能为了速度临时改变物理开关。
- CUDA 构建、上述回归和 CPU↔GPU 生产场一致性均已通过；A/B、Jeans 128²
  和加密 Cellular 对实测最快 CPU 的整程 GPU 正收益均失败。
  O6／O6+ 状态保持开放，不转移到 O7 或长期 O9。

生产输出和原始计时在本工作区 `output/o6plus_*` 与本机 `/tmp/o6plus_*`、
`/tmp/arch_o6plus_*`；这些是本机手动验收样本，不加入每次提交都跑的 CI 矩阵。
