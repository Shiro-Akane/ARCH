## 不应从这些字段推出什么

`Driver.h` 在 `execute_regrid` 前后计 Host 墙钟；区间包含其中等待的设备工作，
不等于独占 AMR kernel 时间。记录已标记与 backend trace 重叠，不能再次相加。
它也不是整个 AMR 系统的全部成本：普通步中的 ghost exchange、reflux 等还有其他入口。

宏步 0 的 regrid 区间只有毫秒级，但这不等于完整冷启动；CUDA context、EOS／network
上传、程序启动和 I/O 等不能都由它代表。现有 backend trace 提供状态、传输、kernel 和
同步计数，没有 burn／diffusion 每步墙钟。因此不能靠这些记录补出全应用稳态时间，
也不能把约 88% 的其余应用时间全部标记为燃烧或扩散。

对后续工作的含义：regrid 这一入口已有可测变化，燃烧／扩散及初始化的具体耗时分解
仍需在正式矩阵结束后另做诊断。当前大网络 5–10 倍的性能差距不由这张小网络表解释，
新 native-wave 候选也尚未因此取得任何运行资格。

只读取已合格 JSON，检查 108 条运行、105 条比较、冻结身份、原五次重复和 regrid 求和。

不执行物理模型或 CUDA。各统计量分别取中位数，不要求两个分区的中位数相加等于总区间中位数。
