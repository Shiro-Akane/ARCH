## 方法与边界

沿用 `run_sedov_amr_timing.py` 和 `verify_s4.py`。先两档 CPU8/CUDA pilot，再依次测量 8/1/2/4/16 线程；每档、每后端 1 次 warmup + 5 次正式测量，串行交替后端次序，不选择性删除样本。

原 4×4、8×8 Sedov：HLLC / PPM / RK3，CFL=0.4，AMR max=2、regrid=2，终止物理时刻 0.02。计时从 ARCH 进程创建到退出，包含初始化、计算、AMR、强制端点 I/O 和退出；排除输入生成、checkpoint 比较及预热。不是 kernel-only 计时。

保持 `OMP_DYNAMIC=FALSE`、`OMP_PLACES=cores`、`OMP_PROC_BIND=close`，只扫描 `OMP_NUM_THREADS`。各线程报告核对源码/构建/二进制/计时配方身份；跨线程检查仍调用原场比较器及原工作量比较，不更改预算。

`run_observed_timing.sh` 在每个正式线程阶段前后保存环境，并约每 10 秒记录进程名称/负载、GPU 利用率/显存、vmstat。观察进程仅采集只读信息，不终止其他作业、不运行 profiler 或编译。采样覆盖有限，无法观察 vGPU 物理宿主上的其他租户，不能宣称裸机独占实验。

历史旧 CUDA/新 CUDA 比值与本轮新 CPU/新 CUDA 比值分开。线程扫描中的最佳点只指本次样本中位数最小者，不是全平台最优值。性能数值不替代科学独立正确性或内存安全验收。
