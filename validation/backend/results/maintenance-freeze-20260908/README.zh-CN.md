## 本机同配置 AMR 计时

[计时摘要](amr-timing-review.json)及完整的[小档](sedov-timing-small.json)／
[中档](sedov-timing-medium.json)报告，比较同一优化程序的 CPU 与 CUDA 执行。
机器为 WSL2、i7-10700、16 GB 已安装内存及 8 GB 显存的 RTX 3060 Ti；
WSL 来宾分配约 7.7 GiB 内存。两个后端进程使用相同的八线程 OpenMP 环境。
每档、每个后端先预热一次，再正式测量三次，全部串行执行。

两档均使用两级细化，相同的二维 Sedov 物理、HLLC/PPM/RK3 方法、阈值和终止物理
时刻 `0.02`。这一观察窗口包含实际运行期细化与粗化，不仅是初始化网格。
下表中位数不包含预热和成本试跑。

| 基础块布局 | 接受步数 | 初始 → 终态叶块 | CPU 端到端 | CUDA 端到端 | CUDA / CPU |
| --- | ---: | ---: | ---: | ---: | ---: |
| 4 × 4 | 354 | 40 → 88 | 12.011 s | 39.670 s | 3.30 |
| 8 × 8 | 711 | 88 → 208 | 54.186 s | 185.632 s | 3.43 |

这两个算例中，CUDA 耗时分别为 CPU 的 3.30 和 3.43 倍，均未获得加速。
CPU/CUDA 场、守恒、接受步数、运行期拓扑序列及源码／脚本身份通过既有检查。
场预算保持 `rtol=1e-8`、`atol=1e-11`，守恒保持 `rtol=2e-12`、`atol=2e-10`。
小档有三次运行期拓扑变化，其中两次叶块净增加、一次净减少；中档有十二次，
其中八次净增加、四次净减少。这些分类统计事务前后的净变化，不代表事务内每个
父子块操作的次数。

端到端计时从 ARCH 进程创建到退出，包含初始化、计算、AMR、终态输出及清理，
不含验证器。另行记录的运行期重网格事务总耗时中位数，小档为 CPU 1.404 s／CUDA
2.279 s，中档为 6.664 s／10.890 s。初始化单列，嵌套重叠轨迹不重复相加。
程序没有单独的求解器或 kernel 计时器，不能把端到端减去重网格的差值称为纯流体
耗时。两组受保护运行均未触发中止，swap 未增长。

复现时启用 `BUILD_TESTING=ON`，应用和检查点比较器必须来自同一个 CUDA 构建。
在仓库根目录执行，并选用不存在或为空的输出目录：

```bash
python3 tools/run_memory_guarded.py --min-available-mib 1536 \
  --max-swap-growth-mib 256 --pressure-guard -- \
  python3 validation/backend/results/maintenance-freeze-20260908/run_sedov_amr_timing.py \
    --arch build-cuda/bin/ARCH \
    --checkpoint-validator build-cuda/arch_cuda_single_level_validation \
    --output-root build/sedov-amr-timing --blocks 4 8 --levels 2 \
    --time .02 --threads 8 --backend cpu cuda --warmups 1 --repeats 3 \
    --timeout 1200
```

所有者接受如实披露这些性能结果，并按 CPU/CUDA 同功能版本合入。
